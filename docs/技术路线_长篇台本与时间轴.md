# 长篇台本 + 多轨时间轴：技术路线与迁移指南

> 记录「从一个只能合成短句的整合包，扩展成长篇台本编辑器 + 多轨时间轴工作台」的完整思路。
> 目的是：**换一个 TTS 整合包、换一个语音模型，只要照着这套思路，也能做出同样的东西**。
>
> 对应代码：`longform_api.py`（台本层）、`timeline_api.py`（时间轴层）、`web/longform.*`、`web/timeline.*`
> 截至 2026-10-23（前端 v18）。

---

## 0. 一句话概括

原来的整合包是「输入一段文本 → 输出一段音频」的一次性工具。
我们把它改造成两层工程化产品：

```
第一层：长篇台本（编辑 + 批量渲染 + 断点续跑 + 修改追踪）  → 得到「一堆带时间信息的句子音频」
第二层：多轨时间轴（排布 + 剪辑 + 素材 + 混音 + 工程导出） → 得到「成品音频 / 可交给别的软件的工程」
```

关键不是"做了两个页面"，而是**把"文本"变成了"带状态、带时间码、可增量重算的工程数据"**。

---

## 1. 起点：原整合包的能力边界

典型整合包（IndexTTS2、GPT-SoVITS、CosyVoice、FishSpeech…）都长这样：

| 能力 | 现状 |
|---|---|
| 合成接口 | `infer(text, ref_audio, emo...) -> wav`，一次几十字 |
| 前端 | 一个表单 + 一个播放器 |
| 音频 | 单文件输出到 `outputs/`，可能有过期清理 |
| 状态 | 无（关掉页面就没了） |
| 工程 | 无（想改一句就得重传全部） |

真实痛点：

1. 两万字台本要手工切分、逐段提交、逐段下载、再拼接；
2. 改一句话要重跑整段，且不知道"改了会不会影响后面"；
3. 语气/停顿/音效最后只能在别的软件里对时间，来回导文件；
4. 生成 200 句以后，哪些生成过、哪些要重生成，全靠脑子记。

所以扩展目标不是"加一个批量按钮"，而是**给文本建立可持久化的工程模型**。

---

## 2. 设计原则（这几条决定了后面所有实现）

| 原则 | 具体做法 | 为什么 |
|---|---|---|
| **纯增量，不改原程序** | 所有新功能写在 `longform_api.py` / `timeline_api.py`，在 `server.py` 末尾 `register_*` 挂上去 | 整合包升级、模型替换都不影响；出问题能一行注释掉回退 |
| **磁盘即真相** | 状态由音频文件 + 文本指纹推导，不信任内存 | 关页面、崩服务、手改 JSON 都不会"显示未生成但能播" |
| **数据与派生分离** | 台本存"内容"，时间轴只存"差分" | 改台本不会冲掉排布；重生成不会让时间轴全乱 |
| **一套派生规则** | 时间码永远由「顺序累加 dur + pause」算出来，不落盘 | 副本/初始样本/时间轴三处永远一致，没有"同步表"要对 |
| **编辑即工程** | 进时间轴自动建"工程副本"（硬链接音频） | 类似 PS/AE 的"新建工程"，原稿永远是安全区 |
| **能导出到专业软件** | rpp / EDL / Audacity / 混音成品 | 不自建"半吊子 DAW"，把重活交给成熟工具 |

## 3. 总体架构

```
┌──────────────────────────── 浏览器 ────────────────────────────┐
│  /            原整合包主界面（不改）                            │
│  /longform    长篇台本页  longform.html/js/css                   │
│  /timeline    时间轴页    timeline.html/js/css                   │
│      │  fetch /api/v1/lf/*                                      │
└──────┼──────────────────────────────────────────────────────────┘
       │
┌──────▼──────────────── FastAPI（同一进程）──────────────────────┐
│  server.py                                                      │
│    ├─ 原有路由（推理、模型、任务队列…）                          │
│    └─ 末尾：                                                     │
│        try: register_longform(app, api, deps)   # /lf/*          │
│        try: register_timeline(app, deps)        # /lf/tl/*       │
│                                                                 │
│  longform_api.py   台本 CRUD / 批量渲染 / 导出 / 历史 / 预设     │
│  timeline_api.py   轨道 / 片段 / 素材 / 峰值 / 混音 / 工程导出   │
│         │                                                       │
│         └─ 复用原有推理函数 + 同一把推理锁（串行执行，不抢显存） │
└─────────────────────────────────────────────────────────────────┘
       │
┌──────▼──────────── 数据目录（绕开原程序的清理策略）────────────┐
│  longform/                                                      │
│    scripts/<sid>/                                               │
│      script.json          台本（内容 + 每行状态 + 生成快照）     │
│      project.json         时间轴差分（轨道/片段覆盖/素材）       │
│      initial_script.json  进入时间轴那一刻的初始样本             │
│      audio/<uid>.wav      每句音频（文件名 = 行 uid）            │
│      media/*.wav          素材库（上传即转码进工程目录）         │
│      peaks/*.json         波形峰值缓存                           │
│      cache/*.wav          变速预渲染缓存（混音/工程共用）        │
│      export/              导出成品与工程包                       │
│      history/*.json       编辑历史副本                           │
└─────────────────────────────────────────────────────────────────┘
```

**为什么独立数据目录**：原程序的 `outputs/` 常有 7/14 天清理、`prompts/` 有 LRU；
长篇工程动辄几百个文件、几十小时，必须有自己的生命周期。

## 4. 数据模型（迁移时最需要照抄的部分）

### 4.1 `script.json`：台本

```jsonc
{
  "id": "320f1a7be229",
  "title": "台本 主要实验1",
  "created": "2026-10-22 03:10:11",
  "defaults": {              // 全局默认参数（新行继承）
    "ref": "refs/xxx.wav",   // 音色
    "emo_mode": 0,           // 0=同音色 1=情感音频 2=向量 …
    "emo_weight": 1.0,
    "pause": 200,            // 句间停顿 ms
    "sampling": { "temperature": 0.8, "top_p": 0.8 }
  },
  "sampling": { ... },
  "tag_presets": [ ... ],    // 句中/句间标签预设（音效名 + 默认时长）
  "project": {               // 只有"工程副本"才有
    "source_id": "原台本 id",
    "source_title": "原台本名",
    "initial_at": "2026-10-23 03:44:10"
  },
  "lines": [
    {
      "uid": "7186ba3ef3",     // ★ 稳定 id：音频文件名、时间轴片段、峰值缓存都用它
      "index": 1,              // 显示用序号（工程副本里也保持不变）
      "kind": "speech",        // speech | tag
      "text": "（很轻）晚上好呀……",
      "out": "7186ba3ef3.wav", // 生成后的音频文件名
      "dur": 14.92,            // 真实音频时长（派生时间码的依据）
      "status": "done",        // pending | queued | running | done | stale | error
      "sig": "a1b2c3…",        // ★ 文本+参数的指纹，用来判断"改动是否影响已生成音频"
      "pause": 200,            // 行级停顿覆盖（不写=用 defaults）
      "ref": null, "emo_mode": null, "emo_weight": null,   // 行级覆盖（null=继承）
      "gen": {                 // ★ 生成时的参数快照（用于"改了什么"标注 / 撤回）
        "text": "…", "ref": "…", "emo_mode": 0, "pause": 200, "sampling": {...}
      },
      "changes": [ ... ],      // 后端算出的差异（前端只负责显示）
      "can_revert": true
    },
    {
      "uid": "umvihwfr9j46tf", "kind": "tag",
      "tag": "摩擦音", "hold": 800, "inline": true   // inline=句中标签
    }
  ],
  "batches": [ ... ]           // 批量渲染任务记录（可选）
}
```

**三个字段是整个系统能"增量"的基础**：

- `uid`：**永不改变**。音频文件名 = uid，时间轴片段 id = uid，峰值缓存 key = uid。
  只要 uid 稳定，"重生成某句"就只是覆盖 `audio/<uid>.wav`，时间轴不需要重建。
- `dur`：真实时长。时间码**不是存下来的**，而是每次由 `dur + pause` 顺序累加算出来
  （见 5.4），所以永远不会出现"存储的时间码和音频对不上"。
- `sig`：`hash(text + 影响声音的参数)`。渲染完成后写入；台本被编辑时重算 sig，
  不一致 → `stale`（需重生成）。这是"状态自愈"的核心。

### 4.2 `project.json`：时间轴（只存差分）

```jsonc
{
  "rev": 1761...,
  "tracks": [
    { "id": "voice", "name": "语音", "kind": "voice", "gain": 1.0, "pan": 0.0, "mute": false, "solo": false },
    { "id": "t3fa21", "name": "素材", "kind": "sfx",  ... }
  ],
  "clips": {                       // ★ 只存"和默认派生值不一样的地方"
    "7186ba3ef3": { "start": 4.216, "trim_start": 0, "trim_end": 0,
                     "gain": 1, "pan": -0.3, "speed": 1.25,
                     "mute": false, "locked": false, "fade_in": 0.2, "track": "voice" }
  },
  "sfx": [                          // 插入的素材片段（完整记录，没有"默认值"可派生）
    { "id": "s_ab12", "media": "关门.wav", "name": "关门",
      "track": "t3fa21", "start": 12.4, "dur": 2.0, "offset": 0,
      "gain": 0.8, "pan": 0.4, "speed": 1, "mute": false, "locked": false,
      "fade_in": 0, "fade_out": 0.3 }
  ]
}
```

**为什么语音片段只存差分**：一句台本的默认位置由台本顺序决定（第 3 句就在前两句后面）。
用户拖动它才需要记录 `start`。这样：
- 台本里改文本、重新生成 → `dur` 变 → 没被手动拖过的片段自动跟着走（时间关系同步）；
- 用户手工排过的片段保持原位；
- `project.json` 极小（几百句也就几十 KB）。

### 4.3 `initial_script.json`
进入时间轴那一刻 `script.json` 的完整快照。作用：
- "回到初始样本"按钮（把 lines 恢复成快照）；
- 时间轴里显示每句「初始样本时间码 vs 当前时间码」的偏移。

## 5. 关键机制：问题 → 方案 → 实现位置

### 5.1 状态自愈（别让 UI 骗人）

**问题**：自动保存、手改 JSON、异常退出，都会让 `status` 和磁盘实际不符。

**方案**（`longform_api._render_statuses` / `_merge_runtime`）：

```
读台本时，对每一行：
  文件存在 且 sig 与当前文本/参数一致   → done
  文件存在 但 sig 不一致               → stale（有旧音频，可试听，但不进混音）
  文件不存在                            → pending
  正在队列中                            → queued / running（内存标记）
```

**要点**：`status` 是**派生值**，不是可信存储。任何时候重启服务，状态自动正确。

**2026-10 补强**（`_heal_status`）：自愈抽成独立函数，`_load_script` 与 `_merge_runtime` 共用，
并补上「stale 但 sig 一致 → done」这一条。原因是重生成完成后，客户端仍带着旧的
`status: "stale"` 回传，服务端如果无条件尊重它，就会把刚生成好的行又写回 stale ——
表现为「点了重生成，音频好了，标签还是需重生成」。
现在的判定只看两件事实：**文件在不在**、**sig 等不等于当前内容**。

### 5.2 生成快照 → "改了什么" → 一键撤回

**问题**：用户改了音色/情感/停顿，标签变成"需重生成"，但不知道改了什么，
也不知道改回去能不能恢复成"完成"。

**方案**：
1. 渲染成功时把当时的**全部影响声音的参数**写进 `line.gen`（`_gen_snapshot`）。
   ⚠️ 坑：最初用"合并默认值后的有效参数"取值，但那个函数不返回 `text`，
   导致 `gen.text` 永远为空、文本改动检测不出来 —— 必须显式读 `line["text"]`。
2. 读台本时对比 `gen` 与当前值（`_line_changes`），产出结构化差异：
   ```json
   { "field": "text", "label": "文本", "kind": "插入", "insert": "【追加】", "changed_chars": true }
   ```
   文本 diff 用 `difflib.SequenceMatcher` 找最小差异块（`_text_diff`），
   **不要**简单截断前 40 字比较（那样"追加一句话"会显示成"文本没变"）。
3. 前端渲染成行内小标签（`chgchip`）+ `↩ 撤回` 按钮。
   `PATCH /scripts/{sid}` 直接把 `changes` / `statuses` 一并回传（`applyLineMeta`），
   所以改完属性立刻能看到「改 N」和「权重 0.65 → 0.9」，不用重新拉整份台本。
4. 撤回 = `POST /lines/{uid}/revert`：把行上的覆盖值全部改成 `gen` 里的值，
   重算 sig（此时会等于原 sig）→ 状态自动回到 `done`，音频不用重跑。

**迁移要点**：`gen` 里必须包含"只要变就会影响音频"的所有字段：
文本、音色、情感模式/权重/向量/参考音频、分段切分参数、采样参数、停顿（若停顿参与音频生成）。

### 5.3 工程副本（PS/AE 式")

**问题**：用户进时间轴会改动、裁剪、删除，原台本必须安全。

**方案**（`POST /lf/scripts/{sid}/project`）：
1. 新建目录 `scripts/<new_sid>/`；
2. `script.json` 深拷贝，并写入 `project = {source_id, source_title, initial_at}`；
3. `audio/`、`media/` 用**硬链接**（同盘秒级、不占额外空间；改动新文件不会影响旧文件）；
4. 存 `initial_script.json`；
5. 返回新 sid，前端跳 `/timeline?sid=<new_sid>`。

**要点**：
- 硬链接失败（跨盘/权限）→ 回退 `copy2`，不能因此报错；
- 工程副本里**句序号不变**（`index` 保留），只是时间和参数可变；
- `POST /restore-initial` 从 `initial_script.json` 恢复 lines 与项目参数。

### 5.4 时间轴派生：唯一一条规则

```python
cursor = 0
for line in lines:
    if line.kind == "tag":
        cursor += line.hold / 1000          # 标签只占留白
        continue
    dur = line.dur or 字数 / cps            # 未生成时按字数估
    clip = { "start": cursor, "dur": dur, "offset": trim_start, ... }
    cursor += dur + pause / 1000
```

派生时再叠加 `project.json` 里的差分（拖动过的 `start`、裁剪、增益、声像、轨道…）。

**由此自动获得的性质**：
- 副本与源台本时间关系天然同步（同一套规则 + 同一批 `dur`）；
- 改文本重生成 → `dur` 变 → 后续片段顺移（想固定就手动拖，会写入差分）；
- 「锁定」= 不允许写差分（服务端也校验，不只靠前端置灰）。

> ⚠️ 第一次做时踩过：`_initial_timeline()` 用 `line.get("pause")` 而不是"有效停顿"
> （行级为 null 时应取 defaults），导致初始样本时间码比实际早 0.2s。
> **派生函数必须共用同一个"取有效参数"的实现**。

### 5.5 多轨：类型约束 + 重叠分流

- 轨道有 `kind`（voice / sfx）。语音片段只能进 voice 轨，素材只能进 sfx 轨
  （前端拖拽时校验 + 后端保存时兜底）。
- 同一轨两段重叠会产生两路同时出声、导出到 Reaper 也是叠在一起的 item
  → 视觉上能叠，实际混音就"糊"，所以做了**分流**：
  1. 拖动时检测与同轨其它片段是否重叠（只算实心区，被裁掉的"幽灵区"不算）；
  2. 重叠**保持 0.5 秒**才触发（避免擦身而过就跳轨）；用 `setTimeout` 而不是
     "在 mousemove 里累计时间"，否则鼠标停住不动永远不会触发；
  3. 优先放进**同类别的空白轨**；没有空白轨才新建一条（按拖拽方向插在当前轨上/下方）；
  4. 松手时再兜底检查一次，保证最终不留重叠。

### 5.6 素材库与标签：标签是"吸附点"不是"内容"

- 台本里的句中/句间标签（音效点）**不占时间轴轨道**，只变成画布上的**标记线**：
  - 拖素材靠近标记 → 自动吸附对齐；
  - 鼠标在标记线附近（窗口宽度 10% 内）→ 出现"插入素材"提示；
  - 该位置已经有片段 → 不提示（否则会误导）。
- 提示窗**不能接收鼠标事件**（`pointer-events:none`）：否则它出现在光标下方，
  会抢走 hover → 画布触发 mouseleave → 自己消失（闪烁）。改为"纯展示 + 点画布插入"。
- 素材上传即转码（44.1k 单声道）并落到**工程目录** `media/`，随工程走、可重命名、可删除。

### 5.7 播放：为什么最后换成原生 `<audio>`

第一版用 Web Audio（`AudioBufferSourceNode` + 调度窗口）。问题：
- 片段要 fetch + `decodeAudioData`，首播有延迟；
- "需重生成"的句子被 `playable=false` 过滤掉，明明有音频却听不到；
- 用户环境里各种"看不到波形/没声音"的排查成本极高（headless 测不出真实出声）。

第二版改为**每个片段一个 `HTMLAudioElement`**（池化复用，挂到隐藏容器）：

```
play(): 记录起点 → 每 60ms tick：
  对当前时间窗内应发声的片段 → audio.currentTime = offset + (pos - clip.start)
                              → playbackRate = speed, volume = clip.gain × track.gain
  离开片段的 → pause()
seek()/pause(): 全停 + 复位
```

**优点**：浏览器原生管线，出声最稳；变速直接 `playbackRate`；不需要 AudioContext 权限。
**代价**：无法做实时声像（左右声道）与实时倒放 → 声像只在**混音导出**里生效（导出才是成品）。
> 结论：**试听用原生播放器，效果用服务端渲染**，这个分工比全押 Web Audio 稳得多。

### 5.8 电平表：不接管输出也能动

需求是"播放时看到音量与 L/R 电平"。若用 `MediaElementSourceNode` 接管输出，
一旦 AudioContext 被挂起就又回到"没声音"的老坑。

**方案**：按"当前播放位置命中了哪些片段" + 各片段**缓存的波形峰值** + 增益/声像/淡入淡出，
推算左右电平：

```
amp = peak[位置比例] × clip.gain × track.gain × 淡入淡出包络
L += amp × cos(θ),  R += amp × sin(θ),   θ = (pan + 1) × π/4
```

再套硬件表手感（起快落慢），显示 `dBFS = 20log10(max(L,R))`。
峰值未加载时给 0.22 的保守值，保证表会动。

### 5.9 混音与工程导出（坑最多的一块）

**混音**（`_render_mix`）：分块流式（默认 1 秒一块），内存只占一块；
单块内按 `[a,b)` 与每个片段求交集、读源、加淡入淡出包络、按声像分配到 L/R、
累加、`clip(-1,1)`、写盘。所以 2 小时工程也不会爆内存。

**工程导出**：
| 格式 | 做法 | 关键坑 |
|---|---|---|
| Reaper `.rpp` | 手写文本工程：TRACK / ITEM（POSITION、LENGTH、SOFFS、VOLPAN、FADEIN/FADEOUT、SOURCE FILE）+ MARKER | ①**变速片段用预渲染文件**（从内容 0 秒开始），`SOFFS` 必须写 0，否则 Reaper 里会再跳一段；② `fade_in/fade_out` 曾经没被保存（清洗函数漏字段），导出就没有淡入淡出 |
| CMX3600 EDL | 一行一个片段：源入/源出/记录入/记录出 + 25fps 时间码 + `* FROM CLIP NAME` / `* TRACK` | ①源入点必须是片段真实偏移（裁过的片段否则错位）；②EDL 天生不带音量/淡入淡出/声像/变速，必须在说明里讲清楚 |
| Audacity 4 | `.aup3` 是 SQLite 数据库，无法外部生成 → 给「每轨一条从 0 秒开始的 WAV + `labels.txt`（Audacity 标签轨 TSV）+ 导入说明」 | 分轨必须**都是 0 秒起点**，导入后时间轴才天然对齐 |

> 通用的产品判断：**不要试图自己造 DAW**。把自己定位成"时间线数据源"，
> 输出业界能读的格式（rpp/EDL/WAV+标签），后面的事交给专业软件。

### 5.10 采样率与格式

- 输出格式：WAV(16/24/32f) / FLAC(16/24) / MP3 / OGG，可选声道（1/2）、采样率（16k~96k）、
  时段（开始/结束秒）、行范围。
- **重采样**：优先 `soxr`（流式 `ResampleStream`，块边界无爆音），其次 `scipy.signal.resample_poly`，
  最后 `np.interp` 兜底。混音是**边混边重采样**（每块喂给流式重采样器），不落中间文件。
- **体积预估**：WAV/FLAC 用 `时长 × 采样率 × 声道 × 位深` 算；
  有损格式按实测码率表折算（本机没有 ffmpeg/lame，libsndfile 内置编码器码率上限较低：
  MP3≈48kbps、OGG≈31kbps @44.1k 立体声），并在 UI 明确写"要高保真请选 WAV/FLAC"。
- 导出后**返回真实大小与码率**，用实际值校正用户预期（预估只是参考）。

### 5.12 音色素材库与「前期准备」工具链

**问题**：真实工作流不是「打开台本就念」——素材常常是视频、是带 BGM 的歌、是手机录的带底噪的音频。
这些必须在进台本/时间轴之前处理干净，否则 TTS 的参考音色会带噪、时间轴素材会带 BGM。

**方案**：独立的**素材库（全局，不随台本）** + `ffmpeg` 内置 + 一组 DSP 处理。

```
longform/materials/
  index.json                 # 元数据（id/file/name/kind/source/op/parent/dur/sr/ch/size/created）
  <名字>_<id>.wav            # 统一 44.1kHz WAV（PCM16）
  .trash/                    # 删除是移进来，不是 rm
bin/ffmpeg.exe               # 随包内置（≈84MB，LAME/AAC/Vorbis/FLAC 编码器齐全）
```

**导入链路**（`POST /lf/media/upload`）：

```
上传(音/视频) → 写临时文件 → 能 sf.read 就直接读；读不了交给 ffmpeg 解成 wav
→ 取前 2 声道 → soxr 重采样到 44.1k → 写 materials/ → 记 index
```

- 视频只取音轨（`-vn`），不需要用户自己先转格式；
- 音频保留立体声（分离人声必须靠左右差异），不做默认降混；
- 单文件上限 512MB（`MAT_MAX_BYTES`），超了直接 413；
- ffmpeg 是**可选增强**：找不到时音频仍可导入，只是视频/罕见容器不行，能力接口会告诉前端。

**处理链路**（`POST /lf/media/{id}/process`，固定顺序执行，产出**新素材**不覆盖原件）：

| 顺序 | 操作 | 实现要点 |
|---|---|---|
| 1 | 裁剪时间段 | 按秒切片，先裁能省后面所有步骤的算力 |
| 2 | 提取人声 / 伴奏 | 见下 |
| 3 | 降噪 | 谱减：每频点取能量最低 15% 帧估噪声底，减 `k×noise`，留 2~10% 底 |
| 4 | 去首尾静音 | 20ms 帧 RMS 与阈值比较，找首尾，留 60ms 余量 |
| 5 | 响度标准化 | 峰值归一（不削波）或 RMS 归一（听感均匀） |
| 6 | 淡入淡出 | 线性斜坡 |
| 7 | 采样率/声道转换 | soxr + 单声道降混 / 立体声复制 |

**人声分离（中置提取）的数学**——零模型、秒级、可解释：

```
SL, SR = STFT(L), STFT(R)
sim = 2|SL·conj(SR)| / (|SL|² + |SR|² + ε)        # 0..1 左右相干性
mask = clip(sim, 0, 1) ** (1.5 + 4.5·strength)     # 强度越大掩码越硬
mid = (SL+SR)/2 ; side = (SL-SR)/2
人声 = iSTFT(mid · mask)
伴奏 = iSTFT(side + mid · (1 - mask))
```

为什么这样有效：人声（尤其旁白/主唱）几乎总是**居中且同相**，左右相干性接近 1；
而伴奏的乐器分布在不同位置、混响去相关，相干性低，被掩码压掉。

**必须接受的限制**（写进 UI 提示，不要藏）：
- 伴奏本身也在中间（大量流行歌）时一定会有残留，这是 DSP 的物理极限；
- 单声道素材**无法分离**（左右已合并），接口直接 400 而不是假装处理；
- 会轻微损伤人声高频（掩码把部分谐波一起压了），强度别拉满。

**DSP 的工程细节（都是踩过的坑）**：
- **分块处理**：20 秒一块、0.6 秒交叉淡化，避免 10 分钟音频一次 STFT 吃掉几百 MB；
- **纯 numpy STFT**：`sliding_window_view + rfft / irfft`，不依赖 librosa（省掉 numba 冷启动）；
- **iSTFT 要除以窗平方和**，否则重叠相加后音量起伏；
- **单声道降混必须放在分离之后**（先降混就永久丢失左右差异）。

**与其余系统的连接**：
- 处理出的「人声」→ `POST /lf/media/{id}/as-ref` 注册到音色库（hash 去重 + 改名磁盘文件），
  台本里立即可选；
- 也可以直接拖进时间轴的素材轨（时间轴 media 同样是 44.1k WAV）；
- 素材库是**全局**的，不随台本删除；台本删除不会连带素材。

### 5.13 编辑体验：回车语义、右键菜单、批量改属性、进度与统计（2026-10）

这一批都是"手感"问题，实现不复杂，但几个坑值得记下来。

**回车语义**（`onRowKey` / `splitLine` / `insertLineAfter`）
- 句中回车 = 切分：左段留在本行，右段成为新行，`inline` 标签按位置分到两边；
- 句末回车 = 在**本行下方**插入空行（不是追加到文末），并聚焦到新行；
- 有选区时先删掉选中的字再切（`deleteSelectedText` 会同步平移标签位置）。
  早期实现是「光标在行尾就提示没有可切分的内容」，等于逼用户去点底部按钮，手感很差。

**右键菜单**（`openLineCtx` / `buildCtx` / `showCtxAt`）
- 编辑区 `.row` 与工作台 `.bcard` 共用一个函数，菜单项：编辑属性、复制文本、
  复制这一句（新 uid，音频置空）、只选/往前全选/往后全选、插入空行、插入标签、
  试听/重生成/导出、撤回、删除。
- 全选只取 `visibleEntries()`（当前筛选后可见的行），避免"选中了看不见的行"。
- 右侧面板的「⋯ 更多」`openSideMenu`、台本卡片 `openScriptMenu` 与行菜单
  复用同一个 `#ctxMenu` 元素，注意切换时清掉 `.wide` 类。

**批量改属性**（`openBulkProps`）
- 每个字段一个勾选框，只有勾了的才写进 `line.ov` / `line.pause`；
- 已生成的行转 `stale`，然后走正常的 `saveNow()`（它会带回新 changes）。

**进度条**（`paintRender` + `.progresswrap.ps-*`）
- 总进度 = `(done + line_progress) / total`，比只看句数平滑；
- 模型阶段来自 `GET /render` 新增的 `model` 字段（`tts.state()` 的 `phase`）：
  `unloaded / loading / ready / error / unloading / reloading`；
- `done == 0 && phase != ready` 时进度条进入"不确定"形态（CSS 动画来回扫），
  同时阶段药丸停在第①步 —— 否则用户看到 0% 会以为卡死；
- 样式只切 class（`ps-bar / ps-glow / ps-seg / ps-stripe`），记忆在 `localStorage["lf.progStyle"]`。

**统计**（`_stats`）
- 旧实现把"有音频"和"状态 done"混着用，`done` 一旦被 stale 覆盖，顶栏就永远显示不对；
- 现在一次算清：`done / stale / pending / error / running / has_audio / audio_dur /
  est_dur / rate`，各状态**互不重叠**，前端 chips 直接读，并且可点击筛选；
- `est_dur` = 已有音频 + 未生成字数 / 实测语速 + 行间停顿 + 标签留白，
  语速用已生成行的 `字数 / 时长` 反推（没有就按 3.5 字/秒）。

**音色 / 素材的多种显示方式**
- `REFV.view` / `MAT.view` 存在 localStorage，渲染时只换容器 class
  （`mode-list / mode-card / mode-grid`），DOM 结构按模式分别构建；
- 右键菜单与列表/卡片/网格共用同一批动作函数（`matAsRef` / `runMatPreset` …），
  避免"换了个显示方式按钮就不能用了"。

### 5.14 音效素材库 + 标签挂音效 + 时间轴自动落位（2026-10）

**为什么单独一个库**
音色（参考音频）和音效（成品音）用途不同：前者被行引用、只取前 10 秒；
后者被标签引用、要保留完整长度。混在一个 `materials` 里会让「素材预处理」的
列表一半是音色一半是音效。所以：
`longform/sfx/index.json` + `longform/sfx/*.wav` 独立存放，
预处理复用 `_apply_ops()`（与素材库同一套顺序），只是结果写进音效库。

**数据结构**：标签行多一个字段
```json
{ "kind": "tag", "tag": "门铃", "hold": 600,
  "sfx": { "mid": "音效id", "gain": 1.0 } }
```
`hold` 同时是「留白」和「音效延迟」——这是刻意的：用户只填一个数，
音效必然出现在「标签时间 + 留白」，时间轴与台本页永远对得上。

**时间轴派生**（`timeline_api._build`）
- 扫到 `kind=tag` 时记下 `tag_time`，`start = tag_time + hold/1000`；
- 音效文件按需拷进 `<工程>/media/`（`_media_dir`），混音/工程导出都读这里；
- 派生的片段 `id = tagsfx_<标签uid>`、`locked=True`、`from_tag=<uid>`，
  每次都从台本现算，不写进 `project.json` —— 这样改留白/换音效立刻生效，
  也不会和时间轴里手动插的素材混淆；
- 标记（markers）带上 `sfx_mid`，右侧标记列表据此显示 🔔。

**坑：工程副本不跟着源台本变**
`POST /scripts/{sid}/project` 是**复制**一份（原台本留作初始样本），
所以在源台本上改标签不会影响已有工程。测试时踩过：改留白后时间轴没动，
其实是改错了文件。UI 上要在工程副本里改，文档也要写明。

**坑：撤销删除后标签变「未生成」**
删除只删行、不删音频；撤销把行整体恢复。但旧版 `payloadLines()` 只回传
文本/参数，不回传 `out/dur/sig`，服务端把它当新行 → `out=None` → 未生成。
修法两层：
1. `payloadLines()` 带上 `out/dur/sig/elapsed`；`_merge_runtime` 遇到「服务端没有
   这一行」时，先看客户端给的 `out` 文件还在不在，在就保留；
2. 历史快照里的运行态会过期（重生成之后撤销，恢复的是生成前的旧指纹），
   所以 `syncScriptMeta()` 成功后调 `refreshHistoryRuntime()`，
   把 UNDO/REDO 快照里的 `out/dur/sig/gen/status` 按当前行刷一遍（文本不动）。
另外 `_merge_runtime` 补了一条：客户端带来的旧 `sig` 与服务端新 `sig` 冲突时，
若服务端 `sig == 当前内容指纹`（说明刚生成过），以服务端为准。

**重命名弹窗为什么会「跑到工作台上」**
`#drawer` 的 z-index 是 120，`#modal` 原来只有 100 —— 从抽屉里点重命名，
居中的 modal 其实被压在抽屉下面，看起来像弹在了外面的工作台。
除了把 modal 提到 160，这类「一步输入」统一换成 `promptAt()` 小卡片
（`#popcard`，z-index 170）：贴着鼠标出现、靠近底部自动翻到上方、
回车保存、Esc/点外面取消。删除确认这类需要看清楚的仍用 modal。

### 5.15 试听/导出/文件管理的一次收口（2026-10）

**「停止播放」为什么要一个登记表**
之前每个面板各拿一个 `new Audio()`（行试听、音色、素材、音效、弹窗里的临时试听），
谁也不知道谁在播：切到另一个面板时前一个还在响，关掉抽屉也停不下来。
现在统一成 `PLAYERS: Map<HTMLAudioElement, onStop>`：
`regPlayer()` 登记，`stopAllAudio()` 全部 pause + 归零时间 + 回调复位状态；
每次点新播放先 `pauseOthers(audio)`。顶栏「⏹ 停止播放」、Esc、关闭抽屉、
关闭弹窗、切换台本都走同一个出口。

**筛选「有句中标签」**
`FILTER.status` 增加 `inline` / `inline0` 两个取值，判定就是 `line.inline.length`；
工具栏再加一个「只看句中标签」按钮与下拉联动（按钮高亮 = 正在筛）。

**行尾「⋯」没反应**
不是没绑定，是被自己的全局监听吃掉了：`document.addEventListener("click", ...)`
用来点外部关菜单，而按钮的 click 冒泡到 document 时菜单刚打开就被关掉。
右键能开，是因为 contextmenu 不触发 click。修法：打开菜单的按钮 `e.stopPropagation()`。
（同类按钮：台本卡片的「⋯」、面板「⋯ 更多」当年也是这么修的。）

**导出格式：一条编码链**
`_encode_audio(data, sr, fmt, bit_depth, quality, channels, sample_rate)` 是唯一出口，
单句下载（`GET /audio/{uid}?format=...`）与 ZIP（`_export_lines_zip(..., fmt=...)`）共用：
先定声道（单声道取平均、立体声复制）→ 重采样（soxr/scipy/线性）→ libsndfile 编码。
坑：`sf.write()` **没有** `channels` 参数（声道由数组形状决定，`channels=` 只属于
`SoundFile` 构造器），传了会直接 `TypeError`。
ZIP 只有在「导出参数正好等于源文件（22050 单声道 WAV）」时才直接 `zf.write`，不重编码；
现在默认导出声道是立体声，所以默认走重编码（见 §5.16）。

**文件管理：音色只存模型认识的东西**
音色是喂给模型的，模型只认 22050 单声道 PCM WAV。所以 `POST /lf/refs` 现在
先解码（wav/mp3/flac/ogg/m4a 都行，视频不行）→ 混单声道 → 重采样 22050 →
写 WAV → 用**归一化后的波形**算 sha1 做 id。效果：
- 模型侧不会拿到读不出的文件；
- mp3 和 wav 传同一段音频会落到同一条（去重）；
- 三个库各管一摊：`longform/refs/`（音色，22050 单声道 WAV）、
  `longform/sfx/`（音效，44.1k WAV，可选立体声）、`longform/materials/`（中间素材）。

**音效预处理：换一套动作**
音效和「参考音频」的处理目标完全不同，硬套音色那套（人声分离 + 裁前 15 秒）不成立。
`_apply_ops()` 扩了 `filter(hp/lp)`、`gain_db`、`speed`、`pitch`、`reverse`，顺序：
裁剪 → 分离 → 降噪 → 去静音 → 滤波 → 增益 → 变速 → 变调 → 标准化 → 反向 → 淡入淡出 → 转换。
- 变速用 audiotsm WSOLA（保持音高），失败退回重采样并在标签里标注「(变调)」；
- 变调 = 重采样到 `sr/r` 再按 `1/r` 做 WSOLA：音高 ×r、时长不变。
  ⚠️ 写成 `sr*r` 会反着来（时长 ×r），实测 5 半音变成 1.78s 才发现；
- 滤波用 scipy 二阶巴特沃斯（低切去轰鸣、高切去嘶声）。
前端按「去向」切两套卡片（`#matOpsVoice` / `#matOpsSfx`）与两套快捷预设，
`collectMatOps()` 分派到 `collectVoiceOps()` / `collectSfxOps()`（2026-10 后由
`MAT.target` 决定，不再是作用域，见 §5.16）。

**视频进音效库会不会污染混音？**
不会。`_decode_upload()` 只把音轨读成波形，`_save_sfx_item()` 落的是 44.1k WAV，
视频文件根本不入库；时间轴从音效库取素材时 `POST /media/from-sfx` 拷的也是这条 WAV，
混音/工程导出（rpr/EDL/分轨）读的同样是 WAV。所以功能保留，只在 UI 上说明「视频只取音轨」，
并对 >60s 的音效给一次「会盖住后面的语音」提醒。

### 5.16 素材导入台：文件流转收口 + 声道/属性 + 导出默认立体声（2026-10）

**问题：三个地方都能「处理音频」，共用一个面板靠作用域切换**
`#drawer` 的 media 面板原来由 `MAT.scope` 决定「读写 /media 还是 /sfx」，
处理卡片也按作用域切换。用户从「音效库 → 音效预处理 → 切回素材」时，
面板切回 `/media`，看到的是导入台里历次上传/派生的一堆中间文件 —— 数据没错，
但**语义是错的**：同一个面板一会儿显示音效库、一会儿显示中转站，谁也说不清
「我看到的这些到底入库了没有」。

**方案：一条单向流水线，导入台是唯一入口**
```
上传/拖拽（批量） → materials（导入台，44.1k WAV，保留声道）
                       │  ops（可选）
                       ├─→ refs（音色，22.05k 单声道 WAV）
                       └─→ sfx （音效，44.1k WAV，声道不变）
```
- `MAT.target ∈ {ref, sfx}` 取代 `MAT.scope`：**只决定去向与用哪套处理项**，
  列表永远是 `/media`；`matApi()` 固定返回 `/media`；
- `POST /lf/media/{mid}/store {target, ops, remove_source}` 是唯一出口：
  处理与入库一步完成，导入台不再产生「处理结果」中间文件；
- `POST /lf/media/clear {ids} | {all:true}`：**安全阀**——ids 为空且没传 all 直接 400。
  （踩过：测试里传 `{}` 把用户上传的 11 个素材全清了，只能从 `.trash` 里按 id 逐个恢复。）
- `POST /lf/media/from-sfx`、`/from-ref`：把已入库的东西拷回导入台再改，
  原点保留 → 想「在旧音效基础上调一版」不用重新上传。
- 前端 `applyMatTarget()` 统一刷新：去向按钮高亮、处理卡片显隐、
  快捷预设行、主按钮文案、抽屉标题。

**声道：默认「不变」是刻意的**
`_apply_ops` 的 convert 段本来就是 `ch = int(cv.get("channels") or data.shape[1])`，
即没选就跟随原文件。这次把它在 UI 上说清楚（选项文案「声道不变（原文件）」），
并明确唯一例外：**存入音色库必须单声道**（模型只认 22.05k 单声道 PCM）。
存入音效库只重采样到 44.1k，声道原样保留（`_save_sfx_item` 只在 >2 声道时才截断）。

**音频属性**
`_audio_props(path)` 用 `sf.info` + `os.stat` 给出：容器/子类型、位深（PCM_16→16）、
采样率、声道数与「单/双」文案、时长、码率（size×8/dur）、大小。
三个 `GET /lf/{media|sfx}/{mid}/info`、`/lf/refs/{rid}/info` 共用它，
前端 `showAudioProps(kind, id)` 渲染成表。右键菜单里三个库都加了「ℹ 属性」。

**导出默认立体声**
`_encode_audio / _est_bytes / _export / _export_estimate / _export_lines_zip /
lf_line_audio` 的 `channels` 默认值 1 → 2，请求侧 `req.get("channels") or 2`。
拼接导出本来就有 `if ch == 2: chunk = np.stack([chunk, chunk], axis=1)`，
所以只需改默认值；ZIP 的「默认参数直接打包不重编码」快路径条件同步改成 `channels > 1` 时重编码。
前端 `exCh` 第一项改为「立体声（双声道，默认）」并 selected，`exOptControls` 默认 2。

```js
const srcDur = Math.max(0.05, c.src_dur || (c.dur + (c.offset || 0)));
const i0 = Math.floor(clamp(c.offset / srcDur, 0, 1) * pk.length);
const i1 = Math.max(i0 + 1, Math.ceil(clamp((c.offset + c.dur) / srcDur, 0, 1) * pk.length));
// 每个像素列在 [i0 + k/n*span, i0 + (k+1)/n*span) 里取 max
```
验证方法（`_shot_trim.py` + 人眼/像素统计）：6 秒 AM 测试音（包络周期 2s），
未裁剪 3 个鼓包；裁到 4 秒后仍是「同频率的 2 个鼓包」而不是把 3 个拉伸塞进更窄的盒子。

### 5.18 三个素材库统一版式 / 导入台跳转 / 内嵌导入台 / 撤销与历史（2026-10）

**1. 素材库版式统一（音色 / 音效 / 预设）**
- 问题：三个面板各写一套（`phead` + `row2` + `optrow` + 说明），标题重复（抽屉头一个、面板里又一个），
  小屏时工具条挤成两行。
- 方案：抽出一套 `.lib*` 结构，三个面板共用：
  `libacts`（主按钮 + 导入台）→ `libbar`（视图切换 / 搜索 / 刷新 / 数量）→ `libhint` → `liblist` → `libfoot`。
  抽屉头改成 `dh-t`（`b` 标题 + `small` 副标题），副标题写「这个库干什么 + 文件从哪来」，
  面板里不再重复大标题。
- 坑：`renderRefList` / `renderSfxList` 里 `box.className = "reflist mode-" + view` 会把新加的工具类
  整个冲掉（列表高度限制失效），必须写成 `"reflist liblist mode-" + view`。

**2. 导入台的「去某个库」跳转**
- 存完最常做的下一步就是去库里用它，所以在「处理并存入」下面加一排 `pfoot.jumprow`：
  `#btnJumpRef` / `#btnJumpSfx` → `openDrawer("voice" | "sfx")`。
- 视觉上用虚线次要按钮（不跟主按钮抢），hover 才染主色。

**3. 时间轴内嵌导入台（不跳转）**
- 时间轴加 `#deskMask` + `#deskFrame`，src 指向 `/longform?desk=1&embed=1&target=sfx&sid=…`。
- 台本页加 `EMBED` 模式：`html.embed` 下隐藏 `lf-head / lfMain / 抽屉头 / modal / popcard`，
  `#drawer` 改成 `position:static`，`.drawer-box` 铺满 100%。
- 双向通信：导入台存成功 → `parent.postMessage({type:"lf-stored", target})` → 时间轴刷新音效库；
  内嵌时按 Esc / 点「关闭」→ `postMessage({type:"lf-desk-close"})` → 父窗口收抽屉
  （否则 iframe 会把自己清成白屏）。
- 坑：`hidden` 属性对 `display:flex` 的元素无效，必须显式写 `[hidden]{display:none!important}`
  —— 否则导入台一进页面就挂在最上层（还带个空白 iframe）。

**4. 撤销 / 重做（快照式）**
- 不做命令模式（编辑点太多、每个都要写逆操作，容易漏）。用「整份 project JSON 快照」：
  `HIST.base` 保存「上一次稳定状态」，改动后 600ms 静默才把 base 推进 undo 栈、base 换成当前。
  → 拖滑杆 / 拖片段这种连续操作自动折叠成一步；`persist()` 路径也会 `undoMark()`。
- `reload()` 里只有 `HIST.timer == null` 时才对齐 base：`persist()` 是「改完立刻存+重载」，
  若无条件对齐，会把刚发生的改动提前吸收掉，撤销栈永远是空的。
- 撤销 = PATCH 整份快照 + 重新拉时间轴；顺带把选中的片段清掉。

**5. 历史版本（落盘）**
- `timeline_history/` 与台本页 `history/` **必须分开**：两边格式不同，串了会互相清空数据。
- 每次 save 后节流 90s 自动存一份；`HISTORY_KEEP=40` 滚动清理；回退前先存「恢复前」。
- 列表项时间用的是 epoch 秒（float），前端别直接 `.slice()`（会 `is not a function`）。

**6. 标签音效的「落轨」修复（串轨 + 重叠的根因）**
- 现象：删掉一个素材，别的片段自己挪到另一条轨，还叠上了。
- 根因有三层：
  1. `_build` 把标签派生的音效**永远**放在第一条素材轨（`sfx_track`），两个标签音效必然叠；
  2. 派生片段不在 `project.sfx` 里，`commitClip` 找不到对应项 → 换轨结果根本没落盘，
     任何一次重载（删除、插入、切页都会触发）都会把它拉回第一条轨；
  3. `_load_project`/`_save_project` 遇到未知轨 id 时回落到 `p["tracks"][0]`——而 tracks[0]
     通常是**音声轨**，于是「素材」被塞到了音声轨上（看起来就是片段自己跳轨）。
- 修法：
  · `project.tagfx = {标签uid: {track, gain, mute}}` 持久化派生片段的落轨与属性；
  · `_build` 先按 `p["sfx"]` 建占用表，再给每个标签音效找「该时段空着的素材轨」，
    有 `tagfx.track` 就照办（用户手动搬过就以用户为准）；
  · 未知轨回落改成 `_sfx_fallback()` → 第一条**素材**轨；
  · 删轨时顺带清理指向它的 `tagfx`。
- 派生片段仍保持「位置=标签时间+留白」：删/拆会被拒绝并提示回台本页取消挂载。

### 5.19 智能导入：多格式解析 + 任务模板 + 预览编辑（2026-10）

> 注：这里的「12 个任务模板」后来被 **§5.21 的 5 类（按文本特征）** 取代，
> 解析器（inspect 那一层）与预览编辑仍然沿用；模板相关的 `TEMPLATES` 已删除。

**文件**
- `lf_import.py`：纯逻辑（解析 + 规划），不碰存储，可单独测；
- `longform_api.py`：三个接口 `inspect / plan / commit` + `text`（粘贴）与 `sample`（示例）。

**为什么不把解析放进接口里**
解析出的「中间源」可能很大（一部剧本几万字），换模板/改选项要反复 plan。
`POST /lf/import/inspect` 把中间源落到 `longform/_import/<token>.json`（24h 自动清理），
之后 `plan` 只带 token，前端不用反复上传。

**中间结构（block）**
```python
{"text": "...", "kind": "para|dialogue|action|scene|chapter|cue",
 "role": "阿澈", "scene": "INT. 咖啡馆 - 夜", "chapter": "第一章",
 "page": "第 2 格", "module": "镜头 3", "lang": "中文", "stage": "放松阶段",
 "note": "...", "start": 1.0, "end": 3.2, "next": 3.4}
```
各格式解析器只负责产出 blocks，**分组、过滤、分段全在后面的统一管线里**，
所以加模板不用改解析器，加格式也不用改模板。

**解析要点**
- docx：不装 python-docx，直接 `zipfile` 读 `word/document.xml`，按 `w:p` 取 `w:t`，
  顺带读 `w:pStyle`（Heading 1/2、标题 1）当章节；
- fountain：标题页（`Key: value`）→ 场景头（INT./EXT./内景/外景）→ 角色行（短、无句末标点、
  下一行紧跟正文）→ 括号提示 → 对白；中文角色名没有大小写，所以不能用「全大写」判断；
- srt：按空块切 cue；一条 cue 两行且一行中文一行外文 → 拆成两条 block 并按 CJK 判语种；
- csv：表头关键词自动认列（正文/角色/标签/备注），认不出再退回第 1 列；
  没有表头就当纯数据从第一行读。

**分段器 `split_smart`**
1. 扫描出「括号深度 0」的句末标点作为切点（引号/括号内一律不切）；
2. 按上限合并；
3. 仍超长 → 在深度 0 的逗号/顿号处再切；
4. 找不到安全切点 → **整段保留并标 `over`**，进 issues 让人工拆。
`_safe_cut()` 负责在 `[0, limit]` 里找最靠后的深度 0 位置，找不到返回 -1。

**分组**
`group_by` 支持单词（role/scene/chapter/kind/speaker/module/page/lang/stage）与组合
（`chapter_role` / `page_role` / `lang_role` / `chapter_kind`），组合就是按 `_` 拆开再拼。
模板只提供「推荐值 + 可选值」，用户在第二步随时改。

**几个只有踩过才知道的细节**
- fountain 的角色行不能用 `isupper()` 判断（中文角色名永远不 uppercase），
  要用「短 + 无句末标点 + 下一行是正文」；
- 舞台提示（括号行）**不能单独成段**，否则会念出「收起伞」；统一挂到下一段的 note；
- 场景头不进正文，但可以作为分组键（`group_by=scene`）；
- 漫画的「【第 1 格】小林」：剥掉分格标记后剩下的短名字是角色，
  新一格开始时必须把 `cur_role` 清空，否则下一格的旁白会被算到上一个角色头上；
- 字幕的「延迟」不是新字段，直接算 `next.start - end` 写进行的 `pause`（≤5000ms），
  这样生成和导出的行为与手工调的停顿完全一致。

**提交**
`commit` 只吃前端编辑后的 groups：每个 segment → `_new_line()` +
`group` / `note` / `slow` / `pause`，分组参数写进 `ov`；
每个分组一条 batch（`{id,name,uids,params,created}`），与「新建分组」的效果一致，
所以后面的「按分组生成 / 编辑分组」都不用改。

**映射 CSV**
`GET /lf/scripts/{sid}/export/map` 输出
`序号,uid,分组,正文,附属备注,慢语速,时长(秒),音频文件,状态`，
给后期对轴用；音频文件名来自行上的 `out`，没生成就是空。

新增/变更的数据字段（script.json → lines[]）：
```json
{"group": "店员", "note": "场景：INT. 咖啡馆 - 夜；（雨声）", "slow": true,
 "t0": 1.0, "t1": 3.2}
```
`t0/t1` 只在字幕类来源里有：句子的「出现时间 / 结束时间」（秒），只做对轴与时间轴落位，
不参与 TTS。
`_normalize_line` 会带上这三个字段（只在前端明确给了值时覆盖），所以保存/回滚都不会丢。

### 5.20 智能导入二期：顺序 / 时间码 / 模板示例 / 备注字段 / 重生成判定（2026-10）

**1. 顺序只跟原文，分组只做归类**
- 每个分段带 `i`（全局递增的原文序号）。`plan` 输出时组内按 `i` 排序；
  `commit` 把所有组的分段**按 `i` 全局排序**再写 lines。
- 以前是「按组写行」，角色一交错，台本就变成「先所有 A、再所有 B」，顺序全丢。
- 前端编辑时的 `i` 维护：拆分 → `i + 0.01`（小数插在两段之间）；上移/下移 → 互换 `i`；
  组末新增 → 本组最后一段 `i + 0.01`（没有就 `max + 1`）。`commit` 缺 `i` 的段落到末尾。

**2. 字幕：时间码变成属性，不进正文/备注**
- srt 的 cue → block 带 `start/end/next`；分段上写 `t0/t1`（秒），句间空档写进 `pause`。
- note 不再塞 `"1.00s-3.20s"`（以前整条备注栏都是时间码，还会被导出成「附属备注」）。
- 单语字幕不再按语种分组（只有一种语言时 `lang` 维度自动去掉，避免出现「原文 · 旁白」）。
- 时间轴 `_build` 里：`base_start = max(cursor, t0)`，字幕稿能按原时间落位又不互相压住。
- 双语字幕仍是「一条外文一条中文交替」，因为一条音轨同时只能出一路声；
  只要一种语言就在预览里删掉另一组。

**3. 括号里的停顿（正念/引导）**
- `PAUSE_RE` 同时认 `【】` 与 `（）`：`（停顿 3 秒）`/`（静默 5s）`/`【pause 800ms】`。
- 单独的「（停顿 5 秒）」不占一行，挂到上一段的 `pause` 上。
- `PAUSE_MAX` 从 5s 提到 30s（前端 input 的 max / clamp 同步改）。

**4. 模板说明 + 标准格式示例**
- `TEMPLATES` 每项新增：`formats / detail / rules / sample`。`/lf/import/templates` 直接带出去；
  `/lf/import/template/{tid}` 返回单个模板（也支持 `/sample/{tid}` 取示例文本）。
- 前端：模板卡右上角「?」+ 规则面板「📄 示例 / 说明」→ 同一个弹窗（说明、标签、规则 chip、
  `pre.impsample` 示例、「复制示例」、「用这份示例试一遍」）。
- 坑：`.mask.imp` 是 z-index 200，`#modal` 只有 160 → 弹窗 DOM 在、但被向导压住（看不见）。
  `#modal` 提到 260。

**5. 备注 / 分组 / 慢语速 是「行」的一部分**
- 根因：`payloadLines()` 没带 `group/note/slow`，而 `_normalize_line` 用「没给就是 None」，
  于是前端**自动保存一次就把导入的分组和备注全清空**（看着像导入没生效）。
- 修：`payloadLines` 带上 `group/note/slow/t0/t1`；`_normalize_line` 增加 `t0/t1` 收敛
  （`_num_or_none`）；行属性弹窗新增 分组 / 附属备注 / 慢语速（+ 只读的出现时间）。
- 行上的 `▤ 分组` `✎ 备注` 小标可点（直接进行属性）；没有备注的行悬停出现淡淡的「＋备注」。

**6. 「需重生成」为什么以前会整篇误标（根因）**
- `_line_sig` = `json.dumps([text, ref, emo_*, seg_tokens, sampling])` 的 sha1。
- 浏览器 JSON 往返一趟会把 `0.0` 变成 `0`、`10.0` 变成 `10`（JS 数字没有整/浮之分），
  默认参数一保存，**所有行的指纹就都变了** → 整篇变「需重生成」。
- 两层修法：
  1. `_sig_canon()`：数字统一成 float（0 与 0.0 归一）、列表/字典递归、bool 单独保留；
  2. `_sig_state()`：指纹对不上时再用 `_line_changes(gen vs 当前)` 复核 —— 内容一致就
     认成「不过期」并顺手把指纹换成新算法（老数据自动痊愈）；真改了才 stale。
- `_merge_runtime` 同样改用这一套；另外补上「没有指纹（老数据/手工塞音频）」的分支：
  音频在就是 done，并补一份当前指纹（这里不能借用 `_sig_state`，它没指纹只能返回 False）。
- `pause`/`hold` 不参与指纹：只改停顿不需要重跑（音频本身没变）。

### 5.21 智能导入重构：按文本特征分 5 类（2026-10）

**为什么改**
- 之前是「先选任务目标（12 个模板）」，模板里把「分组方式 + 一堆布尔开关」写死。
  问题是：同一份文本可能既像剧本又像小说，用户得先猜该选哪个模板；而且模板把
  「文本长什么样」和「我要干什么」混在一起了。
- 现在反过来：**先看文本特征** → 判定 5 类之一（可手改）→ 每类各一套切分/分组策略，
  选项按 schema 渲染，加选项不用改前端。

**分类器（lf_import.detect）**
- 抽特征：时间码个数（srt cue / 行首 `[hh:mm:ss]` / 整行时间）、
  「角色：」前缀数与去重角色数、裸角色行数（短行无标点 + 下一行正文）、
  场景头数、成对引号数、指令标签数（含关键词命中）、停顿标记数、
  短行比例（≤20 字的行占比）。
- 打分：timeline（srt=1.0；时间码 ≥2 → 0.55+0.05N）、
  script（角色 ≥2 → 0.62+0.06N；裸角色行 ≥2 → 0.5+0.08N；+场景 0.12；fountain ≥0.9）、
  novel（引号 ≥2 → 0.5+0.06N）、tag（关键词标签 ≥2 → 0.55+0.07N；
  有停顿标记 → ≥0.5+0.08N；短行比例 >0.72 且 ≥10 行 → 0.68）、plain=0.35。
- 交叉惩罚：标签稿 / 停顿稿里的短行不像角色名 → script × 0.6；
  章节标题不算裸角色行（否则小说会被判成剧本，踩过）。
- 取最高分；<0.45 退回 plain。返回 `{cls, score, confidence, evidence[], ranked[]}`，
  前端第二步直接展示「为什么这么判」+ 其他可能性。

**五套策略（`PLANNERS`）**
| 类 | 切分 | 延迟/时间 | 分组 |
|---|---|---|---|
| timeline | 一条 cue 一段（超长再切） | 空档 → pause（`smart/fixed/none`，阈值+系数）；t0/t1 | 不分组 / 语种 / 说话人 / 时间段 |
| script | 角色/场景/动作分块，同角色合并 | — | 角色 / 场景 / 场景+角色 / 章节 |
| novel | 引号（含可选括号）边界切成旁白/台词 | — | 章节 / 旁白·台词 / 章节+旁白 |
| tag | 一行一段（或合并），标签剥离 | 【停顿 x 秒】→ pause（可设上限） | 标签 / 章节 / 不分组 |
| plain | 按长度 / 一句一行 / 一段一行 | 可按段加停顿 | 不分组 / 章节 / 每 N 段 |

**时间轴类的延迟算法（重点）**
```python
gap = next.start - cur.end            # 毫秒
if gap <= gap_min:      pause = 0     # 默认 120ms：字幕连排
elif gap >  gap_max:    pause = gap_max  # 默认 3000ms：换镜头别越拖越长
else:                   pause = gap * scale  # scale 默认 1.0
```
- 一条 cue 拆成多条（多语种/多段）时，**空档只挂在最后一条**，否则每条都带一次停顿，
  整体会慢一倍。
- 纯文本的 `[00:12] 正文` 也能解析成 cue（`_cues_from_text`），end 用下一条 start 推断。

**选项 schema（前端零改动能加选项）**
```python
_o("gap_mode", "延迟策略", "select", "smart",
   [["smart", "智能"], ["fixed", "固定值"], ["none", "不加延迟"]], hint="…")
# type: bool / select / number；带 min/max/step/hint
```
- `defaults_of(cid)` 给默认值；`plan()` 用 `defaults ← opts` 合并，并校验 group_by 合法。
- 每类还有 `presets`（一键套一组选项），前端渲染成一排 chip。

**接口变化**
- `GET  /lf/import/classes`（`/templates` 保留为别名）→ 5 类 + 选项 schema + 预设
- `POST /lf/import/detect` `{token}` → 分类结果（前端第二步顶部那条「识别为…」）
- `POST /lf/import/plan` `{token, cls, opts}`（`template` 仍兼容）
- `GET  /lf/import/class/{cid}`、`GET /lf/import/sample/{cid}`
- commit 里 `import.cls` 记录用的哪一类 + `detect` 证据

### 5.22 时间码识别强化 + 时间轴批量选择（2026-10）

**问题**：`[00:12] 正文` 只认「行首 + 一个空格」，正文和时间码挤一行、标点用全角/破折号/箭号、
四段当帧……全漏。批量改一堆片段只能一个个点。

**时间码解析层（`lf_import.py`）**
- `_TC_FOLD`：全角标点 → 半角，`str.translate` 1:1 替换，长度不变 → 影子串下标与原文严格对齐，
  切时间码时按原文下标切，正文一个字不动。
- `_TC_RE`（宽松候选）：`h:m:s[.ms | :帧]` / `m:s[.ms]` / `h-m-s` / `1时2分3秒` / `2分3秒` /
  `3.5秒` / `1'23"45`；`_tc_seconds()` 再掐头去尾 + 六种格式 + 范围校验（分秒 <60）。
- `_tc_line()` 判定归宿：**区间**（两个码之间只隔箭头/破折号/波浪线/空白）→ start+end；
  **行首** → start；**行尾** → start；`tc_pos="any"` 才认句中。区间整体吃掉（含箭头），
  避免「→」留在正文里。
- `parse_timeline()`：剔 srt 序号行、时间码独行时后文归该段、end 用下一条 start 或字数估。
- ⚠️ 续行必须用 `\n` 粘：用空格会把「中英双语字幕」并成一行，`bilingual_split` 直接失效。
- `src["raw"]` 保留原文（自定义格式要重新解原文，srt 的 `text` 只有正文）。

**自定义格式 + 校验（新增能力）**
- `tc_custom`：贴样例（数字串变通配，整体一个捕获组）或写正则（group1=开始、group2=结束）。
- `POST /lf/import/tc/check {token|text, pattern, pos, fps}` → 认出多少处 + 前几条样例 + 提示。
- 前端选项 schema 支持 `type:"text"`，配一个「校验」按钮，绿/红直接回显。

**时间轴批量选择**
- 状态：`S.multi`(Set) + `S.anchor` + `S.marquee` + `S.bulkOpen`；
  Ctrl/⌘ 点加选、Shift 点同轨连选、空白拖框（含所有轨道下方空白）、Esc 清空、Ctrl+A 全选。
- 底部 `.bulkbar`（≥2 段或右键「打开批量操作条」）：选择条件（全部/本轨/可见范围/未生成/
  需重生成/已静音/已锁定/反选）· 按组（组名来自 `clips[].group`）· 解锁/锁定/静音/音量/
  移轨（顺序排开或保持时间）/复制/删除/重新生成。
- 写盘抽成 `writeClipOverride()` + `bulkCommit()`：一次 `markDirty`，撤销算一步。
- ⚠️ 文档菜单：`.bulkbar` 的按钮 click 会冒泡到 document 的「点别处关菜单」监听，
  不排除就会刚弹出就被关掉。

**「重新生成」位置不变**
- `POST /lf/tl/{sid}/regen {uids, pin_start}`：先把每条语音片段当前位置钉进
  `project.clips[uid].start`，再 `_start_render`。时长变了也不会顶走后面的句子。
- ⚠️ `_build()` 返回的是 `tracks[].clips`（不是平铺的 `clips`），钉位置时别取错。
- 代价：位置锁死 + 时长变化 → 可能和前一段重叠，完成后提示「⇄ 整理重叠」；
  想恢复自动排位，片段属性有「回到台本位置」。

### 5.23 片段关键帧：音量 / 声像自动化（2026-10）

**数据**（`project.json`）
```jsonc
"kf": {
  "<片段id>": { "gain": [[t, v], ...], "pan": [[t, v], ...] }
}
// t = 相对片段起点的秒（整段挪位置时曲线跟着走）；v: gain 0~4、pan -1~1
```
- `_clean_kf()`：只留已知属性、按 t 排序、同一时刻去重、越界收敛、点数上限 240/属性。
- 有曲线的属性**以曲线为准**（静态 gain/pan 让位）——否则「调了滑块没反应」很容易被当成 bug。
- `_build()` 把 `kf` 挂到每个 clip 上，前端直接 `c.kf.gain`。

**画布交互**（`web/timeline.js`）
- 曲线画在片段内部：gain 琥珀色、pan 蓝色；选中的片段画方块点，未选中 60% 透明。
- 命中判定 `kfHit()` 在 `locked` 之前：**锁定的片段也能改关键帧**（那不是位置）。
- Alt+点击片段 = 在该处加点；拖动方块改时间+数值（就地 splice 重排）；双击方块删除。
- 属性面板：音量/声像两个页签、`＋ 播放头加点`、逐点时间/数值输入、清空、
  有曲线时把对应静态滑块**禁用并划线**。

**播放**：`clipVolumeAt()` 走 `kfValue()`，`syncAudio()` 每帧更新 → 边播边听曲线。
- >100% 增益和声像 `element.volume` 做不到，加了个按需 WebAudio 图
  （`MediaElementSource → GainNode → StereoPanner`），只对有自动化的片段建。
- ⚠️ 安全阀：`AudioContext` 不是 `running` 时**不建图**（先退回 element 音量）。
  一旦接了 MediaElementSource，声音只走图，图挂起就会变哑。
  `play()` 里先 `warmAudio()`（用户手势里 resume 才生效）。

**导出**
- 混音：按曲线逐样本算 gain（`np.interp`）与 pan（逐样本 cos/sin）→ 实测 RMS 能对上。
- 工程包（rpp/edl）：目前只带静态音量，曲线不带（RPP 的 take 包络格式没在本机验证过，
  不敢瞎写）；片段清单 CSV 多了一列 `kf`（如 `gain:3 pan:2`）。
- 复制/拆分片段会连关键帧一起处理（拆分在切点补一个点，两段各自连续）。

### 5.24 时间轴改生成属性 + 曲线平滑（2026-10）

**「改属性并重生成」为什么不用做同步**

进时间轴时台本页已经 `switchScript(工程副本)`，所以两边操作的是**同一个 script.json**；
时间轴写 `line.ov / pause / slow`，台本页读的就是它。真正要补的只有「台本页要能察觉」：
`window.focus` / `visibilitychange` 时比一下 `script.updated`，不一样就静默重载（有本地
未保存改动时跳过）。顺带给 `/longform` 加了 `?sid=` 深链接。

**接口**
- `GET  /lf/tl/{sid}/line-props?uids=a,b` → 每句的 `ov` + 生效值（默认合并）+ pause/slow/status
- `POST /lf/tl/{sid}/line-props {uids, ov, pause, pause_clear, slow, regen, pin_start}`
  - 只认 `ref / emo_mode / emo_weight / emo_vec / emo_text / emo_ref` 这几个键（白名单）
  - `ov` 里给 `null` = 清掉这条覆盖；`pause_clear:true` = 停顿回到默认
  - 写盘走 `_normalize_line` + `_merge_runtime`（和台本页保存**同一条路径**）→ 参数进了
    指纹就自动变「需重生成」，只改停顿/慢语速则保持 done
  - `regen:true` 时接 `_start_regen`（先钉位置再渲染）；渲染起不来不报 4xx，
    返回 `regen_error` 字符串——属性已经存了，别让用户白填
- `_pin_starts()` / `_start_regen()` 抽成公共函数（`/regen` 与 `line-props` 共用）

**UI**：片段属性顶部「🎛 改属性并重生成…」、右键同名项、批量条「🎛 属性并重生成」。
弹窗字段：音色 / 情感模式 / 情感权重 / 情感描述 / 行后停顿（含「用默认」）/ 慢语速标记；
底部两个开关「改完立即重生成」「保持现在的位置」。单条只提交**真正改过**的字段，
避免平白多出一条「改过生成属性」徽标；批量则按左侧勾选项逐个应用。

**曲线平滑**
- 算法 `kfSmoothPts()`：内部点三角权重窗口平均（首尾固定）迭代 N 次，再按偏差阈值
  `eps` 把多余点并掉（点少了反而更顺，拖动也不卡手）。
- 四档预设 `KF_SMOOTH`：轻度(1,1,0.004) / 中度(2,3,0.006) / 强力(3,4,0.012) /
  去抖(1,2,0.02)。最后一条同时压缩点数。
- 入口：关键帧区块「〰 平滑」菜单（只平滑当前曲线 / 整段所有曲线各 4 档）、
  批量条「〰 平滑」（对选中片段的全部曲线）。
- 平滑是一次 `markDirty`，撤销能整批退回。

⚠️ 菜单被「点别处关闭」误杀的坑：按钮 click 会冒泡到 `document` 的关闭监听，
除了排除 `.ctxmenu/.bulkbar`，再给 `buildMenu()` 弹出的菜单 120ms 免死窗口
（`ctxAt` 时间戳），否则属性面板里的菜单「刚弹出就没了」。

VST3 插件的可行性另见 `分析_VST3插件支持.md`（结论：离线链路改动小，实时要换播放引擎）。

### 5.25 情感控制统一：一套组件，四个入口（2026-10）

**问题**：情感这块以前是「三处各写一份，各缺一块」——
主界面有情感参考音频 + 8 轴向量；台本页只有「点情绪」（一键单轴，不能叠加）；时间轴
只有一句「情感描述」。想给某句配「委屈巴巴 + 参考音频」得回主界面重做一遍。

**做法**：新增 `web/emoctl.js`（两页共用，自带样式，只用主题变量），导出三个构造函数：

```js
EmoCtl.mount(host, opts) -> {read(), setMode(), refreshRefs(), ...}   // 整套
EmoCtl.audio(host, opts) -> {get(), set(id), refreshRefs(list)}       // 只挑参考音频
EmoCtl.vector(host, opts) -> {get(), set(arr), hasAny()}              // 只调 8 轴
```

`read()` 统一返回 `{emo_mode, emo_weight, emo_vec, emo_text, emo_ref}`，
`emo_mode=null` 表示「跟随默认」，`emo_vec=null` 表示全 0（写盘时删键）。

**接入的四个入口**
| 位置 | 组件 | 说明 |
|---|---|---|
| 台本页 行属性 | `mount` | 模式 / 音频 / 向量 / 文本 / 权重一次给全 |
| 台本页 批量改属性 | `audio` + `vector` | 两行独立勾选，勾了才写 |
| 台本页 分组参数（新建/编辑） | `audio` + `vector` | `applyBatchParams` 补 `emo_ref` |
| 台本页 全局默认参数 | `audio` + `vector` | 抽屉里两块，绑定 `SCRIPT.defaults` |
| 时间轴 改属性并重生成 | `mount` | 单条整块；批量时整块一个勾选 |

**情感参考音频**
- 来源：音色库（`/lf/meta` 的 refs），分组里「已标记情感」排最前（🎭）。
- 外部导入：`POST /lf/refs` 多一个表单字段 `purpose=emo`，入库时给 ref 打
  `uses: ["emo"]`。**音频只存一份**（模型解析路径只有 `resolve_ref` 这一套），
  所以情感参考音频和音色是同一个库，音色库里也会显示「情感」徽标。
- 试听：`GET /lf/refs/{rid}/audio`，与主界面同源。

**向量**：8 轴，每轴 = 滑杆 + 数值 + `−`/`＋`（0.05 步进）；快捷填充 8 个单情绪
（0.85）+ 4 个复合情绪（委屈 / 紧张 / 强撑 / 温柔）+ 清零。复合情绪是给
「一句话里有两三种情绪」准备的——单轴推高在模型里容易被归一化掉。

**校验**：`emo_mode=1` 没选音频 / `emo_mode=2` 全 0 → 弹窗不关、直接提示。
时间轴的 `modal()` 补了「`onOk` 返回 false 就不关窗」。

### 5.26 关键帧曲线形态：经过点的平滑曲线（2026-10）

**上一版理解错了**：把「平滑」做成了「对数值做窗口平均」——那会**改关键帧的值**，
用户要的是「点一个都别动，只是点与点之间别拉直线」。

**现在**：插值从折线换成单调三次 Hermite（PCHIP），端点固定、经过每个节点、
段间一阶连续。选单调版本而不是 Catmull-Rom 是因为它**不过冲**：
音量节点之间不会冲到 0 以下 / 400% 以上（那是爆音），声像也不会甩出 ±1。

- 数据：`project.kf[片段id].shape = {gain: "smooth"|"linear", pan: ...}`，缺省 `smooth`。
- 前端：`pchipOf()` 缓存节点斜率（`WeakMap`，点数组被替换后自动失效）；
  `kfAt(pts, t, dflt, shape)` 按形态求值；画布按像素采样画曲线（折线仍走老路径）。
- 后端：`_pchip_eval(xs, ys, tt)` + `_kf_curve(points, tt, shape)`，混音与试听同一条曲线。
- UI：「〰 平滑曲线 / 〰 折线」按钮（当前曲线）、菜单里可整段两条一起切、
  批量条「〰 曲线形态」对选中片段批量切。撤销算一步。
- ⚠️ 旧的「抹平（改数值 + 压点数）」逻辑整段删掉了：语义不同，留着只会混淆。

### 5.27 HRTF 双耳空间音频（2026-10）

**两条链路，两套实现**（浏览器没法加载原生 HRIR，服务端也没法用浏览器的）：
- 试听：WebAudio `PannerNode` + `panningModel="HRTF"`（浏览器自带 HRIR，真双耳）。
- 混音导出：服务端 `_Binaural`（球头近似，见下）。

**数据**（`project.clips[uid] / sfx[] / tagfx[uid]`）：
`binaural: bool`、`az: -180~180`（右为正）、`el: -90~90`、`dist: 0.2~30` 米。

**离线模型**（`_Binaural.render`，按块处理，跨块保留状态）：
- ITD：Woodworth `t=(a/c)(θ+sinθ)`，a=8.75cm，最大约 0.66ms；分数延迟线性插值。
- ILD + 头部遮挡：远耳 `1-0.35·lat` 增益 + 一阶低通（越侧越闷）。
- 前后：`fb=(1-cos az)/2` 让正后方整体变闷（3.6kHz 左右的低通，粗略替代耳廓线索）。
- 仰角：±6% 增益；距离：反比律 `1/(1+0.6(d-1))`。
- 说了实话：**不是测量 HRIR**，左右/远近/遮挡是真的，前后/仰角是近似。

**前端**：
- `kfGraph()` 拆成 `src → gain → out`，`out` 在 `StereoPanner` 与 `PannerNode` 之间换。
  ⚠️ `createMediaElementSource` 一个元素只能建一次，所以换输出级必须「只换后半段」，
  不能整条重建（重建会抛 InvalidStateError，且原节点已接管声音）。
- 属性面板：双耳开关 + 俯视方位盘（拖动 = 方位 + 距离，圆心是听者、上方是正前）
  + 前/右/后/左快捷键 + 仰角滑杆 + 距离输入。
- 开着双耳时**忽略声像**（含声像关键帧、轨道声像）——空间位置是绝对的，
  再叠一层左右平衡会把它拉回立体声，UI 上已注明。

**已知边界**：耳机听得出左右/远近/前后；外放基本听不出；导出与试听的音色细节
略有差异（浏览器 HRIR vs 球头模型）；方位可做关键帧自动化（见 §5.28），仰角/距离仍是静态。

**后续升级评估**：换实测 HRIR（SONICOM / KEMAR）只改 `_Binaural` 一个类，
1~2 天可见效；3D Tune-In（2026-02 起 LGPL-3.0）是实时引擎，接入属于换引擎级别。
详见 `分析_HRTF升级.md`。

> 已落地（2026-10）：见 §5.29 —— 默认 KEMAR HRIR + 房间混响，球头模型保留为回退。

### 5.28 曲线跟手修复 + 方位（HRTF）关键帧（2026-10）

**拖动关键帧时平滑曲线不更新**

根因：PCHIP 的斜率缓存是 `WeakMap<点数组, 斜率>`。拖动是**就地 splice 同一个数组**
（`c.kf[prop]` 本体不变），缓存键不变 → 一直拿拖之前的斜率；折线直接读点，所以「折线跟着动、
曲线不动」。修法：缓存项带一份内容指纹（FNV 风格累加 `n:hash(t,v)`），
`pchipOf()` 里先比指纹，变了就重算。O(n) 且 n ≤ 240，每帧几百次插值也不值得更复杂。

**方位关键帧（让声音绕着人走）**

- 数据：`kf[id].az = [[t, 度], ...]`，`-180~180`（0 正前 / 90 正右 / 180 正后），
  与 gain/pan 同一套清洗、形态（smooth/linear）、撤销。
- 后端混音：`az` 曲线 → 逐样本角度数组 → `_Binaural.render`。时变时按 **128 样本一块**，
  每块用块首角度算 ITD/ILD/滤波；块之间延迟历史与滤波器状态连续，听感是连续移动。
- 前端播放：`syncAudio` 每帧用 `kfValue(c, "az", local)` 调 `placePanner`。
- UI：双耳开启时关键帧页签多一个「方位」；空间盘的圆点跟着播放头走；
  **有方位曲线时拖盘与前后左右快捷键置灰**（否则「拖了没反应」），给「编辑方位曲线 / 清空」两个出口，
  没曲线时给「＋ 给方位做自动化」。
- ⚠️ 关掉双耳要把 `KF.prop` 从 `az` 退回 `gain`，否则页签里没有任何一个高亮。

### 5.29 P1/P2：实测 HRIR + 房间混响（2026-10）

**P1：定位从「球头近似」换成实测 HRIR**

- 数据：`assets/hrir/MIT_KEMAR_normal_pinna.sofa`（710 方向 / 44.1k / 512 抽头，
  授权「无使用限制，建议引用」）。换成 SONICOM 只要把 .sofa 丢进同目录或用
  `INDEXTTS_HRIR` 指定，加载器支持任意 `SimpleFreeFieldHRIR`。
- 依赖：只加了 `h5py`（放 `_vendor/`，非 pip 环境也能用）；卷积用已有的 scipy。
- `hrir.py` 三件事值得记：
  1. **对齐**：每个方向/耳把起始延迟剥掉单独存 `dly`。不对齐就插值/淡化两个方向的 IR，
     会因为时间错位梳状滤波（金属声）；
  2. **插值**：KEMAR 网格不规则（192 个方位 × 14 个仰角），按球面角距离取最近 3 个做
     反距离加权，不能用规则网格的双线性；
  3. **渲染**：先做「时变分数延迟」把 ITD 加回去，再用对齐后的 IR 卷积；
     时变用块内线性过渡 + IR 前后块各半，方位在动也不会咔哒。
- ⚠️ **SOFA 方位角是逆时针**（+90 = 左），我们项目是 +90 = 右，加载时取反，
  否则左右整体镜像（这个 bug 试听十秒就能发现，但看代码看不出来）。
- 回退：没有数据 / 没有 h5py → `_make_binaural()` 返回老的 `_Binaural`，离线永远能跑。

**P2：房间混响（镜像源 + 统计尾巴）**

- `rooms.py`，不引入 pyroomacoustics：运行时是嵌入式 Python，少一个重依赖少一份装不上的风险；
  而且我们只需要「长方体 + 均匀吸声」，80 行就够且可测。
- 五个预设：小卧室 0.35s / 客厅 0.6s / 走廊 0.95s / 大厅 1.9s / 室外 0.1s。
- 算法：
  1. Sabine 从 RT60 反推 α；
  2. 镜像源枚举 8 阶，听者左右各 9cm 两个「耳朵」分别累加，得到双耳 RIR（有 ITD/ILD 的反射）；
  3. **切掉直达段**（直达交给 HRIR，否则会叠两份）；
  4. 晚期用「指数衰减的去相关噪声」补上，从早期结束处接缝，电平与早期对齐
     —— 纯镜像源做不到 2 秒 RT60（阶数要几十阶、镜像数爆炸），工业做法都是这样拼；
  5. 分段一阶低通（16k → 1.5k）模拟高频先衰减；
  6. 归一化到固定湿声电平（分母有下限，避免「室外」被放大成零星回声）。
- 实测 RT60：0.36/0.35、0.56/0.6、1.69/1.9（都在 ±12%），左右耳相关系数 0.15~0.25（不是单声道复制）。
- 取档：方位 45° × 距离 3 档，IR 在内存里缓存；`/lf/tl/room-ir` 直接给前端同一份。
- ⚠️ **导出时长要加尾巴**：`_mix_span` 把有房间的片段的 RT60×1.2（上限 3s）算进总长，
  否则余响会被切掉。⚠️ **块边界要 flush**：片段结束后它就不再进循环，卷积尾巴得单独吐出来
  （`RoomRenderer.flush()` / `BinauralRenderer.flush()`），这一条不补，尾巴只在片段内部存在。

**数据模型**：`clips[uid].room / send`（`_clean_clip` 白名单），前端属性面板
「房间（混响）」下拉 + 干湿比滑杆；选了房间默认 25%。

**试听也带混响**：前端 `ConvolverNode` 加载 `/lf/tl/room-ir` 同一份 IR，
从 `gain` 分一路到湿声（干声那路不动）。所以「听到的 = 导出的」，不是两套声音。

### 5.30 多套 HRIR 并存 + 近场补偿 + 空间关键帧改数据模型（2026-10）

**一、多方案整合（数据集层）**

- `hrir.py` 从「单个默认集」改成 **profile 注册表**：`profiles()` 扫 `assets/hrir/*.sofa`，
  外加永远可用的 `sphere`（球头解析）。`get_set(name)` 按名字取，`"sphere"` 返回 None
  → 调用方用 `_Binaural`。
- 每段片段可带 `hrtf`（空 = 默认），混音时按 `clip.hrtf` 建渲染器；回退链
  **指定集 → 默认集 → 球头**，任何一步失败都不会没声音（实测名字打错也照常出声）。
- **入库标定**：加载时把「平均方向的宽带增益」归一到 1（等于干声）。
  不做这一步，换数据集整体响度会差 2~3 dB，A/B 时会误判「换的那套更好听」。
- `lookup(az, el, dist)` 增加**距离维**：数据集有多层（近场集）时按 log 距离取上下两层
  各自查一次再插值；只有一层（KEMAR 1.4m）时忽略，交给 `NearField` 近似。
  ⚠️ 距离维读的是 SOFA `SourcePosition` 第三列（半径），以前只读了前两列。

**二、距离律修正（这是个真 bug）**

老公式 `1/(1+0.6·max(0,d−1))` 在 `d ≤ 1` 时**恒等于 1.0** —— 面板上拖到 0.2m/0.5m/1.0m
输出逐样本完全相同，`dist` 一直只是个数字。现在统一成 `1/(0.4+0.6d)`（1m 处归一）：
0.2m +5.7dB、0.5m +3.1dB、3m −7.6dB。浏览器侧同样算这条（`PannerNode.rolloffFactor = 0`
把它的自带衰减关掉，避免叠两次）。

**三、近场近似（`hrir.NearField`）**

远场数据集补不出「贴耳」，这里补两个最强的主观线索：
- **proximity**：低频抬升（一阶低通 180Hz 加回去），0.2m 时 150Hz 以下约 +5dB；
- **远耳遮挡增强**：距离越近、越偏侧，远耳 3kHz 以上越闷（远场数据 ILD 约 10dB，近场实测可到 20dB+）。
  实测 4~10k 的 ILD：1m 时 +21.2dB → 0.2m 时 +25.0dB。
- 球头模型只吃 proximity（它自己已有远耳低通，再补一次会过度发闷）。
- 面板上写明「这是近似补偿，不是实测 HRIR」。

**四、空间关键帧：从「方位曲线」改成「一个点 = 一个位置」**

之前 `kf.az = [[t, 度]]`，等于把「空间」退化成了「左右」；仰角/距离没法随句子变化，
而它们才是「凑近/绕到身后」的主线索。

- 数据：`kf.space = [[t, az, el, dist]]`，四点一组；`shape.space` 决定平滑/折线。
- 求值：`_kf_space_envs()` 按分量各自插值（PCHIP），三条逐样本数组一起喂渲染器；
  `BinauralRenderer.render()` / `_Binaural.render()` 的 az/el/dist 都支持数组。
- 迁移：`_build()` 见到老的 `kf.az` 就用**这段片段当时的静态 el/dist** 补成四点组
  （听感与迁移前一致），并把 `shape.az` 改名为 `shape.space`。
- UI：页签「空间方位」（画布上仍只画方位那条曲线，因为纵轴只有一根）；
  点列表是 **2×2 网格**（时间/方位 一行，仰角/距离 一行）——四个输入横排会挤出面板、单位还会折行。
  拖点只改「时间 + 方位」，仰角/距离保持；双击删点、Alt 加点、播放头加点都保持四点组。
- 空间盘：有关键帧时圆点跟着播放头走（方位 + 距离都动），拖盘/快捷键置灰。
- 「🎧 耳语 / ASMR 预设」：贴耳 0.35m、偏一侧 72°、录音棚（RT60 0.12）、干湿 6%。

**五、波形竖线密度**

以前固定 `n = min(420, w/2)` 根：长音频放大到 3000px 时每 7~8px 一根，看着像稀疏栅栏。
改成按像素宽度排（`w/1.6`，上限 2400）；峰值点比像素少时用插值取样，避免「几十根柱子重复」的方块感。
实测宽 2861px → 1788 根（≈1.6px 一根）。

⚠️ 另一个真 bug：`_Binaural` 没有 `flush()`，只要走球头回退（sphere / 数据集缺失），
混到最后一个块就 500。已补（返回等长零）。

### 5.31 KU100 近场数据集接入（2026-10）

**数据**：TH Köln「Spherical Near-Field HRIR Compilation of the Neumann KU100」
- `CIRC360`：0.25/0.50/0.75/1.00/1.50m，水平 1°（360 点）；
- `L2702`：0.50/0.75/1.00/1.50m，Lebedev 2702 点全向（有仰角）。
- 原始 48kHz / 128 抽头 / 每距离一个 `.sofa`；`License` 属性写 **CC 3.0 BY-SA**。

**为什么需要打包**：SOFA 一个文件一个半径，而查表需要「一套数据里带距离维」。
新增 `hrir.pack(items, out)`：把多个单距离 SOFA 合成一个 `.npz`（已对齐、已标定），
`HRTFSet.load()` 直接读 npz，`profiles()` 也扫 `*.npz`。产出两套：
- `KU100_near.npz`（4 层 0.5~1.5，全向，7.6MB）
- `KU100_near_circ.npz`（5 层 0.25~1.5，水平 1°，1.3MB；**贴耳用这套，真测了 25cm**）

**打包时必须做的归一**：近场数据方向性极强（正前弱 / 侧向强）。只按全向中位数归一，
会得到「正前方越近越轻」——方向反了。所以每层再按**正前**归一到 1：
距离响度交给 `dist_gain`，「近处侧向更强」这个真实方向性保留。
实测（`KU100_near`）：各层正前能量都 = 1.000；侧向 0.5m/1.5m = 2.83/1.68。

**踩到的两个坑**
1. `_onset()` 的抛物线细化：`0.5*(y0-y2)/den` 在平顶起始（den→0）时会飞出几百个采样。
   KU100 有这种 IR，结果 `_align_ir` 把整条 IR 切空 → 那个方向彻底没声，延迟 1407 采样。
   修法：偏移钳到 ±0.5；`di >= len(ir)-2` 时视为无效、不位移。
2. 近场素材很「热」：0.25m 近耳比 1m 高约 10dB，直接硬裁会把气声削成方波。
   在双耳输出加了一次**软限幅**（`0.9*tanh(x/0.9)`，只在峰值 >0.9 时触发，无状态不抽吸）。
   ASMR 预设同时把 fader 设到 0.7。

**实测线索（这才是「贴耳」的判据）**
- 4~10kHz 的 ILD：1.5m +20.8dB → 0.5m +26.6dB → 0.25m +28.2dB（远场数据到不了）；
- 0.5m 层仰角 +45° 与 0° 的高频谱差约 4dB；
- 距离插值：0.6m 的 IR 与 0.5 / 0.75 都「更像」，且不等于任何一层。

**ASMR 预设**：贴耳 0.35m、偏一侧 72°、录音棚（RT60 0.12）、干湿 6%、fader 0.7，
并自动挂上「最小距离层 ≤0.3m」的数据集（即 `KU100_near_circ`）。

### 5.32 空间音频面板重做：开关 → 方案 → 图形摆位（2026-10）

**菜单逻辑**（之前是一屏十几个控件，开着双耳才看得懂）：
1. **开关**：`空间音频 已开启 / 未开启`。关着时整块只有一行提示，HRIR / 混响 / 图形都不渲染。
   打开时如果从没配过，直接落一套「近讲旁白」（不然开了双耳只有一个不知道听什么的空壳）。
2. **方案**：一个下拉（用户要的「子菜单」），九个预设，选中即整套换：
   `贴耳 ASMR / 床边耳语 / 近讲旁白 / 室内对话 / 影院环绕 / 大厅回声 / 户外开阔 / 走廊经过 / 自定义`。

- 现象：导出混音每隔约 1 秒一声轻响；导出工程（分轨）和单句导出都没有。
- 定位：把同一段 ASMR 素材按 4 种配置混音，只有开双耳（HRTF）时出现；
  二阶差分在 **每个整秒边界** 比段内高 10~75 倍 —— 正好是混音块长 `BLOCK_SEC = 1.0`。

     改成逐样本乘（`out * 1/(0.4+0.6d)`）。
  2. `rooms.RoomRenderer` 在 IR 长度变化时把卷积尾巴清零 → 换房间一声「咔」；
     改成保留尾巴、截断/补零到新长度。

  即使用户没设淡入淡出。

**③ 裁剪：左右两侧都能拉回完整片段**
- **根因（真 bug）**：`_build()` 里有个局部变量 `sf = line.get("sfx")`，把
  `import soundfile as sf` 遮蔽了 —— `sf.info(path)` 永远 `AttributeError`，
  被 `except` 吞掉，文件时长恒为 0。于是素材的 `src_dur` 只能按 `dur + offset` 反推，
  右边裁一刀 `src_dur` 就缩了，**刷新后右边缘再也拉不回去**。
  修法：加模块级别名 `_sf_info = sf.info`，读时长全用它；`src_dur = max(dur+offset, 文件真实时长)`。
- 语音片段同理：`src_dur = max(base_dur, trim_start + dur)`。
- 左侧还修了一个边界：以前贴着头（start≈0）往左拖会把 `start` 写成负数，
  服务端落盘又夹回 0，一刷新左边就短一截；现在 `delta ≥ -min(offset, start)`。
- 片段右键新增「↔ 恢复完整片段（取消裁剪）」：`offset=0`、`dur=src_dur`、
  左边被裁过的整体左移回原位 —— 比在边缘上一点点拖稳。

**④ 倍速预览**

**⑤ 空间面板跟着播放头实时更新**

修法：抽出 `refreshSpatial()`，`draw()` 与 `tick()` 都调；`posNow()` 播放中一律返回

### 5.37 录制通用化 / 固定间隔波形 / 三库素材 / 三平面摆位（2026-10-25 晚二）

  位置/数值没变就不重复记点；停止时 `kfSet` / `kfSpaceWrite` 一次性落盘；
  取消回滚 `base`。频率单位从 Hz 改成**秒**（`REC_INT`，0.02~2s，存 `tl.recint`）。

**② 波形：固定时间间隔一条竖线**
原来是「按像素宽度算条数」（`n = w/1.6`），所以同一段音频放大后线条变少、缩小后糊成一片。
现在改成时间取样：**每 10ms 一条**（>30s 用 20ms，>90s 用 50ms，>300s 用 100ms），
横坐标 `x = x0 + (t/dur)*w`，每条的幅度 = 该时间窗内峰值最大值。
同一段音频无论怎么缩放，波形**形状一致**，放大只是线距变宽。
`__tl.waveInfo(id)` 现在返回 `{n, w, step, pps}`（测试用来确认 step 不随缩放变）。

### 5.38 补丁包的 .bat 必须纯 ASCII（v1.4 踩坑，重要）

**症状**：别人拿到 v1.3 的补丁包，双击 `安装.bat` 满屏报错，装不上：

```
't' 不是内部或外部命令，也不是可运行的程序
系统找不到指定的路径。
'版湰' 不是内部或外部命令……          ← "版本" 被按 GBK 解成乱码
'欢浼氬厛澶囦唤鍒?_patch_backup\' 不是内部或外部命令……
```

**原因**：`cmd.exe` 打开 .bat 时是**按系统 OEM 代码页（中文 Windows = 936/GBK）逐字节解析**的，
和文件里写不写 `chcp 65001` 没关系（那一行本身也已经是被解析过的字节了）。
原来 `安装.bat` 存的是 **UTF-8**，里面又有中文 `title`/`echo`/中文文件名，
于是 UTF-8 的三字节汉字被拆成 GBK 的双字节 + 残余字节，把 `set` 这类命令都吃掉了，
才会出现 `'t'`（set 的尾巴）这种报错。文件里一旦有非 ASCII 字节，这坑必踩。

**修法（v1.4）**：
1. `安装.bat` 里**一个中文都不留**，全部 ASCII，换行用 CRLF、不带 BOM（2292 字节，0 个 >127 的字节）；
2. 安装器改名 **`install.py`**（ASCII），bat 里只出现 ASCII 路径：
   `"%PYEXE%" %PYARGS% "%~dp0install.py" %*`；
3. 所有中文提示交给 Python 打印（控制台句柄走 `WriteConsoleW`，cp936/cp437 都不乱码）；
   `install.py` 里加了 `sys.stdout.reconfigure(errors="replace")`，英文版 Windows 打不出汉字也不会崩；
4. Python 探测用子程序 `:probe`（`where py` / `python` / `python3`），
   优先本级 `runtime\python.exe`、再上一级 `..\runtime\python.exe`——避免在 `if (...)` 块里判 `errorlevel`；
5. 缺 `install.py` / 缺 `payload\` 也各自给一句 ASCII 提示，不至于闷着失败。

**校验（已进 `_t_patch.py`）**：
`安装.bat 纯 ASCII`、`安装.bat 是 CRLF`、`安装.bat 指向 install.py` 三条断言；
另外真机跑过：把包装进假整合包（`runtime` 用目录联接），`cmd` 下
`安装.bat --dry-run` 能识别 `..\runtime\python.exe`；把 runtime 挪走又能回退到系统 `python`，
两条路径都通、退出码能透传。

> 以后凡是往包里塞 `.bat`/`.cmd`，都按这条走：**ASCII 内容 + CRLF + 中文交给 Python 输出**。

### 5.40 第三轮：复制粘贴纠偏 / 重排延迟 / 变速与时长 / 粘性标尺 / 波形重做（2026-10-25 晚四）

**① 复制粘贴「粘的是上一段」**
根因两层：
- 普通点选时只设 `S.sel`、往 `S.multi` 里塞了旧片段（多选残留），Ctrl+C 走 `copySelection()` 时读的是集合 →
  复制到旧的；现在点选会把集合收成「只有这一段」（`!inMulti(c.id) || size>1` 时 clear+add），
  并且 Ctrl+C 显式传 `[c.id]`。
- 服务端 payload 里素材片段没有 `name` 字段（显示名在 `text`），`pasteClip` 只读 `clip.name` →
  粘出来的标签全是媒体文件名（`xxx.wav`），看着就像「粘了别的素材」。现在 `name: clip.name || clip.text || clip.media`。

**② 台本右侧面板：进度条提到顶部 + 模型/依赖状态**
- 把整个 `#progWrap` 从「生成」页签里搬出来，放在 `.ptabs` **上面**，和三个页签平级 → 切「批量/导出」也一直看得见进度。
- 新增 `.topstat` 状态条：模型（复用 `paintModelState` 的档位）/ ffmpeg / 人声分离（Demucs，带 device 与「离线权重」），
  来源是 `/lf/media/capabilities` + `/lf/meta`；右侧 `⟳` 手动重检。
- 空闲时给 `#progWrap` 加 `.idle`：收起进度条/阶段/样式选择，只留「模型 + 一句提示」，不白占高度。

**③ 重排音声片段延迟（新按钮）**
- 顶栏 `↕ 重排音声延迟`：按 `index`（台本句序）把每条音声轨上的片段**依次排开**：
  `start_i = start_{i-1} + dur_{i-1} + pause_{i-1}`，`pause` 取 `pause_ms`（服务端 `_eff()` 算好的有效停顿，行上没设就跟默认）。
- 只写 `start`，时长/裁剪/音量/空间/关键帧/淡入淡出都不碰；素材轨完全不参与；先弹窗说明再执行，进撤销栈。
- **坑**：音声片段默认 `locked: true`，而 `_save_project` 对锁定片段会拒绝 `start/trim` 改动 →
  重排先临时解锁写入、落盘后再锁回去（第二次 PATCH 的 prev 已是新位置，不会回滚）。弹窗里会写明这件事。

**④ 语音片段可以复制成独立素材**
- `copySelection` 不再拦语音；粘贴时对 `kind === "voice"` 的条目调 `POST /lf/tl/{sid}/media/from-voice {uid}`：
  服务端把 `scripts/<sid>/audio/<uid>.wav` 拷成 `media/<句子前16字>_<随机>.wav`，返回名字与时长；
  前端用 `addSfx()` 落成**普通素材片段**（带原来的音量/声像/空间/淡入淡出），台本里不会多一句，删掉也不影响原句。
- 因此 `pasteClipboard()` 变成 async，三个调用点（Ctrl+V、空白右键、片段右键）都改成 await；
  片段右键的「复制/剪切」不再是灰的（只有标签音效 from_tag 不能复制）。

**⑤ 速度 UI：滑杆居中 + 「变速时长」**
- 右键去掉 ×0.9 / ×1.1，只留「⚡ 调整速度…」与「恢复原速」。
- 属性面板速度块：滑杆 0.5–2（1× 正好在中间，往左慢往右快）+ 数字框 + 「变速时长」（填目标秒数 → 自动 `speed = 源可用长度 / 目标`）+ 「1×」复位。
- 滑杆宽度上限 78px、数字框固定 62px（`.rowline input[type=range]{max-width:78px}`），不再把输入框挤出面板。

**⑥ 变速后还能拉回原长**
`trim_right` 的上限原来是 `src_dur - offset`（源长度），没除以速度 → 2× 的片段能拉回两倍长。
现在 `maxDur = (src_dur - offset) / speed`；`trim_left` 也按 `delta / speed` 换算时长，避免左右不一致。

**⑦ 标尺/播放头常驻顶部**
- HTML 里在 `#cv` 前加 `<canvas id="cvRuler">`，CSS `position: sticky; top: 0; margin-bottom: -26px; z-index: 5`
  ——负 margin 让它不占布局高度，直接盖住主画布自己的标尺带；`.head-spacer` 也 sticky，保证轨道头与内容对齐。
- `drawRulerOverlay()` 用与主画布同一套 `xOf/stepOf` 画刻度，并画**播放头三角 + 竖线**；在标尺上拖动/点击 = 定位播放头（`mousedown` + document mousemove）。

**⑧ 总时长**
- `maxScroll()` 多留 5s + 半个视口，否则拖到当前总时长就到头、拖不出新长度。
- `extendDurationToClips()`：任何片段末端超出 `S.data.duration` 就撑大，写进 `project.duration`（`_build` 里 `max(计算值, project.duration)`）。
- 顶部时间窗的总时长可点改（prompt），改小于片段末端会自动撑回。
- 混音弹窗新增「总时长算到哪儿」：`visible`（显示末端）/ `full`（未显示部分末端，`start + (src_dur-offset)/speed`），
  透传到 `_mix_span/_mix_estimate/_render_mix`。

**⑨ 单选/多选描边**
`isSel = S.sel === id || multi` 而 `multi` 恒真（点选也进集合）→ 红框 + 紫圈同时出现。
现在 `multiSel = S.multi.size > 1`，只有真多选才画紫圈/勾标/不画裁剪手柄；单选只有红框。

**⑩ 波形重做成「填充包络」**
不再一根根画竖线，而是按 `px = clamp(round(可视宽/780),2,4)` 采样、每列取窗内峰值，
拼成「上包络 → 下包络反向」的闭合路径 `fill()`，再补一条 0 轴中线。
好处：缩放/长短片段视觉一致，不会出现栅栏感或看不见；配色另给 `waveFill / waveFillSfx`（原来 rgba 只有 .32，填充几乎看不见）。

**⑪ 音效试听可暂停**
`mkSfxRow` 的试听按钮接 `play/pause/ended` 事件切「▶ 试听 / ⏸ 暂停」；同一个音效再点=暂停，换音效会重新设 src。

**回归**：新增 `_t_tl_round3.py`（单选/多选、单选复制粘贴、语音→素材、重排、速度 UI/裁剪上限、标尺粘性、总时长与混音口径、波形信息、试听暂停）；
`_t_tl_ui2` 的「标记可滚到」改用 rect 计算（原来用 `offsetTop`，把顶栏高度也算进去，属性面板变高后会误判）。


### 5.41 第四轮：波形随变速 / 音声副本轨 / 跨轨重排 / 整组拖动 / 内置 ffmpeg / 图文教程（2026-10-25 晚五）

**① 波形跟着变速（原来「变了速波形不变」）**
- 根因：取样时把「时间轴上的秒」直接当「源里的秒」用（`a = (off + t) / srcDur`）。
  变速改的是 `dur`，源窗口没变，于是片段宽度变了、波形形状没变。
- 现在 `rate = c.speed`，取样按 `a = (off + t × rate) / srcDur`：
  2× 的片段在屏幕上短一半，但覆盖的源范围不变（形状被压缩），1× 还原。
- `__tl.waveInfo()` 多返回 `speed / srcSpan / off / srcDur`，测试断言 `srcSpan ≈ dur × speed`。
- **配色调淡**：填充色从 `rgba(31,53,96,.55)`/`.5` 降到 `.22`/`.2`（深色主题 `.3`/`.27`），
  中线 alpha 从 .65 降到 .5 —— 波形只做底衬，关键帧曲线（音量/声像/空间）才是主角。

**② 音声片段：只能复制、不能剪切；新增「音声副本音轨」**
- 右键的「剪切」对 `kind === "voice"` 置灰（剪切会把台本那一句的音频搬走，容易误会）；
  「复制」可用（Ctrl+C 复制后 Ctrl+V 仍然按「变成独立素材」处理）。
- 新增菜单项「⧉ 复制到素材轨『音声副本音轨』」→ `copyVoiceToCopyTrack(c)`：
  1. `POST /lf/tl/{sid}/media/from-voice {uid}`：把 `audio/<uid>.wav` 拷成 `media/<前16字>_<rand>.wav`；
  2. 找名为 `音声副本音轨` 的 sfx 轨，没有就新建；插入位置 = **最后一条音声轨之后**
     （`orderedTracks()` 是 voice 组 + sfx 组，所以它自动排在素材组最上面）；
  3. `addSfx()` 落片段，并把 `gain/pan/az/el/dist/binaural/room/send/hrtf/fade_*` 一起抄过去；
  4. `project.tracks` 同步插入，`persist()` 落盘。
- 台本行数不变、原句不动；副本改名/裁剪/删除都与台本无关。

**③ 重排音声延迟：跨音轨按句序**
- 老实现按 `track` 分组、每组各自 `min(start)` 起排，句子一旦分布在多条音声轨，
  排完变成「A(轨1) / C(轨2) / B(轨1)」。
- 现在：所有 `kind === "voice" && index != null` 的片段**全局按 index 排序**成一条队，
  从「最早出现的那个起点」开始，`t += dur + pause_ms/1000` 依次排。
  片段仍留在原轨（不为了排序而换轨），素材片段完全不参与。
- 弹窗文案同步：会写出「跨 N 条音声轨」；若首句/末句不在同一条轨，会提示这是同一条时间线。

**④ 多选整组拖动**
- 之前点选规则是「点谁就收成谁一个」，于是按住多选里的某一段时，集合已经被拆成 1 段，
  `comps` 为空 → 只拖了一段。
- 现在点选分两种：点在**集合外**→收成它一个；点在**集合里**→先保留整组（`wasMultiSel`），
  松手时若 `!dragMoved`（位移 ≤ 2px）再收成单选。
- 拖动时同伴按「主体实际位移（含吸附/夹紧）」平移，并夹一次「没人被推到负时间」；
  跨轨时同伴按**同类型轨列表里的序号差**整体平移（不够就贴边，不会把素材塞进音声轨）。
- 松手时同伴也 `writeClipOverride()` 一次，一次 Ctrl+Z 可整体回退。

**⑤ 内置 ffmpeg**
- `bin/ffmpeg.exe`（7.1 essentials，87MB）进 `payload/bin/`，安装器按普通文件铺到包根 `bin/`；
  `_ffmpeg_candidates()` 第一优先级就是 `<root>/bin/ffmpeg.exe`，所以装完即用、不需要联网，
  也不再依赖用户机器上有没有 ffmpeg。
- 体积：压缩包 ~135MB（ffmpeg 87MB + Demucs 权重 80MB，压缩后合计）。

**⑥ 「第一次用？看看这里」图文教程**
- 台本页顶栏按钮 `#btnGuide`（暖色描边）→ `window.open("/guide")`，独立页面不影响正在编辑的台本。
- `longform_api` 新增两条路由：`GET /guide`（`web/guide.html`）、`GET /guide-img/{name}`
  （`web/guide/*.png`，正则白名单 `[A-Za-z0-9_.-]+\.png`）。
- 教程内容：6 步（导入台本 → 提取音色 → 生成音声 → 加音效 → 时间轴编辑 → 导出混音）、
  每步「位置 / 怎么做 / 截图 / 提示」+ 快捷键表 + 5 条常见问题（ffmpeg、去伴奏、模型加载、
  总时长、单句复用、从头再来）。
- 截图由 `_shot_guide.py` 用 CDP 实拍（`web/guide/g1..g6`），
  `make_patch.py` 用 `copy_tree("web/guide")` 一起打包 —— **离线可看**，不依赖外网图床。
- 页面用 `prefers-color-scheme` 自适应深浅色；竖长面板图用 `.narrow` 限制在 440px，避免糊成大图。

**回归**：新增 `_t_tl_round4.py`（波形 srcSpan / 副本轨位置与台本不变 / 跨轨重排 / 整组拖动 / 教程页与 6 张配图）；

### 5.42 第五轮：轨道分组排序 / 导出体检 / 台本列表多选 / 全功能地图（2026-10-26 凌晨）

**① 「音声副本音轨」跑到最下面 —— 根因是「数组顺序 ≠ 界面顺序」**
- 界面用 `orderedTracks() = voiceTracks + sfxTracks` 分组画，但底层 `project.tracks` 数组可能是**交错**的

### 5.44 并发与重度使用：五个竞态 / 静默丢数据的修复（2026-10-27）

这轮不是加功能，是把「手快时才出现」的问题逐条钉死。共同点：**异步请求没有身份校验，也没有排队**。

**① 快速连点台本 → 最后打开的却是先点的那份**
`switchScript(sid)` 里 `await api()` 期间，用户又点了另一份；先发出去的请求后返回，
把 `SCRIPT` 覆盖成旧台本。修法：模块级 `SWITCH_SEQ` 自增序号，`await` 前后各校验一次，
过期响应直接 return（同时 `clearTimeout(saveTimer)`，别让旧台本的防抖保存晚一步打过来）。

**② 渲染轮询串台**
`pollRender()` 用 `SCRIPT.id` 发请求，`await` 回来后继续 `SCRIPT.lines.forEach(...)` ——
此时 `SCRIPT` 可能已是新台本，于是把旧台本的 `render` 状态写进新台本（显示"正在生成 xx%"，
甚至因 `state=done` 提前 `stopPolling`）。修法：进入时记 `sid`，回来后 `if (SCRIPT.id !== sid) return`。

**③ 点「开始生成」后切台本 → 请求打到新台本**
`startRender` 先 `await saveNow()` 再取 `SCRIPT.id` 发请求。修法：进入时记 `sid`，保存后校验，
请求固定用 `sid`，响应回来再校验一次才更新 `RENDER`。
（后端 `_start_render` 有全局 `_ACTIVE` 锁，第二个任务返回 409，所以"连点两次"本身不会起两个渲染。）

**④ 时间轴连拖两下 → 界面退回上一版**
`persist()` 是 `save()`（PATCH）+ `reload()`（GET），两次快速操作会并发：
PATCH 乱序 = 旧数据盖新数据；reload 乱序 = 界面拿到中间态。
修法：模块级 `PERSIST_CHAIN` 串行化，且 **保存后若 `S.dirty` 又被置位就跳过 reload**
（否则 reload 会用服务端旧快照把刚改的内容冲掉，改动就丢了）。
`markDirty` 里 700ms 的定时保存也挂到同一条链上（原来它和 persist 是两条独立路径）。

**⑤ 改完立刻关页面 / 刷新 → 静默丢改动**
时间轴原来只有 `beforeunload → resetPool`（重置音频池），**没有任何保存**；
700ms 防抖没跑完就关，这次改动就没了，也没有提示。
修法：`beforeunload` 里若 `S.dirty`，先用 `fetch(..., {keepalive: true})` 抢发一次 PATCH
（页面卸载后请求仍会继续），再 `preventDefault()` 弹确认。
实测 350ms 内服务端就能读到新值（早于 700ms 防抖），说明抢存生效。

**顺手确认没问题的**：后端 `_write_json` 是 tmp + `os.replace` 原子写、
台本 PATCH 与工程保存都有 `_LOCK`、撤销栈有上限（台本/时间轴各 80 步）。

**回归**：新增 `_t_round7.py`（连点 3 份台本、连拖 2 次、拖完立刻 beforeunload、40 次快速选择/变速）；
`_t_round6/5`、`_t_tl_new2/ui2/keys/round4`、`_t_lf_ui/misc/sfx/tags` 全绿。


### 5.45 多选行为的统一（2026-10-27）

用户报了两件事：`L` 只锁一段、多选拖拽换轨后仍分散。查下去发现是同一个模式：
**多选只在部分入口被考虑到了，其余入口仍然按「当前那一段」处理。**

**① L 键 / 右键锁定**
原来 `c.locked = !c.locked` 只作用于右键点中的那一段。新增 `lockSelection(c)`：
`clipsForBatch(c)` 取整组（多选且包含 c 时返回 `selClips()`，否则 `[c]`），
**全锁才解锁、否则全部锁定**（混合状态优先锁），一次 `commitClip` 循环写回。

**② 多选拖拽换轨后仍分散 —— 根因是 `locked`**
旧代码收集拖动同伴时排除了 `locked`：
```js
if (z && z.id !== c.id && !z.locked) comps.push(...)
```
而**音声片段默认 `locked=True`**（位置锁死、跟随台本时间轴），所以多选拖音声片段时
`comps` 永远是空的 —— 只有被按住那一段会动，其余原地不动。
现在：不再排除锁定同伴，但拖动前把它们**临时解锁**（服务端 `_save_project` 不接受修改
锁定片段的 `start`，不解锁会被拒绝），移动后保持解锁并 toast 提示"想锁回去按 L"。

**③ 换轨时整组落到同一条轨**
旧逻辑是"按同类型轨列表的序号差平移"：组内本来就分散在 V1/V2 上的话，平移后仍在两条不同的轨上，
哪怕旁边全是空轨也合不到一起。改成：**同类型同伴全部 `moveClipToTrack` 到主体落下的那条目标轨**，
整组视为一个片段；类型不同的（音声 vs 素材）不硬塞，留在原轨。

**④ 其余入口一并对齐**
- 右键「删除这段」→ 多选时显示「删除选中的 N 段」，复用批量删除（带确认）；
- 右键「淡入/淡出」→ 打开时记 `fadeList`，应用时整批 `setFade` + `commitClip`；
- 右键「调整速度」→ 同样记 `spdList`，应用时整批 `applySpeed`；
- 右键「静音」「复制到副音轨」「复制属性」上一轮已对齐。

**测试**：`_t_round8.py` —— 混合状态按 L 全锁 / 再按全解、菜单文案反映整组、
三段分散在两条轨上拖动后全部落到第三条轨、语音片段删除项禁用（说明认到了整组）。
回归 `_t_round5/6/7`、`_t_tl_new2/ui2/keys/round4`、`_t_lf_ui/tags/misc/sfx` 全绿。

### 5.46 多选手感的三个「入口没接上」（2026-10-27 晚）

用户实际用了一遍，报了三件具体的事：框选之后按 `L` 没反应；多选后在一段上右键，
选中状态又变回一段；悬浮窗的锁定/静音各有两颗按钮，太占地方。三件事指向同一个老毛病：
**状态只在一个入口里维护，别的入口按自己的假设读它。**

**① 框选没有「锚点」，L 键直接短路**
`keydown` 里写的是 `const c = S.sel ? clipById(S.sel) : null;` + `if (key === "l" && c)`。
点选 / Ctrl 点选都会设 `S.sel`，**框选只往 `S.multi` 里塞 id，从不设 `S.sel`** ——
于是框完按 `L`，`c` 是 `null`，整行判断直接跳过，连 toast 都没有。
修法两条一起上：
- `lockSelection(c)` 不再强制要求入参：多选 ≥2 段时一律按 `selClips()` 整组处理，
  单段才回落到 `S.sel`，两者都空就提示「先选一段（或多段）再锁定」；
- 框选 `mouseup` 时给个锚点：`S.sel = 最后加入集合的那段`（`S.anchor` 同步），
  顺带让右侧属性面板有内容可显示，`V` 静音、属性复制也有主语。

**② 右键把多选打散 —— 是 `mousedown` 干的，不是 `contextmenu`**
右键也会触发 `cv` 的 `mousedown`（没判 `e.button`），于是走了「点在多选集合里 → 先保留整组，
松手没拖动就收成单选」的那条路（`wasMultiSel` 分支）。`contextmenu` 里只写了 `S.sel = c.id`，
`mouseup` 一到 `endDrag` 就把集合清成一段。
修法：`mousedown` 里 `if (e.button !== 0) return;`（右键不再进入点选/拖拽状态机）；
`contextmenu` 里改成「点的那段**在集合里** → 保留整组；**在集合外** → 才收成单选的这一段」，
并 `updateBulkBar()` 让悬浮窗的计数与按钮状态跟着走。

**③ 悬浮窗按钮合并成两态**
`bkUnlock / bkLock / bkMute / bkUnmute` 四颗 → `bkLock / bkMute` 两颗：
- 全部已锁 → 显示「🔓 解锁」，否则「🔒 锁定」（混合状态按「全锁」算，和 `L` 一致）；
- 全部已静音 → 「🔊 取消静音」，否则「🔇 静音」；
- 状态在 `updateBulkBar()` 里按 `cs.every(...)` 刷新，当前态加 `.on` 高亮（红框红字）；
- 点击直接复用 `lockSelection()` / `muteSel()`，**按钮与快捷键走同一条代码路径**，不会再各说各话。

**④ 顺带修掉的两个「幽灵选中」**
- `clearMulti()` 以前只清 `S.multi`、留着 `S.sel`：取消选择后按 `L`/`V` 仍会偷偷改
  「上一次点过的那段」。现在连 `S.sel`/`S.anchor` 一起清，并只在确实有东西被清掉时重绘；
- 框选单击空白（`!d.moved`）也把 `S.sel` 置空，避免同一类幽灵锚点。

**测试**：新增 `_t_round9.py` —— 真实拖框（mousedown→mousemove→mouseup）后断言 `S.sel` 非空、
按 `L` 全锁 / 再按全解；完整模拟右键三连（`mousedown(button=2)` → `contextmenu` → `mouseup`）
后多选仍是 3 段、菜单文案仍是「选中的 3 段」、没有残留 `S.drag`；
`bkUnlock/bkUnmute` 已不存在、`bkLock/bkMute` 文案随状态翻转且点击生效、`.on` 高亮正确；
点集合外的片段右键才收成单选；`clearMulti()` 后按 `L` 不改任何片段。
回归 `_t_tl_bulk`（同步改成两态断言）、`_t_round8`、`_t_tl_keys/new2/round3/round4/ui2/fix/libs`、
`_t_round5/6/7`、`_t_kf_ui/kf_drag`、`_t_space_ui2/space_kf_ui`、`_t_lf_ui/sfx_ui`、`_t_room_ui` 全绿。

### 5.47 「只生成选中行」把整篇都跑了（2026-10-28 凌晨）

用户手动只勾 2 句，生成页选「选中行」，结果 5 句全跑。查下来是一条**协议断链**：

```js
// longform.js（旧）
if (mode === "uids")      body = { mode: "uids", uids };
else if (mode === "batches") body = { mode: "batches", batches };
else                      body = { mode };          // ← "sel" 走到这里，uids 被丢掉
```

```python
# longform_api.py（旧）
mode = req.get("mode") or ("uids" if req.get("uids") else "all")
if mode == "batches": ...
elif mode == "uids": ...
elif mode == "missing": ...
else: uids = 所有非空行                              # ← "sel" 落到这里 = 全篇
```

两个「else」撞在一起：前端以为 `sel` 是合法枚举、把 uid 列表丢了；后端也不认识 `sel`，
把未知值当成 `all`。于是「选中行」在协议层就等于「全部行」，UI 上却看不出任何异常。

**修法（两端都收口）**
- 前端：`btnRender` 的 `sel` 直接走 `startRender("uids", [...SEL])`；
  `startRender` 内部对 `sel`/`uids` 统一发 `{mode:"uids", uids:[...]}`，列表为空就弹提示、不发请求；
- 后端：`mode in ("uids", "sel")` 都按 uid 列表处理；**`sel` 没带 `uids` 键 → 400**；
  **未知 mode → 400**（不再 fallback 到 all）；`batches` 空选 → 400；
- 原则：**范围类参数「不确定就报错」**，绝不猜「全篇」——猜错的代价是一次整篇重跑。

**测试**：`_t_round10.py`，用「没设默认音色 → 开跑前必然 400」当探针，错误信息里的
「有 N 行没有可用音色（第 x、y 行）」正好反映服务端最终认到的范围，因此不用加载模型：
- 后端 8 项：`sel`+2 uids → 2 行（第 1、3 行）、`sel` 缺 uids → 400、未知 mode → 400、
  `all` → 5 行、`batches` → 组内 5 行、`batches` 空 → 400、`uids` 单行 → 1 行；
- 前端 5 项：建 5 句分组后初始 0 行选中、勾第 2/4 行 → 提示「有 2 行（第 2、4 行）」、
  勾满 → 5 行、切「全部行」→ 5 行、切回批量页签选择不被分组改写；
- 正向 1 项：配好音色后勾 2 行点「开始生成」，提示必须是「开始生成 2 句」。

### 5.48 WinError 5 与「分组编辑」四件事（2026-10-28 凌晨二）

**① `[WinError 5] 拒绝访问: 'script.json.tmp' -> 'script.json'`（渲染线程被打断）**
旧的落盘是三行：

```python
tmp = f"{path}.tmp"
with open(tmp, "w") as f: json.dump(data, f, ...)
os.replace(tmp, path)
```

Windows 上 `os.replace` 走 `MoveFileEx`，**要求目标文件的所有句柄都带 `FILE_SHARE_DELETE`**，
而 Python 的 `open()` 不带。渲染时前端每 1.2 秒轮询 `GET /render`，那边 `_load_script()`
正好在读同一个 `script.json` —— 撞上就 `PermissionError`，异常一路冒到 `_render_loop`，
整次渲染中止（用户看到的就是「出错中止：渲染线程异常」）。杀毒 / 索引服务刚写入就扫描也会造成同样结果。

修法（`_write_json` / `_read_json`）：
- **唯一临时名** `script.json.<pid>.<tid>.tmp`：两个线程同时保存不会互相抢同一个 tmp；
- **全局写锁** `_JSON_IO_LOCK` 串行化落盘，杜绝「A 刚 replace、B 的 tmp 已被搬走」；
- **退避重试**：`os.replace` 遇 `PermissionError` 重试 10 次（20ms→120ms，约 1 秒），
  足够等轮询的读句柄松开或杀毒扫完；
- 读也重试 4 次，避免读到替换中的半成品；失败时清掉 tmp，不留残渣。

**② 编辑分组能加减句子**
`openBatchDialog(existing)` 顶部插入全台本句子清单（`.bpick-row`：checkbox + 序号 + 文本 +
状态徽标），`picked` 集合就是最终 uids；工具条「＋ 加入选中的 N 句 / 全选 / 清空」；
保存时 `rows.filter(picked).map(uid)` 按正文顺序写回，并提示「加入 X 句、移出 Y 句」。
清单放在**任务名下方**而不是底部 —— 情感向量那 8 个滑杆太长，放底部每次都要滚到底。

**③ 拆分 / 插入 / 复制继承分组**
新增 `inheritBatches(oldUid, newUid)`：把新 uid 插到原 uid **后面**（保持组内顺序同正文）。
`splitLine` / `insertLineAfter` / `duplicateLine` 都调用；`mergePrev` / `mergeNext` 用
`mergeBatchUids(keep, drop)` 把被吃掉那行的组关系并到保留行。

**④ 分组的勾选与「一键生成」**
- 跨页签共用 `BATCH_PICK`：批量页每张卡片左上角 checkbox、生成页「按批量任务」列表都读写它；
- 批量页底部 `.batchrun`：「已勾 N 个分组 · 共 M 句（重叠只跑一次）」+ 全选 / 清空 +
  「▶ 生成勾选的 N 个分组」→ `startRender("batches", null, selectedBatchIds())`；
- `selectedBatchIds()` 不再从 DOM 读勾选，改读 `BATCH_PICK`（并把已删除的组 id 清掉）。

**⑤ 生成页的「选中提示」**
`#rSelHint` 放在「渲染范围」标题上方，`updateSelHint()` 在 `updateSelInfo()` / 切页签时刷新：
「**已选 N 句** · 未选 M 句 · 共 T 句」，N=0 时附一句「选中行模式要先在左侧勾几行」。

**⑥ 后端 batches 校验的坑**
`PATCH /scripts/{sid}` 里 `batches` 在 `lines` **之前**处理，校验合法 uid 时只有旧 lines ——
拆分产生的新 uid 因此被当成脏数据过滤掉（前端明明加进组了，落盘后又没了）。
现在把「本次请求带来的 incoming lines 的 uid」也并入 `valid`。

**测试**：`_t_round11.py`（13 项）—— 24 并发写 + 36 并发读无 5xx、目录无 `.tmp`；
**测试进程持着 `script.json` 读句柄 0.4 秒期间保存仍成功**（重试生效，旧实现必 500）；

### 5.50 长剧本丢句 / 啪声 / ASMR 近场破音（2026-10-28 凌晨四）

用户报三件事：素材台该默认 Demucs；长剧本导出混音「丢句 + 很小的啪啪声」；
低语 + 近场空间音频「破音 / 像劣质麦克风录的」。后两个都是**采样率与增益口径**问题。

**① 变速片段：预渲染缓存写死了 44100**
`_prepared_source()` 把源按速度重采样后要写一份缓存，代码是：

```python
want = int(clip_dur * SR)      # SR = 44100（混音内部采样率）
seg = np.pad(seg, (0, want - len(seg)))     # 源是 22050 时长度只有一半 → 补零
sf.write(wav_path, seg, SR)                 # 22050 的样本被标成 44100
```

两个错误叠在一起：时长按 44100 算（源 22050 → 后半被补零，听感「丢句」），
采样率字段写错（播放快一倍、音调高、块边界一声「啪」）。修法只有两行：
`want = int(round(clip_dur * sr))`、`sf.write(..., int(sr), ...)`。
诊断 `_diag_speed.py`：speed=2 时输出 880 Hz、整段 RMS 一致、零跳变（修前是后半静音 + 音调错）。

**② 近场破音：三个增益叠在一起**
- **KU100 的 npz 打包集从来没做过响度标定**（SOFA 分支有、npz 分支漏了）：
  1 kHz 灵敏度是 KEMAR 的 3~4 倍，同一句话换数据集直接差 10 dB；
- `dist_gain(0.2) = 1/(0.4+0.12) = 1.92`（+5.7 dB），而近场 HRIR 本身已含「近=响」的能量；
- `NearField` 再给 180 Hz 以下 +5.6 dB（0.2m 时 t=1、k=0.9）。

低语素材峰值本来就在 −3~−6 dBFS，三层一乘就进 `_soft_knee`（0.85 起压）——
听感正是「破音 + 毛糙，像劣质麦克风」，而且**试听（WebAudio）比导出更严重**
（前端还有独立的 +6 dB 低频补偿，距离律也是旧的 1/(0.4+0.6d)）。

修法：
1. `HRTFSet.__init__` 统一按 **1 kHz 灵敏度** 标定到 0.5（所有来源都走，幂等）；
   不用总能量 —— KEMAR 512 taps 与 KU100 118 taps 的 IR 长度不同，能量口径没法比；
2. `dist_gain` 改成 `min(1.25, 1/(0.45+0.55d))`：近场封顶 +1.9 dB，1m=0 dB，2m=−3.8 dB；
3. `NearField` proximity 0.9→0.55（+5.6→+3 dB），过渡 (1−d)/0.8 → /1.0；
4. `_soft_knee` 阈值 0.85→0.92、上限 0.98→0.995（低语不再被持续压）；
5. 前端 `timeline.js` 同步同一条距离律与 3 dB 低频量，试听 / 导出终于一致；
6. `_render_mix` 返回 `peak`，前端在导出结果里提示「峰值贴上限，建议降 2~3 dB」。

标定后实测（1 kHz 正弦，双耳能量口径）：三个数据集 1m 处 0.50 / 0.52 / 0.50，
0.2m 处 0.69 / 0.75 / 0.86（修前 KU100_circ 是 2.19）；低语 + circ + 0.2m 导出峰值 0.769，
`|x|>0.985` 占比 0% —— 不再削顶。

**③ Demucs 设为默认**
两处下拉把 Demucs 排第一并 `selected`，`matPresetOps` 的 separate 也带 `engine:"demucs"`；
后端 `engine` 默认值改 `demucs`，**失败自动退回中置提取**并在动作标签里写
「中置提取（Demucs 不可用）」，不让整条素材处理失败。
`_t_demucs.py` 实测相关性：Demucs 0.992 / DSP 0.705。

**测试**：`_diag_mix.py`（40 句长剧本：0 丢句、0 主频错、0 跳变）、`_diag_speed.py`
（变速 880/660/440 Hz、前后半 RMS 一致、0 跳变）、`_diag_asmr.py`（峰值 0.769、不削顶）、
`_diag_binaural.py`（三数据集 1m 增益一致）；`_t_ku100.py` 的「各层能量=1」改为

### 5.51 「每秒一声嗒」的真凶：双耳渲染每 1 秒被重新调用（2026-10-28 上午）

用户反馈很关键：**浏览器试听没有，导出混音才有**。试听走 WebAudio（PannerNode 一次建好），
导出走 `_render_mix` 的分块循环 —— 差异只在后者。

**定位过程**（`_diag_step.py`）：同一个 6 秒片段，跑四种配置，量每个整秒边界的二阶差分：

| 配置 | 边界 d2 均值 | 段内 99.9% |
|---|---|---|
| 干声 | 0.0083 | 0.0331 |
| **仅双耳** | **0.0458** | 0.0080 |
| 仅房间 | 0.0092 | 0.0340 |
| **双耳+房间** | **0.0457** | 0.0119 |

只有开双耳才有台阶，且落在每个整秒（= `_render_mix` 的块边界，不是 render 内部的 4096 块）。

**根因**：`_render_mix` 每块（1 秒）调一次 `st_bin.render(seg[:hi-lo], ...)`。
`BinauralRenderer` 虽然用 `tail` / `hist` 保留了跨块状态，但**每块开头仍会产生约 0.05 的相位跳变**
（块内 4096 分块时状态是连续的，一旦跨调用就有偏差）。听感就是每秒一声很轻的「嗒」。

**修法**：把双耳渲染改成**整段一次渲染，再按块切片叠加**：

```python
if c["id"] not in bin_audio:                 # 首次遇到这个片段
    s_all = rd.slice(src_off, int(c_len * SR))   # 整段读
    s_all *= gain / 关键帧包络 / 淡入淡出        # 整段算，避免块内重算
    bl, br = st_bin.render(s_all, az, el, dist)  # 一次渲染
    bin_audio[c["id"]] = (bl, br)
...
o0 = int(round((a - c["start"]) * SR))       # 当前块对应整段里的位置
buf[lo:hi, 0] += bin_audio[c["id"]][0][o0:o0 + (hi - lo)]
```

内存按片段缓存，超过 24 段就丢掉最早的（LRU），长剧本也不会爆。
改完边界 d2：**仅双耳 0.0458 → 0.0013、双耳+房间 0.0457 → 0.0018**（比信号自身波动还小）。

**同批修掉的另外两个「啪」源**
- **变速缓存没有版本号**：`_prepared_source` 用「源文件 size+mtime」判断缓存有效性，
  改了算法旧缓存照样命中 —— 修好的问题在用户机器上会一直复现。加 `PREP_CACHE_VER = 2`
  （进缓存文件名与 meta），旧缓存自动作废、首次导出重建，结果里报告「重建 N 段变速缓存」；
- **显示长度 > 实际音频**：`dur` 可能比源里剩的长（改过速/裁过尾/素材被替换），
  以前照 `dur` 读，多出来的部分补零 —— 有声/静音交界处硬切。新增 `_clip_audible_len(c)`，
  块的 `b`、`idx` 跳过、淡出基准全部按它算，导出里报告「N 段比音频长（已按实际长度收尾）」。

**测试**：`_diag_step.py`（四种配置的边界 d2）、`_diag_clicks.py`（12 秒单片段，块边界零跳变）、
`_diag_clicks2.py`（重叠/房间/双耳/变速/22050+48000 混合、44.1k 与 48k 输出，零尖峰）、
`_diag_speed.py`、`_diag_asmr.py`；`_t_mix_clip_store.py` 的「整秒边界没有明显台阶」由失败转通过。

### 5.53 标签跟随：标签在时间轴上「跟不跟句子」（2026-10-29）

**用户报的现象**：对某一句直接重生成之后，有些标签像被钉在原来的位置，没有跟着句子动。

**根因（两条都成立，互相掩盖）**

1. **句间标签的落点取的是「台本流位置」**：`_build` 里维护一个 `cursor`，
   一句句累加 `base_dur + pause`，标签就落在 `cursor` 上。可是句子的**实际位置**来自
   `project.clips[uid].start`（拖动 / 重排 / 换轨后写进去的覆盖值），两者可以差很远 ——
   只要句子被移动过，标签就留在流位置上不动；
2. **句中标签的音效从来没生成过片段**：`_build` 只给 `line.inline[]` 生成 marker
   （`kind: "inline"`），没有 `clips.append`。所以「句中标签挂音效」在时间轴上只有一条标记线，
   混音里也没有声音 —— 而长按提示写的是「会在时间轴上生成对应素材」。

**数据模型**

```python
project.tagfollow = {"mode": "follow" | "fixed" | "inline" | "between"}
project.tagpos    = {"t:<标签行uid>": 12.34, "i:<句uid>:<标签k>": 4.56}   # 冻结的绝对时间
```

- marker 带 `key`（`t:` / `i:` 前缀），固定口径按 key 取 `tagpos`；
- 句中标签在台本侧带稳定键 **`k`**（`longform_api._clean_line` 缺省补一个）：
  `inline` 是按 `pos` 排序的，拿数组下标当键会在改位置后串位（A 的冻结时间跑到 B 身上）；
- 派生的标签音效片段带 `tfx`（覆写键）：句间 = 标签行 uid（兼容老工程），句中 = `uid#k`。
  前端 `writeClipOverride` 写 `project.tagfx[c.tfx || c.from_tag]`，同一句挂多个句中音效不会串轨。

**落点算法**

```python
tag_cursor = 0.0
# 语音行处理完之后：
tag_cursor = start + dur          # ← 实际片段结束（不是流位置）；直接覆盖，左拖也回退
# 标签行：
tag_time = _tag_time("t:" + uid, tag_cursor, inline=False)
tag_cursor = tag_time + hold      # 连续两个标签会按留白往后排
```

`_tag_time` 按口径决定「用派生值还是冻结值」：`follow` 全部派生；`fixed` 全部冻结；
`inline` / `between` 只让其中一类派生。冻结值缺失时回落到派生值（老工程不用迁移）。

**冻结的时机**：`POST /lf/tl/{sid}/tagfollow {mode, resnap}` —— 切到固定类口径时，
先用「全部跟随」跑一遍 `_build` 拿到当前所有标签的落点写进 `tagpos`（`resnap=false` 只补缺失的 key，
`resnap=true` 全部重写；界面上的 **⟳** 就是后者）。`follow` 不动 `tagpos`，随时切回来都不丢。

**marker.pinned 的语义**：不是「此刻值和派生值不同」（两者可能刚好相等），而是
**「这一类标签在当前口径下被固定住了」** —— 用户看到 📌 就该知道它不会跟句子走。

**顺手修的界面问题**：右侧面板顶部的 `.topstat` / `.progresswrap` 没有左右内边距，
窄窗口下「还没开始。选好范围后点…」贴着面板边缘、甚至被裁掉；补 12px 与 `.ppane` 对齐。

**测试**：`_t_round13.py`（38 项）—— 默认跟随（句间标签 = 上一句片段结束、句中标签 = 起点 +
比例×时长 + 延迟）、两个标签的音效片段起点、拖动 + 变长后一起移动、`fixed` 冻结后不动、
`inline` / `between` 各跟一半、`resnap` 重取、非法 mode 400、界面弹窗 4 个方案落盘、
时间轴下拉同步与 📌 显示、无 JS 异常。

### 5.54 三层默认值 + 标记面板（含「按 M 解除静音」复盘）（2026-10-29）

**三层默认值，别再混在一个抽屉里**

| 层 | 存在哪 | 作用范围 | 改它的入口 |
|---|---|---|---|
| 全局偏好 | `longform/settings.json`（`GET/PATCH /lf/settings`） | 这台机器上所有台本 / 工程 | 顶栏「⚙ 设置」上半部分 |
| 台本默认 | `script.defaults` / `script.sampling` | 单个台本里没单独覆盖的行 | 「⚙ 设置」里折叠的「台本默认参数」 |
| 工程覆盖 | `project.clips[uid]` / `tagfx` / `tagfollow` | 单个工程 | 时间轴（拖、属性面板、标记区下拉） |

```json
// settings.json
{"tl": {"lockVoice": true, "tagFollow": "follow", "snap": true, "hoverIns": true},
 "mix": {"format": "wav", "bitDepth": "16", "rate": "44100", "channels": 2, "dmode": "visible"}}
```

- `_load_settings()` 只「缺的补默认、值做收敛」，带 mtime 缓存；`_save_settings()` **先验值再合并**
  —— 非法值保持原样，不是退回默认（否则一次手滑就把用户设置清成出厂）；
- `tl.lockVoice` 进 `_build` 的 `locked: bool(o.get("locked", lock_default))`；
  `tl.tagFollow` 进 `_default_project()`（只影响新工程，老工程有自己的 `tagfollow`）；
- 前端：时间轴启动先 `GET /settings` 再 `reload()`；吸附 / 悬浮窗**本机手动切过的优先**
  （localStorage），否则用设置里的默认；导出对话框用 `mix.*` 预填。

**标记面板：三种来源，一套 key**

- 句中（`line.inline[i]`，key `i:<uid>:<k>`）· 句间（`kind:"tag"` 的行，key `t:<uid>`）·
  普通（`project.marks`，key = 自己的 id）。**普通标记跟句子无关，永远不参与标签跟随**；
- 筛选 / 多选 / 批量都在前端做（`MFILTER` / `MSEL`），批量操作才打接口：
  - `POST /lf/tl/{sid}/tags/sfx {keys, mid|null, gain}` → 改台本里标签的 `sfx`（挂 / 换 / 摘）；
  - `POST /lf/tl/{sid}/tags/mute {keys, mute}` → 写 `project.tagfx[<tfx key>].mute`；
  - `×` 注意 key 换算：标记 key（`i:uid:k`）≠ 覆写键（`uid#k`）。写错 key 的后果是
    「静音点了没反应 / 一刷新就恢复」，所以统一走 `_tfx_key_of()`；
- 右键菜单在列表行与画布标记线（±6px）共用 `openMarkerMenu()`；画布右键**先判标记再判片段**，
  否则标记线太细永远点不到；标记菜单里也带「粘贴到这里」，避免「标记正好在要贴的位置反而贴不了」。

**复盘：「按 M 加标记，某段音频自己解除静音」**

1. `addMarkAt()` 以前是 `markDirty()` + `persist()`：`persist` = **PATCH 整份工程 + reload**；
2. 用户在 700ms 防抖窗口里刚改过静音 / 换轨 / 音量 → 本该死等 `save()` 的改动，
   被这次 `reload()` 拿服务端旧快照盖回去；
3. 现象随触发时机漂移（有时丢静音、有时丢换轨），所以难复现 —— 但根因是**用一个重操作去改一个字段**。

修法两条，缺一不可：
- 标记走独立接口（`POST/PATCH/DELETE /lf/tl/{sid}/marks`），只读写 `project.marks`，不 reload；
- 静音这种「一丢就听得出」的状态改成 **立刻 persist**，不留在防抖里。

同批还抓到两个同源问题：
- `project.tagfx` 的 key 保存时被 `[:20]` 截断，而句中标签的 key 是 `uid#k`（21 字符）——
  覆写永远对不上，表现为「标签音效的静音 / 换轨一刷新就丢」；改成 `[:40]`；
- 标记的 `rangeSelect(m)` 与片段的 `rangeSelect(c)` **同名**：同一作用域里后声明的函数会
  静默覆盖前一个，结果片段 Shift 连选跑的是标记逻辑（只能选 2 段）。改名 `markerRangeSelect()`。
  教训：往一个大 IIFE 里加函数，先 `grep -c "function 名字("`。

**测试**：`_t_round14.py`（47 项）—— 设置默认值 / 保存 / 非法值保持原样、新工程的标签跟随与
锁定跟随设置、标记接口只动 marks（加 / 重名 / 删、重复加 409、片段静音不受影响）、
标签音效批量挂 / 摘 / 静音 / 取消静音、空 keys 400 / 不存在的音效 404、
界面（设置按钮在顶栏、四项全局设置落盘、台本默认折叠、筛选、Ctrl 多选、右键菜单、
**按 V 静音 → 按 M 三次 → 前后端都还是静音**）。
回归 `_t_round13`、`_t_tl_bulk`、`_t_tl_keys`、`_t_round5/7/8/12`、`_t_lf_ui/misc_ui/tags` 全绿。


## 6. 前端实现要点（迁移时直接照抄的结构）

### 6.1 坐标系统（时间轴画布）
```js
pps        // 每秒多少像素（缩放）
scrollX    // 横向滚动（像素）
xOf(t) = t * pps - scrollX + 0.5
tOf(x) = (x + scrollX) / pps
trackTop(i)  // 第 i 条轨的 y（含"新建轨按钮行"高度与分组间距）
trackIndexAtY(y)  // 命中哪条轨
```
**所有拖拽/命中判定都走这四个函数**，不要在各处手写换算。

### 6.2 拖拽状态机
```js
S.drag = { type: "move" | "trim_left" | "trim_right" | "moveLocked" | "scrub",
           c, x0, y0, t0, oStart, oDur, oOffset, oSrcDur, moved, overlapTimer }
```
- `mousedown` 判定区：边缘 10px 内 = 裁剪（`col-resize`），中间 = 移动（`grab`），锁定 = `not-allowed`；
- `mousemove` 里**只更新几何与提示**，重叠分流交给 `setTimeout`；
- `mouseup`：`commitClip()` 写差分 → 自动保存。

### 6.3 绘制顺序（决定视觉层级）
```
1 轨道背景（奇偶交替）
2 裁剪幽灵块（被裁掉的原始部分，半透明虚线；不参与重叠判定）
3 片段本体（渐变填充 + 波形 + 文本 + 标签）
4 选中边框与左右握把
5 网格线
6 标记线 + 标签
7 播放头
```

### 6.4 DOM 与 Canvas 的分工
- **Canvas**：轨道、片段、波形、标尺、标记、播放头（高频重绘）；
- **DOM**：轨道头（按钮/滑块/菜单）、属性面板、素材库、悬窗、右键菜单、弹窗（低频、可交互）。
- 轨道头与画布要**纵向同步滚动**（`scrollTop` 互相同步 + 防递归标志）。
- ⚠️ 坑：`.head` 在 flex 纵向容器里默认会被压缩（64px→55px），轨道头与画布越往下越错位
  → 必须 `flex: none`。

## 8. 验收清单（换模型后照着跑）

**后端（HTTP 级）**
1. 建台本 → 加 3 句 → 渲染 → `status=done`、`audio/` 有文件、`dur` > 0；
2. 改文本 → `status=stale`、`changes` 里能读到 diff、`can_revert=true`；
3. 撤回 → 回到 `done`，文本/参数还原；
4. 建工程 → 新 sid、`project.source_id` 正确、音频是硬链接；
5. 时间轴 `GET /lf/tl/{sid}` → 语音片段**默认锁定**、`start` 与累加结果一致；
6. 改一句 `dur` → 后续片段整体平移、`initial_start` 不变；
7. 混音：wav/flac/mp3/ogg × 单/立体声 × 44.1k/48k × 时段 → 采样率/时长/声道都对；
8. 工程包：`rpp` 有 TRACK/ITEM/MARKER/FADE、`edl` 有 25fps 时间码、`audacity/` 有 labels.txt；
9. 删除台本 → 移入 `_trash`（不要 `rmtree`，某些沙箱环境会拦截并杀死进程）。

**前端（CDP 自动化）**
1. 页面无 JS 报错；
2. 时间轴：N 条轨、语音片段全部锁定、导航窗存在、右键菜单含解锁；
3. 拖动片段改位置 → 刷新后仍在（持久化）；
4. 拖边缘裁剪 → `dur` 变小、幽灵块出现；
5. 播放 → 播放头推进、电平表有读数、文件名正确；
6. 主题切换 → 三页同步且 canvas 重新着色；
7. 导出弹窗：选项齐全、说明可打开、预估数字随选项变化。

## 9. 已知限制与取舍

| 限制 | 原因 | 取舍 |
|---|---|---|
| 试听没有实时左右声像 | 用原生 `<audio>` 播放 | 声像在**混音导出**里生效（成品才是关键） |
| 倒放功能已移除 | 原生播放器无法可靠表达；Web Audio 路径又不稳 | 去掉比半残好（避免误操作） |
| MP3/OGG 码率偏低 | 本机无 ffmpeg/lame | UI 明示，建议交付用 WAV/FLAC |
| 工程导出不写 AAF/OMF | 格式复杂且闭源 | rpp + EDL + Audacity 覆盖主流工具 |
| 重叠只能"分流"不能"自由叠层" | 多轨叠层会让成品不可控 | 需要叠层就新建轨道（本来就是 DAW 的做法） |
| 时间码由 dur 派生，不存盘 | 保证一致性 | 无法做"完全脱离台本的手工时间轴"（那属于另一层功能） |
| 人声分离是 DSP 中置提取，不是模型分离 | 无 pip / 未装 Demucs，模型需额外环境与权重 | 秒级、免模型；伴奏居中时残留，UI 明示"想要更强可换 Demucs" |
| 素材固定转 44.1k | 与时间轴/混音同一条线 | 原始 22.05k 的音色会被上采样（不增信息，但不损听感） |

### 10.2 术语
- **行（line）**：台本里的一条，语音行或标签行；
- **片段（clip）**：时间轴上的一段音频，语音片段由行派生，素材片段来自素材库；
- **差分（diff）**：`project.json` 里只记录与派生默认值不同的部分；
- **初始样本**：进入时间轴那一刻的台本快照；
- **工程副本**：从源台本克隆出来的、用于时间轴编辑的独立台本；
- **幽灵块**：被裁剪掉、但仍以半透明虚线显示的原始长度部分。

### 10.3 参考思路来源
- 工程化交互：Photoshop / After Effects 的"新建工程 + 另存副本"；
- 多轨编辑：Reaper / Premiere 的轨道-片段模型、锁定与吸附；
- 裁剪手感：剪映的左右边缘拖拽 + 原长度虚影；
- 交付格式：AAF/EDL/RPP 生态的"时间线数据源"定位；
- 状态一致性：内容寻址（content-addressed）思路 —— 用指纹决定"要不要重算"。
