# 气声 / 非语音人声的分离：模型选型与实测

> 2026-11-02 ｜ 关联文档：《音效智能拆解_可行性评估.md》  
> 问题：ASMR 里"喘息、耳语、口腔音"这类人发出但功能上是音效的声音，用 MelBand Aspiration 会不会更好？SAM Audio 呢？还有别的路吗？

---

## 0. 先把"喘息"拆成三种需求，否则会选错模型

| 需求                   | 实际要的是什么         | 需要分离模型吗                   |
| -------------------- | --------------- | ------------------------- |
| A. 切音效时**别把喘息漏掉**    | 不丢就行            | **不需要**。从 Original 取，天然不丢 |
| B. **去台词、留喘息**（汉化核心） | 把"说话"和"非语音人声"分开 | 需要                        |
| C. 把喘息做成**独立可复用的一层** | 单独一条轨           | 需要，且要求更高（不能有串音）           |

需求 A 用分离模型反而更差（分离有损耗）；真正需要模型的是 B 和 C。下面的评估都按 B/C 来看。

---

## 1. MelBand Aspiration：真能提气声，但**必须两层用**

模型：`aspiration_mel_band_roformer_sdr_18.9845.ckpt`，**797 MB**，mel_band_roformer，立体声（`num_channels: 2`），  
训练目标就两个 stem：`instruments: [aspiration, other]` —— 也就是"气息"对"其余全部"。  
同在 pymss 模型库（`vocal/aspiration_breath/`），**不需要新后端、不需要新依赖**，一条命令就能下。

### 1.1 三段素材的实测

| 素材            | 气声轨（相对原）     | 说话段里的取值                   | 间隙段里的取值     | 气声 vs 人声相关 |
| ------------- | ------------ | ------------------------- | ----------- | ---------- |
| 148s 纯耳语 ASMR | **−12.0 dB** | −12.1 dB                  | **−0.0 dB** | 0.270      |
| 331s 带音乐床     | −10.8 dB     | −11.0 dB                  | −13.1 dB    | 0.248      |
| 30s 片段（带床）    | −9.8 dB      | 首 −9.2 / 中 −9.5 / 尾 −12.8 | —           | —          |

**怎么读**：

- 纯耳语素材上，间隙段取走 100%（−0.0 dB）、说话段只取 25%（−12 dB），**区分度 12 dB** —— 说明它确实在挑"气息"；
- 句内三段：首 −11.3 / 中 −15.6 / 尾 −12.1（本轮另一组测量）—— **两端比中段多取 3–4 dB**，而气口正好在句首句尾。方向对，但幅度不大，说明把握不算强；
- **一旦有音乐床，区分度就没了**（−11.0 vs −13.1，只差 2 dB），而且 30s 片段上 `气声 vs 伴奏相关 0.289` —— 床被当成气息吸走了。

### 1.2 正确管线：先分人声，再在人声轨上提气声

| 做法                              | 气声轨      | 与音乐床的相关           |
| ------------------------------- | -------- | ----------------- |
| A 直接在原音上提                       | −9.8 dB  | **0.289**（床漏进来）   |
| B 先 `vocal/inst` 分开，只在 vocal 上提 | −13.8 dB | **0.005**（床几乎不进来） |

B 的代价只是多一次推理。结论很明确：**气声模型不能单独用，必须叠在人声分离之后**。

### 1.3 成本

| 项           | 数值                                             |
| ----------- | ---------------------------------------------- |
| 体积          | 797 MB（人声模型才 275 MB）                           |
| 耗时（148s 素材） | 8.8 s（比 BS-Roformer 的 21.2 s 还快，MelBand 8s 分块） |
| 显存          | 与 797MB 权重同量级，实测与 BS-Roformer 同机可共存            |
| 输出          | stereo，**双耳信息没丢**（这一点比 SAM Audio 强）            |

### 1.4 训练域的问题（必须说清）

它的 `aspiration` 类来自歌唱换气（社区模型的标准用途是"去人声留换气"），  
**ASMR 的口腔音、舔耳、黏连声不一定在训练分布里**。实测"首尾比中段多 3–4 dB"这种弱信号，  
支持"它在取呼吸"，但不足以证明它认得所有 ASMR 非语音人声。这一条只能靠耳朵判断（见 §5 试听）。

## 2. 一个已经踩到的坑：模型混放会抢"默认选中"（已修）

把 797MB 的气声模型丢进 `vendor2/roformer/` 之后，`_roformer_scan` 的排序是  
「Roformer 系优先 → 体积大的在前」，于是：

```
pick = aspiration_mel_band_roformer_sdr_18.9845.ckpt   ← 气声模型
```

而 `_roformer_separate` 不指定模型时用的就是 `pick`，它要求产出里有人声轨 →  
直接抛「模型没有产出人声轨」。**也就是说，只放一个模型文件就能让整个人声分离功能失效**，  
而且报错信息完全指不到原因。

已修（`longform_api.py`）：

- 新增 `_roformer_role()`，按文件名判角色：`aspiration / karaoke / speech / vocal / other`；
- 排序改为**角色优先**（vocal → other → speech → karaoke → aspiration），同角色内仍按体积；
- 默认选中改为"第一个 vocal 角色的模型"，而不是列表第一个；
- 明确选了气声模型时给一句人话报错，而不是"没产出人声轨"。

验证：`pick = bs_roformer_voc_hyperacev2.ckpt`，默认分离正常；指定气声模型时报  
「这是气声提取模型（只出 aspiration/other 两轨），不能当人声分离用」。

**这条经验适用于后续所有"可选引擎"**：模型目录是用户可写的，任何"按体积/按时间"的默认排序  
都会在用户多放一个模型后失效 —— 默认值必须按**用途**选，不能按**文件属性**选。

## 3. SAM Audio：能力强，但对我们有三条硬伤

事实（Meta 2025/2026 发布）：

- 开放权重，`facebook/sam-audio-{small,base,large}` + 三个 `-tv` 变体；**HF 上 gated（需申请 + token）**；
- 规模：small 500M / base 1B / large 3B 参数；官方给的 RTF 约 0.7（10 秒音频、单张 A100 约 7 秒）；
- 三种提示：文本（`"breathing"` 这种短语）、视频点击、时间跨度（span prompt，业界首创）；
- 输出 **target + residual 两条轨**；
- 许可：**SAM License**（自定义，不是 Apache/MIT），需申请后才能下。

第三方基准（Hive，arXiv 2601.22599）里对它的评价值得抄下来：SAM-Audio 在该基准上  
**8.2B 参数、约 32 GB 显存**，感知指标很好（FAD≈1.0）但**语义保真差（CLAP-T 落后）**，  
被归因为"倾向条件合成而非真正提取，会产生幻觉纹理"。

对我们的三条硬伤：

1. **输出是单声道**。双耳 ASMR 的方位感来自左右相位差；左右各跑一次是两次独立采样，  
   ITD/ILD 会崩，拼回去的"喘息"会飘。这一条几乎一票否决；
2. **它是生成式的**。我们需要的恰恰是"原样保留那口气"，不是"生成一口听起来像的气"。  
   幻觉纹理在音乐/音效上听不出来，在贴耳喘息上很明显；
3. **分发不可自动化**。gated repo + 自定义许可，补丁不能静默下载，用户要注册、申请、配 token。  
   跟"检测到就启用"的可选引擎模式天然冲突。

结论：**不作为第一阶段依赖**。只在"单声道、短片段、按文字点单"的场景里才有价值，  
而且要接受它"合成"而不是"提取"。

## 5. 我更推荐的方案：不做分离，做"门控 + 拼接"

对需求 B（去台词留喘息），有一个比换模型更省的做法：

```
1. 检测"呼吸/气声区间"（不需要模型：无基频、谱平坦度高、能量包络平滑、常出现在句界）
2. 该区间 → 从 Original 原样取
3. 其余区间 → 用 vocal/inst 分离后的 inst
4. 拼接处做 30ms 交叉淡化
```

**为什么这个更好：**

| 维度   | 分离模型           | 门控拼接          |
| ---- | -------------- | ------------- |
| 音质   | 重建，有损耗/伪影      | **原音，零损耗**    |
| 双耳   | 取决于模型是否 stereo | **天然无损**      |
| 依赖   | 797MB（气声）或更多   | 0             |
| 可解释  | 黑箱             | 每一段都能在波形上指出来  |
| 失败模式 | 串音、幻觉          | 区间判错（看得见、可手调） |

**气声模型在这里仍然有用 —— 但不是当分离器，而是当检测器的先验**：  
它的输出包络本身就是"这里有没有气声"的强特征，比从零调阈值（谱平坦度 + 过零率）稳得多。  
也就是说：**797MB 花在"告诉我气口在哪"，而不是"把那口气抠出来"**。

局限要说清：说话同时喘（重叠）它处理不了 —— 那一段只能二选一，或者留给人工。

## 6. 建议的落地顺序

| 优先级 | 做什么                                           | 依赖               |
| --- | --------------------------------------------- | ---------------- |
| P0  | 门控拼接（检测气声区间 → 从 Original 取）                   | 0 新模型，复用现有切分     |
| P1  | 气声模型作为第二层：`vocal → aspiration/speech`，只在人声轨上跑 | 797MB，同后端        |
| P2  | AudioSep 文本点单（"提取亲吻声"这类）                      | 913MB，Apache-2.0 |
| P3  | SAM Audio：观望。等它支持 stereo、或者我们只需要单声道短片段时再评估    | gated            |

P0 和 P1 是互补的：P0 保真、P1 干净。实际用起来大概率是  
**逐句判定：能门控的走门控，重叠严重的走 P1**。

## 8. 四段真实"特殊片段"实测（2026-11-02 补）

素材：`Downloads\asmr特殊片段测试`（喘息×2 / 舔耳×1 / 运动×1，共 701 秒，44.1k 立体声）。  
三种做法全跑：BS-Roformer（基线）、气声模型直接作用于原音、两层（先分人声再提气声）。

### 8.1 能量归属

| 片段   | 时长   | BS 人声             | BS 伴奏      | 气声（直接）        | 气声 vs 伴奏（直接→两层）   |
| ---- | ---- | ----------------- | ---------- | ------------- | ----------------- |
| 喘息-1 | 407s | **−0.0 dB（100%）** | −23.6（7%）  | −11.3         | 0.291 → **0.036** |
| 喘息-2 | 133s | **−0.1 dB（99%）**  | −20.3（10%） | −9.8          | 0.338 → **0.043** |
| 舔耳-1 | 118s | **+0.0 dB（100%）** | −39.6（1%）  | **−1.7（98%）** | −0.07 → −0.08     |
| 运动-1 | 46s  | **−0.0 dB（100%）** | −24.0（6%）  | −14.5         | 0.406 → **0.047** |

**四段全部被 BS-Roformer 判成"人声 100%"**，伴奏轨只有 1–10%，且舔耳的伴奏轨底部  
有一条 64–100 Hz 的持续泄漏带（谱图上很明显）。也就是说：**"从非人声轨切音效"这条路，  
对 ASMR 的非语音人声彻底不成立** —— 不是"分得不够干净"，是它压根不在那条轨上。

耗时（407s 素材）：BS 31s + 气声 12s + 两层 19s ≈ 63s。

### 8.2 谱图揭示的真相：它是"谐波/非谐波"分离器，不是"呼吸/说话"分离器

看 `喘息-2` 和 `舔耳-1` 的五轨谱图（原 / BS人声 / BS伴奏 / 气声两层 / 气声其余）：

- **喘息**：原音是"带音高的浊音 + 宽带气声"的混合，一排排谐波弧线很清楚。  
  气声轨留下的是**低频沙沙的宽带部分**，其余轨留下的是**谐波弧线** —— 两边刚好互补。
- **舔耳**：原音几乎全是宽带湿润声，只在 3–5s、7s 有几声"嗯"。  
  气声轨拿走全部湿润声，**其余轨只剩那几声"嗯"**，干净得可以直接当"浊音位置指示器"。
- 这解释了此前所有的数字：纯耳语（无谐波）→ 全归气声；舔耳（无谐波）→ 全归气声；  
  音乐床（有谐波也有噪声）→ 噪声成分被吸走一部分。

**所以这个模型的正确理解是：把"带周期的发声"和"不带宽带的噪声"分开。**  
把它当"呼吸提取器"只在"纯气流"这一种声音上成立，遇到任何宽带音（舔耳、摩擦、雨声）都会被一并认领。

### 8.3 由此得到的三条可用/不可用

| 用途                   | 结论    | 依据                           |
| -------------------- | ----- | ---------------------------- |
| 取"气声/耳语层"（做气声化、做呼吸轨） | ✅ 可用  | 喘息素材上气声/其余严格互补，宽带部分干净        |
| 定位"哪儿有带音高的发声"        | ✅ 可用  | 舔耳素材上其余轨只剩几声"嗯"，几乎无误报        |
| **去台词、留喘息**          | ❌ 不可用 | 台词和喘息**都是谐波**，落在同一条轨上，模型无从区分 |
| 从"非人声轨"切音效           | ❌ 不可用 | 四段全部 100% 归人声                |

### 8.4 结论调整：不要"识别音效"，要"按台词区间做减法"

四段实测把方向改写了：**没有哪个模型能通用地判断"这是音效不是台词"**，因为 ASMR 里  
两者在声学上是同一类东西（人发出来的、宽带或带音高的声音）。继续在"分类/分离"上加模型，  
边际收益会一直很低。C:\AI\IndexTTS2.0_v3_asmr_test_out\运动-1

可行的做法只有一个方向：**用打轴给出的"台词区间"做减法** ——

1. 台词区间内：抠掉（或替换成中文 TTS）；
2. 台词区间外：**原样保留整段 Original**，不做任何分离；
3. 区间边界向内缩 100–150 ms 并做 30 ms 交叉淡化，把句首吸气、句尾呼气留给"保留"那一侧；
4. 唯一需要模型的场景：判断某句台词里**是否夹着喘息**（重叠），这时用气声轨在该句内的  
   能量占比做提示，交给人确认 —— 不做自动决定。

这条路线不依赖"模型认不认舔耳"，而且音质零损耗（保留的是原音，不是重建的）。

### 8.5 这批测试没能覆盖的

四段都是**纯音效、无人声台词**，所以测不出"台词与音效重叠"时的表现。  
下一步要验的是：拿一段"边喘边说"的素材，看  
① 打轴区间能否把台词框准；② 框内到底混进了多少喘息；③ 缩边界能不能救回来。  
这比再换一个分离模型更有价值。

**工程提醒**：写"自动挑能量最高的一段做试听"时不要用 `np.convolve` 算滑窗能量 ——  
direct convolution 是 O(N·M)，十几分钟素材会跑死（本次实测脚本就因此被当成卡死杀掉）。  
用前缀和 cumsum 是 O(N)。

## 9. 气声轨的"电流感 / 残留人声"：能优化，但收益有限（2026-11-02 补）

现象（用户听感）：`_asmr_test_out/运动-1/5气声-两层.wav` 里有没去干净的小人声，
还有一层"电流质感"的怪声。逐项拆开查：

| 假设 | 做法 | 结果 |
| --- | --- | --- |
| 相位不一致（模型自己合成波形） | 幅度取模型 `|A|`、相位取原音 `∠V` | 包络抖动 0.240→0.233、谱洞 5.77%→5.59%，**几乎无变化** |
| 软掩蔽漏了谐波 | 相位借用 + 谱减 0.5/1.0 倍其余轨 | 周期性 0.163→0.145/0.140，但谱洞升到 5.65%/6.03%，抖动升到 0.253/0.268（**越减越沙**） |
| 低频隆隆 + 密集小点 | 相位借用 + 高通 110 Hz + 软谱门（低于局部底噪压到 28%）+ TF 中值平滑 | 周期性 0.163→**0.135**；谱图上 64–110 Hz 那条持续亮带**消失**，低频毛刺明显减少；代价是抖动 0.267（更"沙"） |

**结论：能压掉"隆隆"和一部分"毛刺"，压不掉"沙"。**
因为纹理来自模型在这段素材上的谱估计本身（大量孤立时频点），不是相位问题，
所以任何"怎么用它的输出"级别的后处理都只能是打折，不会是质变。

顺带一个更省事的判断：**这段素材（衣物摩擦/运动）根本没有台词**，
它压根不该走"去人声/提气声"这条路 —— 正确产物就是原音，最多加一道 110 Hz 高通去掉隆隆。

## 10. 定点去台词受控实验：喘息能留住，但必须用打轴（2026-11-02 补）

因为前一轮的四段素材都没有台词，测不出"去台词时喘息会不会被一起删掉"，
所以做了一次**有真值**的混合实验：

- 底：真实喘息素材 `02 Bimbo Naptime…` 的 60 秒；
- 台词：`嘉然-正常音1` 的三段各 3 秒，插在 8s / 26s / 44s，比底噪高 3 dB；
- 真值区间已知，因此可以精确算出"喘息掉了多少、台词去了多少"。

| 方案 | 台词区中心 1s | 喘息区保留 |
| --- | --- | --- |
| 混音（原始） | −12.6 dB | 基准 |
| ① 整轨去人声（BS 伴奏轨） | −18.8 dB（只降 **6.2 dB**） | **−2.1 dB** |
| ② 定点去台词（真值区间）+ 清空补底噪 | −25.8 dB（降 **13.2 dB**） | **+0.0 dB** |

**三个必须记住的数**：

1. **BS 在这种混合上只做到"对半劈"**：人声轨 −3.5 dB、伴奏轨 −2.6 dB（相对混音），
   两边能量加起来刚好等于原信号。因为"喘息"和"台词"都是人声类，模型没有区分依据。
   所以"整轨去人声"只把台词压掉 6 dB —— 听感上等于没去；
2. 定点去台词（只动台词区间，区间外原样保留）把台词压了 13 dB，而喘息区**完全不动**（+0.0 dB）；
3. **VAD 会把 81% 的喘息区判成台词**（因为喘息也在人声里）。用 VAD 代替打轴 = 把喘息全删。

**因此"定点去台词"的前提是：区间来自打轴（知道哪儿是句子），而不是 VAD（只知道哪儿有声音）。**
这也正好解释了为什么"打轴"是整套汉化流程的地基，而不是可选项。

**重叠处只能牺牲**：说话同时喘的地方，删台词必然连喘息一起删；
能做的只有把边界向内缩 100–150 ms、30 ms 交叉淡化，把"纯呼吸"的部分留在区间外。
如果一定要保留重叠处，只能人工处理 —— 目前没有可用的模型能分开"同一时刻的台词与喘息"。

## 11. 正常声 → 气声（N2W）：模型不行，DSP 能出气声但不好听（2026-11-02 补）

素材：`嘉然-正常音1`（14.3s，同一人的正常说话），五种做法全部统一响度后比较。

| 方案 | 周期性（越低越像气声） | 共振峰保真（越高越"还是这个人"） | 高/低比 |
| --- | --- | --- | --- |
| A 原音 | 0.259 | 1.000 | −22.4 dB |
| B 气声模型直取 aspiration 轨 | **0.164（还是浊音）** | 0.832 | **−4.8 dB（比真人耳语亮 13dB）** |
| C B + 高通谱门 | 0.147 | 0.772 | −3.9 dB |
| D **LPC 残差替换**（保共振峰、换激励） | **0.071** | 0.909 | −23.1 dB（基本不变） |
| E 相位随机化（旧方案） | 0.056 | 0.987 | −9.1 dB |
| 参考：真人耳语（嘉然-ASMR音3） | 0.530（含背景乐，不可比） | — | −17.5 dB |

**读法**：

1. **模型路线在这里是错的**：`aspiration` 轨并不是"耳语"，它是"去谐波后的残渣"。
   周期性只掉到 0.164（还听得出音高），而高/低比飙到 −4.8 —— 比真人耳语亮 13 dB。
   这就是"电流/嘶声"的来源：它把中高频噪声放大了十几 dB，却保留了音高。
2. **LPC 残差替换是四条路里最像"人在说气声"的**：周期性 0.071（几乎无音高）、
   共振峰保真 0.909（听得懂、还是这个人）、频谱倾斜基本不动（没有人为提亮 ——
   这正是它不像相位随机化那么"怪"的原因）。
3. **但它偏闷**：比真人耳语暗 7 dB。而且加"气流噪声"改变不了这一点 ——
   噪声是在 LPC 滤波器**之前**注入的，会被共振峰重新塑形，频谱倾斜由滤波器决定，
   实测 air 从 0 加到 +18 dB，倾斜一直是 −24.9。
4. 想变亮只能事后加高频，而那正好是用户已经否决过两次的"塑料感"来源。

**结论：这条路不值得做进工作台。**

- 要"真耳语"，目前只能靠真人录音（素材库里已经有），或者等专门的 N2W 模型
  （WhispEar 未开源，见 §6）；
- 要"小声说话"这一档，LPC（D）可以直接用，音色几乎不变、时长不变；
- 模型给的 aspiration 轨不适合当输出 —— 它只适合当"哪里是气声"的**判据**，不适合当成品。

## 12. DnR（Divide-and-Remaster）复测：舔耳终于进了「音效轨」，喘息仍然没有（2026-11-04）

这一轮用户点名要 DnR，另外补了 Demucs 的微调版做对照。素材仍是
`Downloads\asmr特殊片段测试`（喘息×2 / 舔耳×1 / 运动×1，共 704 秒）。

### 12.1 用了哪三个模型

| 模型 | 架构 | 体积 | 输出轨 | 说明 |
| --- | --- | --- | --- | --- |
| **DnR** `model_bandit_plus_dnr_sdr_11.47.ckpt` | bandit | 149 MB | **Speech / Music / Effects** | 电影混音数据集训的「对白/音乐/音效」三分，SDR 11.47。**这是唯一一个把「音效」单独列一轨的** |
| BS-Roformer `bs_roformer_voc_hyperacev2` | bs_roformer | 275 MB | vocals / instrument | 现有工作台默认，基线 |
| Demucs-FT `HTDemucs4_FT_vocals_official.th` | htdemucs | 84 MB | vocals / drums / bass / other | Demucs 的微调版（比整合包自带的大一号） |

跑法：`pymss.cli download` → `create_separator` → `separate`，44.1k 立体声原样输入，
DnR 是单声道模型（左右分别跑再拼回，双耳信息保留）。

### 12.2 能量归属（相对原音，dB；越接近 0 说明这一轨拿走了越多）

| 素材 | DnR Speech | DnR Music | DnR Effects | BS vocals | BS instrument | Demucs-FT vocals |
| --- | --- | --- | --- | --- | --- | --- |
| 喘息-1（407s） | **−2.1** | −8.3 | −8.4 | −0.0 | −23.7 | −0.3 |
| 喘息-2（133s） | **−2.2** | −8.7 | −7.3 | −0.1 | −20.8 | −0.2 |
| 舔耳-1（118s） | −9.9 | −15.1 | **−1.0** | +0.0 | −39.5 | −2.2 |
| 运动-1（46s） | **−3.2** | −5.3 | −11.7 | −0.0 | −23.9 | −0.0 |

耗时（407 秒素材）：DnR 174s / BS 30s / Demucs-FT 24s —— **DnR 慢 6 倍**，因为它对左右声道各跑一遍。

### 12.3 三个结论

**① 舔耳是第一个「被正确归到音效轨」的素材。** Effects 拿走 90%（−1.0 dB），
Speech 只剩 −9.9。这是 BS / Demucs 做不到的（它们都是 100% 人声）——
因为 DnR 的训练目标就是「对白 / 音乐 / 音效」，舔耳在电影里本来就是音效。

**② 喘息仍然被算作 Speech（−2.2 dB，78%）。** 和 BS 一样。原因没变：
喘息有声带振动、有谐波结构，在数据分布上就是「人声」。

**③ 混在一起时它照样分不开。** 做了一次受控实验：喘息底 60 秒 + 在 8/26/44 秒各插 3 秒台词
（嘉然-正常音1，比底噪高 3 dB），真值区间已知：

| 区间 | DnR Speech | DnR Music | DnR Effects | BS vocals | BS instrument |
| --- | --- | --- | --- | --- | --- |
| 台词区（9s） | −1.3 | −9.6 | −11.9 | −0.0 | −23.6 |
| 喘息区（51s） | −1.0 | −8.1 | −15.5 | −0.1 | −20.4 |

**台词区和喘息区都落在 Speech，差值只有 0.3 dB** —— 模型完全没区分「说的」和「喘的」。
这条和 §10 的结论一致，只是换了个模型再验证一次。

### 12.4 所以 DnR 该怎么用

| 场景 | 能不能用 DnR |
| --- | --- |
| 从混音里单独取「纯音效」（舔耳、摩擦、环境声） | **能**，Effects 轨是现有模型里唯一可用的 |
| 去掉台词、保留喘息 | **不能**，两个都在 Speech |
| 判断某句里有没有夹着喘息 | 不能，Speech 里分不出来 |
| 日常配音流程 | 不建议默认启用：慢 6 倍，且对 ASMR 主要素材（喘息）无收益 |

## 13. 能不能把「人声音效」换成工作台音色（Takin-VC 调研，2026-11-04）

### 13.1 Takin-VC 本身：不可用

- 论文两篇：`arXiv 2409.12139`（Takin AudioLLM 系列）、`arXiv 2410.01350`（Takin-VC）；
  团队是喜马拉雅 Everest；
- 方法确实是这个需求最贴的：WavLM + HybridFormer PPG 的自适应混合内容编码，
  论文明确说「能保留呼吸、哭腔等副语言信息」，CFM 解码 + HiFiGAN 声码器；
- **但代码和权重都没有公开**：官方 demo 站 `everest-ai.github.io/takinvc` 已 404，
  GitHub 上唯一同名仓库 `yaoxunji/takin-vc` 是空仓库（0 star，只有一行标题），
  HuggingFace / ModelScope 上没有任何 Takin 权重。
- 结论：**现阶段无法落地，也不存在「偷偷能跑」的版本**。

### 13.2 用同类开源方案做了等价验证（OpenVoice V2）

Seed-VC（同类零样本 VC）在这台机器上卡在 Windows 依赖：它的 v2 模型要用
`facebook/hubert-large-ll60k` + fairseq 系组件，py3.11 + Windows 没有可用轮子。
改用 **OpenVoice V2 的 tone color converter**（纯 mel 域音色替换，依赖只有
torch/librosa/soundfile，125MB 权重）跑通，素材取喘息-2 的 40s 起 10 秒、舔耳-1 的 20s 起 10 秒，
目标音色用工作台里的 `嘉然-正常音1`。

| 素材 | 包络相关（结构保留） | 转后 vs 目标音色 | 转后 vs 原音 | 原音 vs 目标音色 |
| --- | --- | --- | --- | --- |
| 喘息-2 | **0.961** | 0.668 | 0.542 | **0.700** |
| 舔耳-1 | 0.774 | 0.555 | 0.699 | 0.611 |

**读法**：时间结构保留得很好（包络相关 0.96），但**音色没有向目标靠** ——
喘息那行「转后 vs 目标 0.668」比「原音 vs 目标 0.700」还低。也就是说：
转换器输出的是「同一段喘息、换了层皮」，但这层皮不是嘉然。

原因和 §11 一致：这些模型判断「音色」靠的是声门特征 / 共振峰，
喘息、舔耳没有稳定的声门激励，也就没有可迁移的「音色」。
**先把非语音人声分离出来再换音色，同样不成立。**

试听：`C://Users//cx//Downloads//DnR分离测试//换音色试验//`
（`*-原音.wav` 与 `*-换成嘉然音色.wav` 成对，已统一 −20 dBFS）

### 13.3 这条路真要做的三个前提

1. **先能分离**：目前没有模型能把「台词」和「喘息」分开（§12.3 第 ③ 条），
   所以「只换音效、不换台词」在重叠处做不到；
2. **要有非语音的 VC 模型**：现有开源 VC（Seed-VC / OpenVoice / RVC）都是语音域训练，
   对非语音的输出是「换了包络的重建」，不是音色迁移；
3. **能接受生成式替换**：真要做，只能走「用 TTS 生成一段同节奏的喘息」的路线
   （类似音效生成），而不是「把原喘息换成另一个人的」。

短期建议：**这类素材继续用真人录音**（素材库里已有），
等 Takin-VC 或类似的「副语言感知 VC」真开源再评估。
