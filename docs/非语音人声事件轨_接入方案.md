# 非语音人声事件轨：VocalBurst 接入方案

> 2026-11-05 ｜ 对应代码：`longform_api.py`（`_VB_*` / `/lf/sfxb/vb/detect`）、
> `web/sfxbench.*`（4.5 卡 + 事件轨）、`web/longform.*`（模型拓展第三项）
> 关联：《音频打标模型评估.md》《气声与非语音人声分离_评估.md》

---

## 0. 先回答那句问题

> 「给非语音人声加了一条字幕轨，主要是对处理台上的音频片段自动命名、自动识别时间起止，对吗？」

**对，但只说对了一半。** 自动起止 + 自动命名是它最直接的用法，也是这一版做掉的部分；
它真正改变的是**处理台第一次有了「台词之外」的时间信息**：

| 以前只有 | 现在多了一条 |
| --- | --- |
| 字幕轨：哪几秒在说话 | 事件轨：哪几秒有一次非语言发声 |
| 切分只能按响度 / 字幕补集 | 可以按「事件」切，喘息叠在台词里也能单独成段 |
| 片段名字靠「按字幕命名」或手改 | 事件段自动带序号，且知道它属于第几句 |
| 入库后只有「音效台 · 引擎」 | 可以带事件来源、置信度、句号，便于回头找 |

这条轨不是「又一个分离模型」。分离解决「把声音拆开」，它解决「先告诉你声音在哪」。
两者不冲突：DnR 的 Effects 轨管「不是人发出的音效」，VocalBurst 管「是人发出的、但不是语言的声音」。

## 1. 它在工作流里的位置

```
① 选素材
② 处理（可选：去人声 / 去伴奏 / 原样）
③ 切成片段（静音 / 字幕 / 背景 / 起始点）
④ 字幕参考（台词时间轴）
④.5 非语音人声（VocalBurst）        ← 本次接入
      ├─ 只在波形上画事件（不改任何东西）
      └─ 用事件生成片段（自动命名 + 自动起止）
⑤ 处理方案（保存 / 回退）
⑥ 输出与对位（入库 / 写进工程）
```

**为什么放在 ④ 之后、⑤ 之前**：

- 放在 ④ 之后：事件要能和字幕交叉，才能标出「句内 / 句间」；
- 放在 ⑤ 之前：生成片段仍然走同一套「片段列表」，⑤ 的方案保存、⑥ 的入库/对位都不用改；
- 不放在 ② 里：它不是分离，和「留人声 / 留伴奏」不是一个维度，混在一起会让人以为
  「选了 VocalBurst 就能把喘息抠出来」。

### 1.1 一个必须处理的坑：伴奏轨上没有人声

如果 ② 选的是「伴奏（去掉台词人声）」，喘息 / 笑 / 叹气已经被一起去掉了。
这时候跑检测只会得到 0 个事件，用户会以为模型坏了。

处理方式是**先问再换轨**：检测前发现 `stem == instrumental`，弹窗说明
「这条轨上没有人声，要改用原样重新载入吗」，确认后自动把 ② 改成「原样」并重新准备
（只是复制原音，秒级），然后继续检测。不换轨就正常返回 0 个，不报错。

## 2. 数据契约

### 2.1 模型输出

```json
{"start": 57.92, "end": 58.06, "dur": 0.14, "conf": 0.609,
 "cue": 12, "in_cue": true, "cue_ov": 0.12, "type": "", "dup": 0}
```

| 字段 | 含义 |
| --- | --- |
| `start` / `end` | 相对**当前作业音频**的秒数（与字幕轨同一坐标系） |
| `conf` | 事件内逐帧概率均值；不是「类型置信度」 |
| `cue` | 落在第几条字幕（1 起）；0 = 不在任何字幕里 |
| `in_cue` | 事件与字幕重叠 ≥ 自身时长 30% |
| `dup` | 梅尔谱指纹分组号；0 = 没发现重复 |
| `type` | 粗类型名（笑 / 叹气 / 抽气 / 喘息…）；只有装了分类器且组置信度 ≥ 0.45 才有 |
| `type_en` / `type_p` | 分类器的细类 top-1 与组置信度，用于回查；不参与命名 |

### 2.2 后端接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/lf/sepro/status?kind=vocalburst` | 权重 / Whisper 底座 / 设备 / 默认参数 |
| POST | `/lf/sepro/open` `{kind}` | 打开模型目录（不存在就建） |
| POST | `/lf/sepro/test` `{kind}` | 加载 + 3 秒前向，只验链路 |
| POST | `/lf/sfxb/vb/detect` | 跑检测，返回事件 + 句内判定 + 查重分组 |
| POST | `/lf/sfxb/segment` `mode=vb` | 用事件区间生成片段（复用原有打包/电平计算） |

`/lf/sfxb/vb/detect` 请求：

```json
{"job":"0af5aba136", "threshold":0.35, "min_dur":0.08, "merge_gap":0.12,
 "cues":[[0.0,2.4],[2.8,5.1]]}
```

`threshold` / `min_dur` / `merge_gap` 都会被夹到安全范围，避免前端传 0 或负数把模型跑崩。

### 2.3 为什么检测要 30 秒分块、25 秒一步

Whisper 编码器固定吃 30 秒（1500 帧 × 50fps）。直接按 30 秒硬切，跨在边界上的
一次笑会被切成两半，两半都短于 `min_dur`，于是**整次事件消失**。

做法：

- 窗口 30 秒、步长 25 秒（5 秒重叠）；
- 非最后一块只保留「起点落在本块核心区（前 25 秒）」的事件，重叠区交给下一块；
- 最后按 IoU > 0.5 去重，再按 `merge_gap` 合并；
- 尾部不足 30 秒补零，但事件的 `end` 夹到真实时长，不会多出静音尾巴。

代价是 25 秒就要跑一次前向。本机（RTX 5070 Ti Laptop）407 秒素材约 11 秒推理 +
3 秒模型加载；72 秒素材 0.3 秒。可接受，但长素材仍是「点一下等十几秒」的量级。

## 3. 自动命名规则

```text
有类型：  类型 + "-" + 该类型内的序号     例：抽气-001、叹气-001、叹气-002
没类型：  前缀 + "-" + 全局序号           例：非语音人声-001、非语音人声-002
```

- 序号宽度跟着**这一次的事件总数**走（15 个 → 3 位；1200 个 → 4 位），
  避免 `_100` 排到 `_10` 后面（这是之前批量编号踩过的坑，这里复用 `_num_name` 的思路）；
- 有类型时**按类型各自编号**，不是全局流水号：`抽气-001` / `叹气-001` 比
  `叹气-003` / `叹气-007` 好找；
- 事件被「查重」过滤时，名字保留它在事件轨里的原始序号，不做重新编号 ——
  这样片段名和事件轨上的编号仍能对上，方便回查；
- 是否写类型由分类器决定：**组置信度 ≥ 0.45 才写**，拿不准就退回前缀。
  这是为了避免「狼哨-003」这种看似精确、其实乱猜的名字；
- 前缀可改（默认「非语音人声」），所以哪怕不装分类器，也能按素材改成
  「耳语」「口腔音」这类自己的叫法。

## 4. 这一版已经做到的「更多事情」

### 4.1 句内 / 句间（与字幕轨交叉）

对每条事件算它和字幕区间的重叠：

- 重叠 ≥ 30% → `in_cue = true`，事件轨顶部画一条青色短杠；
- 统计里给出「句内 N · 句间 M」；
- 句内事件是最有价值的一类：它说明**台词里夹着一声喘 / 笑**，人耳在长素材里几乎必漏；
- 勾「只要句内事件」可以只生成这一类，句间事件在轨道上变灰但不删 —
  适合专门找「台词里的气口」，不会被几百个环境音效淹没。

### 4.2 按事件切分，而不是按响度

`mode=vb` 直接把事件区间喂给原来的 `_sfxb_pack`：

- 不受「台词和喘息都有声音，RMS 分不开」的影响；
- 不受「字幕只覆盖台词，字幕之外的持续喘息没有边界」的影响；
- 事件段仍然会算 `peak` / `rms_db`，后面的试听、处理、入库、对位全部照旧。

### 4.3 同一个声音反复出现时自动查重

同一段素材里「每句话前都吸一口气」「关门 20 次」很常见。用现有
`_sfxb_fingerprint`（对数梅尔谱 → 去均值 → 归一化）对事件两两算余弦，
≥ 0.985 视为同一组。前端可勾「同一种声音只留第一次」，生成片段时每组只留第一条。

这不是「语义去重」，只是「听感几乎一样」；阈值高，宁可漏合并，不误删。

### 4.4 事件轨导出 SRT

事件本身就是「一条字幕」：起止 + 名字 + 置信度 + 句号。导出后可以：

- 给别的剪辑 / 字幕软件当时码表；
- 拿回工作台当「字幕参考」载入，用「按字幕切分」的补集逻辑再切一遍；
- 作为人工复核清单：一条条听，听到不对就改。

### 4.5 可选的类型命名（82 类分类器）

装了 `classifier/` + `voiceclap/` 之后，事件会多一个 `type`：

- 只信「家族概率和 ≥ 0.45」，不直接信 fine top-1（49% 太低）；
- 有把握的写 `叹气` / `抽气` / `笑` / `咳` / `舔舐`…，没把握留空；
- 片段名因此是混合的：`叹气-001`、`抽气-001`、`非语音人声-004`；
- 请求里可以带 `"classify": false` 关掉，前端目前默认开（就绪时）。

### 4.6 对位时跟着句子走（复用现有机制，不额外写代码）

处理台写进工程时，`_map_cue` 会先判断「这个时间落在载入字幕的第几句」，
再按序号找工程里的那一句，句内按比例换算。所以：

- 句内事件 → 跟着那一句走，换音色后句子变长变短，事件仍在句内相对位置；
- 句间事件 → 按前后两句的边界插值；
- 这条能力不是为 VocalBurst 新写的，但事件轨让它第一次有「句内锚点」可用。

## 5. 本机实测（重要，别只看官方 F1）

素材：`asmr特殊片段测试\` 四段 + `催眠红茶-片段测试2`（72 秒正常台词）。
设备：RTX 5070 Ti Laptop；`model_v2.pt`；阈值 0.50 / 0.35 / 0.25。

| 素材 | 时长 | 0.50 | 0.35 | 0.25 |
| --- | --- | --- | --- | --- |
| 喘息-1 | 406.9s | 4 个 / 0.5s | 14 个 / 2.3s | 25 个 / 4.2s |
| 喘息-2 | 132.6s | 1 个 / 0.3s | 3 个 / 0.5s | 4 个 / 0.7s |
| 舔耳-1 | 117.8s | 1 个 / 0.2s | 2 个 / 0.4s | 5 个 / 1.1s |
| 运动-1 | 45.6s | 0 | 0 | 0 |
| 正常台词（72s） | 72.3s | 0 | 2 个 / 0.3s | — |

结论：

1. **正常台词基本不误报**：72 秒里 0.35 只出 2 个事件，且都在句间；
   127 个 30 秒窗口里 p95 概率是 0.00–0.02。这条比「多检出几个」更重要 ——
   误报会把片段列表淹掉。
2. **ASMR 的持续喘息 / 舔耳，检出率明显低于官方表达性语音基准**。
   官方 F1 0.607 是在「笑 / 咳 / 抽气」这类短事件上测的；
   ASMR 的呼吸更轻、更长、更平，模型经常不把它当「事件」。
   所以：**它适合找「事件型」非语音人声，不适合找「持续型」气声**；
   后者继续用「按静音间隔」切。
3. 默认阈值因此定为 **0.35**（敏感），而不是官方的 0.50；
   处理台里给了三档预设，用户可以自己往回调。

> 这条实测也修正了评估文档里「ASMR 场景需要自己试」的悬念：
> 试过了，能用，但定位要收窄到「事件」而不是「所有非语音人声」。

### 5.1 加装 82 类分类器之后

同一段 407 秒素材、15 个事件：

- 5 个拿到类型：`抽气` ×2、`叹气` ×3；
- 另外 10 个组置信度不到 0.45，退回通用名；
- 典型例子：111.9s 那次被识别成 `Contented Sigh / 叹气 0.644`，
  151.8s / 352.7s 是 `Wistful Sigh / 叹气 0.858 / 0.871`。
- 也就是说：**它更擅长把「叹气 / 抽气 / 笑 / 咳」这类表达性声音分开，
  对 ASMR 的轻声喘息仍然偏保守**（经常落到 0.3 左右，不给类型）。

命名结果因此是混合的：有把握的叫 `叹气-001`，没把握的叫 `非语音人声-004`。
这比全部叫「非语音人声」有用，也比硬给每个都安一个类型诚实。

耗时：首次加载检测模型约 5s + 分类器约 7s，407 秒素材首次总耗时约 27 秒。
之后模型常驻，同样的素材约 7 秒。闲置十分钟或点「释放显存」会一起卸掉。

## 6. 还能在这个基础上做什么

按「投入 / 收益」排序。P1 是这一版已经有的，P2 往后是建议。

### 6.1 P1（已做）

- 事件轨可视化 + 句内标记；
- 按事件生成片段 + 自动命名；
- 查重分组；
- 事件 SRT 导出；
- 与字幕对位联动（复用）。

### 6.2 P2（已接可选）：82 类分类器 → 真正的类型名

`laion/vocalburst-classifier-single`（12MB MLP + 452MB VoiceCLAP 嵌入器）能把事件分成
82 类：`Panting` / `Gasp` / `Chuckle` / `Cough` / `Lip Smack` / `Licking Sound` …
top-1 49%、top-3 77%，粗到 16 个家族时 mAP 0.63。

已经接进来，但是**可选**：`vendor2/vocalburst/classifier/` + `voiceclap/` 存在才启用。

实现要点：

1. 事件段前后各留 0.25 秒，最短补到 0.25 秒，送 VoiceCLAP；
2. **不用 fine top-1 直接命名**，而是把 83 个类的概率按 16 个家族求和，
   取家族 top-1；家族概率 ≥ 0.45 才写类型；
3. 少数细类覆盖家族名（`Panting → 喘息`、`Licking Sound → 舔舐`、
   `Lip Smack → 咂嘴`、`Sniff → 抽鼻`），因为对做音效的人差别很大；
4. `P(no_burst) ≥ 0.5` 时直接不给类型（检测器说「有」，分类器说「没有」，
   以「不确定」处理，不硬命名）。

已验证 VoiceCLAP 的 `trust_remote_code` 代码能在当前 transformers 4.52 下加载
（112M 参数，`encode_waveform` 正常）。剩余工作不是「接进去」，而是：

- 用更多中文 ASMR 素材校准 `min_group_p`（现在 0.45 偏保守）；
- 决定要不要给「台词内的一声喘」单独的命名规则（它常被分成 `叹气`）。

代价：多 465MB 权重、首次多约 7 秒加载；显存占用从 ~2GB 增到 ~2.5GB，
释放显存时一起卸掉。

### 6.3 P2：与 DnR Effects 轨交叉验证

如果作业已经用 DnR 分过轨，可以算事件区间内 Speech / Effects 的能量比：

- Speech 明显高 → 更像「人声 burst」，保留；
- Effects 明显高 → 可能是纯音效（关门、摩擦）误检，降权或标灰。

这能把「误检」从「要人一条条听」变成「按颜色排序先看可疑的」。
代价是多一次 DnR 分离（比 VocalBurst 慢得多），只建议在「精修一遍」时开。

### 6.4 P2：整库扫描 / 批量质检

现在只能在处理台里对**当前作业**跑。再往前一步：

- 对素材库里选中的多条素材后台排队跑检测；
- 产出一张表：每条素材的事件数、总时长、句内占比、平均置信度；
- 用来找「这条 40 分钟的素材里居然一次喘都没有」——可能是录音太干净，
  也可能是分离把喘息去掉了，值得回去检查。

这是「打标」从单条工具变成**资产盘点**的关键一步。

### 6.5 P3：事件驱动的时间轴操作

- **按事件插入**：把事件段直接作为音效片段插进工程，位置按句锚定（现在要先生成片段再插入，
  多一步）；
- **事件避让**：生成 TTS 时，如果某句原片里有喘息，提示「这句原片有气口，中文里要不要补一个」；
- **气口模板**：把同一角色的喘息事件聚成一组，当作「呼吸音色库」，生成时按句间空隙自动铺。

### 6.6 P3：类型感知的命名与检索

有了分类器之后，片段名可以直接是 `喘息-001` / `轻笑-002`，
入库时把类型写进 `op` 或未来的 `tags`，素材库就能按「喘息」筛。
这是最自然的下一步，但依赖 §6.2。

### 6.7 不建议做的

- **拿它做自动删除**：F1 0.607，漏检和误检各三成；它是提示器，不是裁判。
- **拿它替代分离**：它只给区间，重叠在台词里的喘息仍然拿不出来。
- **用持续音素材的检出数评价模型**：会得出「模型很烂」的错误结论，
  它本来就不是为持续气声训练的。

## 7. 边界与已知问题

| 问题 | 现状 | 处理 |
| --- | --- | --- |
| 持续喘息 / 舔耳检出少 | 模型域不匹配 | 用按静音切；文档明确写「事件型 vs 持续型」 |
| 长素材要等十几秒 | 25 秒一块 | 可接受；未来可做后台任务 + 进度 |
| 30 秒窗口边界 | 5 秒重叠 + IoU 去重 | 已验证不会把一次事件切两半 |
| 模型 1.9GB 不进补丁 | 与 BS / DnR 一致 | 检测到才启用；没装不影响任何现有功能 |
| 无类型名 | 未接分类器 | 用可改前缀；P2 接 82 类 |
| 置信度不是校准概率 | 模型输出 | 只用于排序/筛选，不当作「准确率」展示 |

---

## 8. 一句话总结

VocalBurst 给工作台带来的不是「又一个模型」，而是一条**新的时间轴**：
以前只知道「哪几秒在说话」，现在知道「哪几秒有一次非语言发声」。
自动命名和自动起止只是这条轨最浅的用法；真正有用的是它让「句内的那一声喘」
第一次变成了一个可以被看见、被计数、被单独挑出来、并且跟着句子走的对象。
