# 音效智能拆解：可行性评估

> 评估日期 2026-11-02 ｜ 对象：现有工作台 + `/sfxbench`（v0.23 开发中）之上扩展"三轨 + 音效拆解 + 回插时间轴"
> 结论：**可行**，第一阶段约 2–3 天能出可用版。但方案有一处前提需要修正 —— 见 §1。

> **决策（2026-11-02，已定）**：放弃"保留喘息/舔耳等非语音人声"这个目标。
> 原因是实测证明它做不到：这类声音和人声在声学上同属一类，BS 判 100% 人声；
> 气声模型是"谐波/非谐波"分离器，也拆不开"台词 vs 喘息"（详见
> 《气声与非语音人声分离_评估.md》§8、§10）。
> **第一版只做两轨：Original / Instrumental**，三轨（Vocal 单独留一层）不做；
> §1 里的"三轨分工"与 §6.4 的"参考轨"降级为不做，功能范围收敛为
> "**用 BS 分离 → 按算法切段 → 挑片段入库**"，也就是 `/sfxbench` 现在的形态。

## 0. 现状盘点：已经有的比方案假设的多

| 方案要求 | 现状 | 位置 |
| --- | --- | --- |
| 去人声 | 已有，整条引擎链 | `_roformer_separate` / `_demucs_separate` / `_separate` |
| RMS 能量切分 | 已有（前缀和 RMS，hop 20ms / win 40ms） | `_sfxb_db` / `_sfxb_runs` |
| 谱减背景 | 已有（沿时间取中位数当噪声床） | `_sfxb_foreground` |
| 谱通量 onset | 已有（librosa 谱通量） | `_sfxb_segments(mode="onset")` |
| 候选列表 + 试听 + 合并 + 删除 + 入库 | 已有 | `/sfxbench` |
| 打轴结果导入 | **已有**：智能导入认 srt / `[00:01:23]` / 行首时间码，写 `t0/t1` 到台本行 | `lf_import.py` + `_norm_row` |
| 原时间 → 新时间映射的原料 | **已有**：行有 `t0/t1`（原片时间），片段有 `start`（新时间轴） | `timeline_api.py` |

所以真正要新建的只有四件：**三轨落盘、轨道切换、拆分/边界拖拽、`orig + policy` 的落点重算**。

## 1. 必须先修正的前提（实测数据）

拿两段真实 ASMR 素材跑 BS-Roformer（`bs_roformer_voc_hyperacev2`，RTX 5070 Ti Laptop）：

| 素材 | 人声能量占比 | 伴奏 vs 原（相关） | 伴奏轨电平 | 结论 |
| --- | --- | --- | --- | --- |
| 148s「ASMR 电台」纯耳语 | **98%** | — | **−58.9 dB（几乎全空）** | 模型几乎没分，全归人声 |
| 331s「睡眠音声」（含音乐床） | **39%** | 0.840 | −19.9 dB | 分离有效 |

**结论 A：「非人声轨里有音效」只在"有音乐/环境床"的素材上成立。**
纯耳语、耳边口腔音的 ASMR，Roformer 会把绝大部分能量判给人声 —— instrumental 是一条近乎静音的空轨。用户若按方案默认"从非人声轨切音效"，切出来的是分离残留，不是音效。

**结论 B：音效素材的默认来源应当是 Original，而不是任一分轨。**
分离会给瞬态加上谱洞和相位涂抹；一段干净的布料摩擦，从 original 取是原音，从 instrumental 取反而更脏。

**结论 C：三轨的正确分工不是"从哪条取素材"，而是"用哪条做判据"：**

```
Original  ── 素材切片的唯一来源（默认）
Vocal     ── 能量高 = 这一段有人说话/耳语 → 该段不适合当音效
Inst      ── 能量高而 Vocal 低 = 纯音效区 → 优先推荐
```

由此推出一个必须新增的界面元素：**分离有效性检测**。`prepare` 要返回 `vocal_ratio` / `corr_inst`，
低于阈值时直接提示"这段素材分不开，建议从原轨切"，而不是让用户在空轨上白切十分钟。

## 2. 边界检测：实现方式与参数建议

### 2.1 已实现的三条路

| 模式 | 做法 | 331s 素材耗时 | 形态 |
| --- | --- | --- | --- |
| `gap` | 逐帧 RMS（前缀和，O(n)）→ 门限 → 合并小缝 | **246 ms** | 稳，切出"话段"级 |
| `fg` | 中位谱减后再走 `gap` | 2.5 s | 连续床声里的短事件 |
| `onset` | librosa 谱通量峰 | ~1 s | 节奏/打击类 |

门限现为 `min(底噪 + N dB, 峰值 − 6 dB)`（写这行是因为连续音乐里底噪≈峰值，只按前者会把整段判成静音）。

### 2.2 参数建议

| 参数 | 默认 | 建议范围 | 说明 |
| --- | --- | --- | --- |
| hop | 20 ms | 10–20 ms | 10ms 边界更准，代价是帧数翻倍（仍 <1s） |
| win | 40 ms | 2–3 × hop | 太短会把低频鼓动判成静音 |
| 起始门限 | 底噪 + 10 dB | 8–16 dB | ASMR 建议 12 起（呼吸多、易碎） |
| 维持门限（新增） | 底噪 + 6 dB | 起始 − 4~6 dB | 双门限，见下 |
| 最小间隔 | 0.35 s | 0.25–0.4 s | 越大越容易把相邻事件并成一段 |
| 最短片段 | 0.2 s | 0.15–0.25 s | 滤咔哒 |
| 前后留白 | 30 ms | 30–50 ms | 别切掉起音/尾音 |

### 2.3 缺的三件（按性价比排序）

1. **双门限（hysteresis）**：单门限 + 合并小缝只是近似。改成"高门限起、低门限续"，
   喘息这类电平起伏大的事件不会被切成 3–4 段。改动约 10 行。
2. **边界精修**：粗定位后，在 ±150 ms 内找能量谷（或谱通量局部极大）把边界吸过去。
   把误差从 ±20 ms 收到 ±5 ms —— 对"音效卡台词"这件事有实际区别。
3. **拆分**：现在只有合并/删除。波形上点一下 → 在该点切开。**这是第一阶段里被低估的一项**，
   因为实测显示自动切分给的是"话段"，人真正想要的是段内的那一下响声。

### 2.4 一个必须遵守的调参纪律

参数要在**去人声之后**的轨道上调，不能拿原轨调。原轨里人声是主要能量动因，
在原轨上把门限调到"好听"，换到伴奏轨会全错（实测原轨 146 段 / 覆盖 48%，伴奏轨 71 段 / 覆盖 32%，
两者形态完全不同）。

## 3. 自动分类：CLAP 可做，BEATs 不建议

| 项 | CLAP（laion/clap-htsat-unfused） | BEATs |
| --- | --- | --- |
| 许可 | Apache-2.0 | 学术用途，仓库内无 LICENSE 文件 |
| 权重 | **586 MB**（fp32，实测 hf-mirror 可下） | 仅 OneDrive（1drv.ms）链接，无稳定直链、无 checksum |
| 部署 | pip（laion-clap / transformers `ClapModel`） | 需手工下载 + 拷进去 |
| 显存 | 估 0.6–1 GB（batch 1） | 估 0.4–0.8 GB |
| 标签空间 | 开放词表（文本塔） | AudioSet 527 类闭集 |

**BEATs 不建议的原因不是效果，而是分发**：权重只挂在 OneDrive，链接会漂、没有校验和，
跟"检测到就启用、装不上就退回"的可选引擎模式不兼容 —— 用户装不上时没有任何自救路径。
而且 527 类里有 `breathing` / `burping`，但没有"耳舐め""湿润拟音"这类 ASMR 核心类目。

**CLAP 的三个实操要点：**

1. **中文标签必须映射成英文锚点**。laion CLAP 的文本塔是英文语料训的，直接喂"湿润拟音"≈ 随机。
   维护一张内部词表：`耳语→whispering`、`呼吸→breathing`、`衣物摩擦→fabric rustling`、
   `亲吻→kissing / wet mouth sound`、`水声→water dripping`、`敲击→tapping`、`环境音→room ambience`。
2. **不要输出单一标签**，给 top-3 + 分数。CLAP 的绝对相似度不可跨类比较。
3. **阈值按批取**，比如"本批 top 10% 才算高置信"，不要写死 0.3。

派上用场的地方其实是**排序**而不是**命名**：按"像不像音效"给出一个可用的默认顺序，
名字交给台本括号（`【耳舐め】`）去填 —— 这条比分类本身便宜得多。

Mel-Band Aspiration 这类专用气声提取模型：权重的可用性与许可都还没有核实过，
且它解决的是"把气声单独拎出来"，与"切音效"不是同一件事 —— 第一阶段不接。

## 4. 三轨数据管理

### 4.1 推理成本：0

`_roformer_separate` 内部本来就是「vocal 必取，inst 取单独轨或 `原 − 人声`」——
**两条轨在同一次推理里已经算完了，现在只是把另一条丢掉**。
所以三轨只增加落盘和传输，不增加推理时间（实测单次 148s 素材约 19s，331s 约 27s）。

### 4.2 存储成本：真问题

44.1 kHz 立体声 PCM16 ≈ **404 MB / 40 分钟 / 轨**。三轨 = 1.2 GB，现有 `_SFXB_KEEP = 8` 最坏 6.5 GB。

| 措施 | 效果 |
| --- | --- |
| Original 不复制，直接引用素材文件 | −33% |
| 作业保留数 8 → 3 | −62% |
| vocal / inst 存 FLAC（不存 WAV） | 再 −40~50% |

建议三条一起做，40 分钟素材的作业目录从 1.2 GB 降到约 400 MB。

> **顺手发现一个现存缺陷**：`_SFXB["jobs"]` 是内存字典，进程重启就空，但磁盘上的
> `longform/sfxb/<job>/` 目录不会跟着删 —— 现在已经有 16 个目录 / 361 MB，而"只留 8 个"
> 从来没在磁盘上生效过。三轨之后每个作业 ×3，这个泄漏会更快吃满盘。
> 修法：启动时按 mtime 扫一遍、超额的删掉，并且每作业配一个 `meta.json`（不依赖内存）。
> 这条应该并进 P1，不然做完三轨等于给泄漏加了三倍速。

### 4.3 两个边界条件

- `MAT_MAX_BYTES = 512 MB` → 44.1k 立体声 PCM16 上限约 **50 分钟**。40 分钟刚好，60 分钟会被拒。
  若要支持一小时以上的音声，得单独给 `/sfxb/prepare` 放开这个限制（它是内部转码，不是上传）。
- 双耳信息不能丢：`_sfxb_mono` 只用于画包络（安全），`_save_sfx_item` 保留 ≤2 声道（安全）；
  但任何"为省空间转单声道"的想法都要否掉 —— 相位差就是方位感，mono 等于把头麦录的空间信息删了。

## 5. 准确率：实测形态与误检/漏检

`gap` 模式、默认参数、原始素材（未分离）：

| 素材 | 段数 | 中位时长 | >2s 占比 | 覆盖率 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| 148s ASMR 电台 | 27 | 3.52 s | 89% | 84% | 158 ms |
| 140s 轻声细语 | 17 | 3.52 s | 78% | 78% | 121 ms |
| 331s 睡眠音声 | 146 | 0.77 s | 14% | 48% | 246 ms |

**读法**：默认参数切出来的是**"话段"级**，不是"音效事件"级。ASMR 的人声是连绵的，
能切的地方本来就少；覆盖率 78–84% 说明大部分时长被并进段里。

所以第一阶段的产品定位要诚实：**不是"自动切出一堆音效"，而是"标出能切的位置 + 让人快速圈出想要的那几段"**。
在这个定位下，"拆分"和"边界拖拽"比"更聪明的自动切分"重要得多。

| 类型 | 具体表现 | 缓解 |
| --- | --- | --- |
| 漏检 | 连续床声（雨/风扇）被并成一整段，事件不浮出 | `fg` 模式；或整体当"环境床"整段入库 |
| 漏检 | 极低电平耳语低于门限，整段丢失 | 门限按分位数自动给初值，不写死 dB |
| 漏检 | 句内停顿切开后又被 min_gap 缝回去，一段里含两句 | 无所谓 —— 反正要人工拆 |
| 误检 | 呼吸被切成大量 0.2–0.4s 碎段 | ASMR 里呼吸本来就多，按"连着的一串"合并看待 |
| 误检 | 分离残留（电音感）被当成音效 | 默认从 Original 取（§1 结论 B） |

可验收指标（40 分钟作品）：

| 指标 | 目标 |
| --- | --- |
| 边界误差 | 95% ≤ 50 ms（含精修后） |
| 单段可接受率（人愿意留下） | ≥ 60% |
| 人工整理耗时 | ≤ 40 分钟（约 1× 音频时长的一半） |

## 6. 时间轴集成：最省事的一块

### 6.1 为什么说省事

打轴结果（SRT）通过现有智能导入进来，`t0/t1` 已经落在台本行上；时间轴片段有 `start`。
**两者按行对应，锚点表可以直接算出来，不需要新增任何录入流程。**

### 6.2 关键设计：存 `orig + policy`，不要存算好的 `start`

如果插入音效时只写一个 `start`，那么下次"改一句语速 / 重新生成"导致全片重排时，
音效就固定在新位置上，而台词已经移位 —— 这就是方案里担心的"错位"。
正确做法是给片段加：

```json
"orig": { "t0": 12.4, "t1": 15.1, "track": "original", "policy": "follow" }
```

每次重排后重算 `start = map(orig.t0, policy)`。

| policy | 映射方式 | 适合 |
| --- | --- | --- |
| `follow` | 按所在句的局部斜率（该句 新时长/原时长） | 与台词同步：翻页、杯子放下、脚步 |
| `abs` | 按全片总时长比 | 环境/背景（雨声位置本来不精确） |
| `snap` | 算完吸附到 ±0.4s 内最近的句边界 | 大多数"句末才响"的音效 |

`map()` 的分段线性函数由锚点表给出：每行 `(orig.t0 → clip.start)` 与 `(orig.t1 → clip.start+dur)`。

### 6.3 必须可见的一件事

落点算完要把**局部压缩比**带出来。中文比日文短 20–30%，一句 6s 压到 4.5s 时，
句中的音效会被挪前 1.5s；若原句压到 3s，压缩比 0.5，音效位置基本无意义。
**压缩比 <0.7 或 >1.3 的标黄**，交给人判断"跟句走还是改成 abs"。

### 6.4 参考轨

`DEFAULT_TRACKS` 只有 `voice` / `sfx`，混音按 `kind == "sfx"` 选轨。
新增 `kind: "ref"`（只读、不进混音、不导出）天然满足条件，但要过一遍分组/静音/独奏/导出逻辑。

## 8. 分阶段与风险

| 阶段 | 内容 | 估时 |
| --- | --- | --- |
| P1 | 三轨落盘 + 分离有效性检测 + 轨道切换 + 从任意轨切片 + 拆分/拖边界 + `src` 时间戳入库 | 2–3 天 |
| P2 | `ref` 轨 + `orig/policy` + 批量插入 + 压缩比标黄 | 2 天 |
| P3 | CLAP 标签（英文锚点 + top3 + 批内阈值） | 2–3 天 |

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 纯耳语素材分不开（实测 98% 归人声） | 功能对这类素材无意义 | 分离有效性检测 + 默认从 Original 取 |
| 存储膨胀 | 作业目录涨到 GB 级 | 引用 Original + 保留 3 个 + FLAC |
| 40 分钟以上素材被 512MB 上限挡住 | 长作品无法处理 | 单独放开 `/sfxb/prepare` 的内部限制 |
| `fg` 模式 2.5 s 延迟 | 拖滑块卡顿 | 前端防抖 300ms；或先算 1/4 采样率再精算 |
| 压缩比过低导致音效"糊" | 成品听感 | 标黄 + 默认改 `abs` |
| 双耳被 mono 化 | 空间感塌陷 | 全链保留 ≤2ch，禁止自动单声道 |

## 9. 一句话结论

**技术上没有硬障碍，第一阶段甚至大部分基建已经存在。真正的风险不在算法，而在两个判断：**

1. **默认值**：默认从 Original 取、默认提示"分不开"，比任何算法改进都影响成品质量；
2. **产品定位**：把"自动切音效"降级成"标出可切点 + 快速圈选"，这一阶段的满意度会明显更高 ——
   因为实测形态（中位 3.5s 的"话段"）跟"一堆短音效"的预期差得很远，靠 UI 引导比靠算法硬凑更实在。

建议开工顺序：**三轨 + 分离有效性检测 → 拆分/边界 → `orig/policy` 回插**。P3 分类可以永远不做。
