# 音频片段打标：LAION / VocalBurst / YAMNet 的可行性评估

> 2026-11-05 ｜ 关联：《气声与非语音人声分离_评估.md》
> 问题：能不能给音频片段自动打标（这段是喘息？那段是笑声？），并接进「高级音频处理台」？

---

## 0. 先分清三件容易混的事

| 要做的事 | 需要什么 | 现有能力 |
| --- | --- | --- |
| **分离**：把喘息从台词里剥出来 | 分离模型（BS-Roformer / DnR） | 已做；结论是**做不到**（两者都是人声，落在同一条轨） |
| **定位**：这段音频里 12.4s~13.1s 有一次喘息 | **打标 / 事件检测模型** | 目前没有 |
| **分类**：这次喘息属于「喘」还是「笑」 | 分类模型（多标签） | 目前没有 |

§8.4 的结论是「不要试图让模型判断这是音效还是台词，要按区间做减法」——
那么**区间从哪来**？唱词打轴能给出「台词在哪」，但给不出「喘息在哪」。
这一节评估的三个模型，正好补的就是这块空白。

---

## 1. VocalBurst Locator（LAION）—— 最贴，几乎是为这个需求做的

### 1.1 它是什么

- HF：`laion/vocalburst-locator`，Apache-2.0；
- 结构很轻：**Whisper-small 编码器（冻结 + LoRA）+ 一层投影 + 一层时间卷积 + 单 logit**，
  逐帧输出「这一帧是不是 vocal burst」，**50 fps**，30 秒窗口（1500 帧）；
- 输出：`[{start, end, confidence}]` —— **时间戳 + 置信度**，不是分类；
- 权重：`model_v2.pt` **972 MB**（推荐）/ `model_v2_mixed.pt`（背景里有音乐、音效时用）/
  `model.pt`（v1，合成数据训练，已被取代）；
- 配套还有 `laion/vocalburst-captioning-whisper`（给每个事件写一句话）和一个
  **82 类细分类器**（VoiceCLAP 768 维 + 小 MLP，几百 KB）。

### 1.2 它认什么

官方列的目标就是我们要的东西：**笑、偷笑、叹气、抽气、呻吟、哼、粗声、尖叫、哭、
咳嗽、打喷嚏、吸鼻子、清嗓、咂嘴/弹舌、喘气、打哈欠、嗯声** ——
不是「环境音」（雨声、关门声），而是**人发出的非语音声音**。

这跟 DnR 的 Effects 轨刚好互补：DnR 管「不是人发出的音效」，VocalBurst 管
「是人发出的但不是语言的声音」。

### 1.3 官方实测（这是选它的主要依据）

在 **992 条真实野生表达性语音**上，事件级 F1@IoU0.5：

| 权重 | F1 | 精确率 | 召回率 | 最佳阈值 |
| --- | --- | --- | --- | --- |
| `model.pt`（v1，合成数据） | 0.152 | 0.469 | 0.207 | 0.80 |
| `model_v2.pt`（真实数据微调） | **0.607** | 0.678 | 0.669 | 0.50 |

v1 有一个很典型的失败：它只有在阈值 0.80 时精确率才可用，而那时召回只剩 0.21 ——
**在真实录音上它非常不自信**。v2 在 0.50 就能同时拿到 0.68/0.67。

还有一条更值得记的：**后处理参数比换权重影响更大**。同一份 v2 权重，
只把 `min_duration` 从 0.5 秒改成 0.1 秒、`merge_gap` 从 0.3 改成 0.1，
事件 F1 从 **0.243 → 0.598**。原因是真实 burst 的**时长中位数只有 180 ms**，
0.5 秒的下限会先把 96% 的真事件丢掉。

> 对我们意味着：接进来时**必须显式传 v2 的三个参数**（0.50 / 0.10 / 0.10），
> 不能沿用脚本默认值（那还是 v1 的 0.65 / 0.3 / 0.5）。

附带的多标签分类器（82 类）：top-1 准确 49%、top-3 77%；粗到 16 个家族时 mAP 约 0.63。
也就是说「检测到有 burst」比「说清是哪一种 burst」可靠得多。

### 1.4 体积 / 速度 / 依赖

| 项 | 数值 |
| --- | --- |
| 权重 | 972 MB（v2）/ 另加 Whisper-small ≈ 150 MB |
| 依赖 | `transformers`（已有 4.52）、`torch`、`librosa`、`soundfile` —— **整合包全都有** |
| 速度 | 30 秒窗口一次前向，RTX 5070 Ti 上约 0.2–0.5 秒量级（Whisper-small 编码器） |
| 显存 | < 2 GB |
| 许可 | Apache-2.0，可随包分发（但 972MB 不进补丁，走「检测到才启用」） |

**结论：技术上最容易落地的一个** —— 不需要新依赖、不需要新后端，跟现有 pymss/BS 那套
「模型目录 + 检测到才出现」的机制完全一致。

## 2. YAMNet（Google）—— 能用，但粒度不对

- AudioSet 521 类的通用声音事件分类器，MobileNet 骨干，**只有 ~17MB**（TFLite）；
- 输出逐帧 521 类分数（0.48 秒一帧，96 帧约 0.96 秒一步）；
- 类别里确实有 `Laughter`、`Giggle`、`Snicker`、`Sigh`、`Gasp`、`Pant`、
  `Breathing`、`Wheeze`、`Cough`、`Sneeze`、`Throat clearing`、`Sniff` 这些。

**问题在粒度**：它是「通用环境声」分类器，训练数据是 YouTube 视频的混音，
标签体系里**没有「舔耳」「口腔音」「耳语」**这类 ASMR 专属类别。
能给出的最接近的是 `Breathing` / `Wheeze` / `Speech`，三者对我们的场景区分度不足
（喘息、舔耳、耳语很可能都落到 `Speech` 或 `Breathing` 上）。

另外 **依赖不顺**：官方只发 TF Hub / TFLite，整合包的运行时是 PyTorch，
要跑得装 `tensorflow`（几百 MB）或转 ONNX —— 为了 17MB 的模型引入一套新运行时，性价比低。

**结论：不推荐作为主力**。真要用，只在「粗筛出非语音段」这一步有价值，而这一步
VocalBurst 做得更好且依赖更轻。

---

## 3. LAION-CLAP —— 「用文字点单」的可能性，但中文与 ASMR 域都弱

- 音频-文本对比模型（HTSAT / PANN 骨干 + 文本塔），**零样本分类**：
  给一组文字标签（`panting`、`tongue clicking`、`wet mouth sound`），算音频与每条的相似度；
- 权重约 **600MB–1.5GB** 因版本而异，`laion-clap` 包 + HF；
- **优点**：标签可以自己写，不用重新训练 —— 想识别「舔耳」就写 `ear licking`；
- **缺点**：
  1. 训练语料是英文互联网音频，**中文标签基本无效**（得自己英译，且文化词对不上）；
  2. 零样本在**细粒度、同质**的 ASMR 声音上区分度差（耳语/喘息/舔耳在 CLAP 空间里很近）；
  3. 它是「clip 级」判断，**不给时间戳** —— 要做定位还得自己滑窗。

**结论：适合「给整段素材打个粗标签」（如「ASMR / 人声 / 低语）」，
不适合「找出第 12.4 秒那次喘息」。** 优先级排在 VocalBurst 之后。

## 4. 三个模型对比

| | VocalBurst Locator | YAMNet | LAION-CLAP |
| --- | --- | --- | --- |
| 输出 | **时间戳 + 置信度** | 521 类逐帧分数 | clip 级相似度 |
| 目标声音 | **非语音人声（正对）** | 通用 521 类（含但不专） | 任意文字标签 |
| ASMR 细分（舔耳/口腔音） | 检测到「有 burst」，类型靠 82 类分类器 | 无对应类别 | 弱 |
| 体积 | 972MB + Whisper 150MB | **17MB** | 600MB~1.5GB |
| 依赖 | transformers/torch（**已有**） | TensorFlow（**要新装**） | laion-clap 包 |
| 许可 | Apache-2.0 | Apache-2.0 | 视权重 |
| 定位精度 | 50 fps（20ms 帧） | ~0.5s | 无 |
| 落地难度 | **低** | 中（运行时） | 中 |

## 5. 接进「高级音频处理台」的方式

处理台现在的流程是：载入素材 → 处理（分离/降噪）→ 按字幕切分 → 入库 / 写进时间轴。
打标应该插在**「载入素材之后、切分之前」**，作为第 4.5 步：

```
① 载入 → ② 处理 → ③ 波形编辑 → ④ 字幕（可选）→ 【新】④.5 打标 → ⑤ 切分 → ⑥ 输出
```

具体能做的三件事：

1. **在波形上标出事件**：拿到 `[{start,end,conf}]` 直接画成一条「事件轨」，
   和字幕轨并列。点一下跳到那个事件，听一句就能判断是喘息还是别的 ——
   **这本身就是最有用的功能**（相当于给非语音声音装了字幕）；
2. **按事件切片**：把每个 burst 段直接切成素材，命名 `喘息-01`、`喘息-02`；
   这是把「自动切片」从「按字幕间隔」扩展到「按声音事件」；
3. **入库带标签**：切片存档时把 `confidence` 和分类器的 top-1 写进 `tags`，
   以后在素材库按标签筛选（现有标签库机制已经支持）。

不建议做的：**不要拿它做自动决策**（比如「这段是喘息，自动删掉台词」）。
它只说「这里有一次非语音发声」，说不清「这是喘息还是叹气」，也**不能分离** ——
台词和喘息重叠时它只会告诉你「这里有一个 burst」，帮不上拆分。

### 5.1 落地形态（沿用现有机制）

- 新目录 `vendor2/vocalburst/`，放 `model_v2.pt`（可选 `model_v2_mixed.pt`）；
- 新增一项 `kind=vburst`，复用现有 `/lf/sepro/status|open|test` 那套接口；
- 「模型拓展」里加第三个折叠项（结构已经支持，加一个 `<details>` 即可）；
- 处理台加一个「🔍 打标」按钮：跑完在波形上画事件，不自动改任何东西。
- 体积 1.1GB 不进补丁包，走「检测到才启用」—— 和 BS-Roformer / DnR 一致。

### 5.2 必须先说清的局限

- **它是检测，不是分离**：知道「第 12.4 秒有喘息」≠「把这次喘息单独拿出来」；
- **30 秒窗口**：长音频要分块推理再合并，块边界处要留 overlap（否则跨界的 burst 会被切两半）；
- **参数敏感**：必须显式用 v2 的 `0.50 / 0.10 / 0.10`，用默认值会丢掉 96% 的短事件；
- **官方 F1 0.61**：意味着漏检和误检各占三成左右，适合「提示人去看」，不适合「自动决定」；
- 中文素材没有专门评测，官方基准是英文表达性语音，**ASMR 场景的实际表现需要自己试**。

## 6. 建议顺序

| 优先级 | 做什么 | 理由 |
| --- | --- | --- |
| P1 | 接 **VocalBurst Locator**（只看时间戳，先不做分类） | 依赖最轻（transformers 已有）、正好补「非语音人声在哪」这块空白、Apahce-2.0 |
| P2 | 加 82 类分类器，给事件写类型标签 | 几百 KB，能把「喘息 / 笑 / 叹气」分个大概 |
| P3 | 接 CLAP 做整段粗标签 | 只在「素材入库自动分类」有意义 |
| P4 | YAMNet | 不推荐：粒度不合、要新运行时 |

**一句话**：VocalBurst 不是又一个分离模型，它是**给「非语音人声」加了一条字幕轨**。
我们折腾了几轮分离（BS / DnR / 气声模型）都没法把喘息从台词里剥出来，
但「告诉人第几秒到第几秒有一次喘息，让他自己决定留还是删」这件事，它是能做的 ——
而这恰好就是 §8.4 那条「按区间做减法」所需要的那张区间表。
